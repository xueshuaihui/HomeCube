- 来源：2026-10-31 需求评审的 Q11 裁决（评审方起草、需求方审）+ **四问裁决（v0.2 的依据：L1 冻结、`unauth` 单列、§5 合并方向认可并两处补正、L4 迁移分三步走）**。该轮评审的对话记录已在收口后删除，结论**只以本文件与 PRD 为准**——本文件是态词的唯一来源，不引用任何评审过程文档。
- **v0.3 的唯一改动**：登记 L3 新态 `minor`（非成人视图，`27-settings` 的 ⑩ 落地时引入）并写明它与 `readonly` 的互斥口径——见 §4 的 HomeOS 段。枚举冻结不变，L1 仍 8 个、L2 仍 4 个。

## 1. 四层，只有两层进 `data-states`

| 层 | 含义 | 落在哪 | 例 |
|---|---|---|---|
| L1 页面态 | 整页没有正常内容可看 | `body[data-state]` | 空列表、网络失败、无权限 |
| L2 过程态 | 整页正在等待一个动作完成 | `body[data-state]` | 保存中、导出中 |
| L3 业务态 | 整页内容有效，但对象处于某种业务状态 | `body[data-state]` | 已跳过、已归档、已结清 |
| L4 交互态 | 页面某个局部在展开/选择/录制 | **`data-ui`**，不得进 `data-states` | 浮层打开、选择器、拖动中 |

判定口径：一个态若只影响页面内的某个区块（浮层、行内按钮、字段），就是 L4。

## 2. L1 页面态：封闭 8 个

| slug | 中文名 | 语义 | 禁止用法 |
|---|---|---|---|
| `default` | 默认 | 正常内容态；**每页必须有** | 不得作为「什么都没写」的兜底 |
| `loading` | 加载中 | 首屏数据未回 | 不得用于「保存/提交」（那是 L2） |
| `empty` | 空态 | 请求成功但零条 | 不得与 `error` 混用（零条不是失败） |
| `error` | 失败 | 请求失败或服务端 5xx | 不得用于权限不足（用 `denied`） |
| `offline` | 离线 | 无网络 | 不得用于服务端超时 |
| `denied` | 无权限 | 角色/可见性拒绝（403） | 不得用于「未登录」（用 `unauth`，见 §5） |
| `readonly` | 只读 | 有读权无写权，页面可看不可改 | 不得用于「临时锁定」 |
| `conflict` | 冲突 | 版本冲突或并发抢占（409） | 不得用于表单校验失败（用 `invalid`，见下方边界） |

**（v0.2 冻结）这 8 个就是页面态的全部，多一个少一个都要改本表。** 边界补一条：**`invalid` 不进 L1**——表单 / 字段校验只影响局部，落 L4 的 `data-ui`（`data-ui="invalid"` + 字段名），页面级仍然按上面 8 个取值。判据：`invalid` 出现时页面其余内容仍可读可操作，因此它不是「整页没有正常内容可看」。

## 3. L2 过程态：封闭 4 个

`processing`（保存/提交/检查统一）、`exporting`、`sending`、`queued`。

现状里 `saving`(4)、`submitting`(3)、`checking`(1) 是同义三写法，v1.0 统一合并为 `processing`；`exporting`(2)、`sending`(1)、`queued`(1) 因有独立文案与可取消行为，保留。

## 6. 命名规则（六条）

1. 全小写、连字符分隔，不用下划线（`reset_offline` → `reset-offline`）。
2. 页面态用**形容词/名词**（`empty`、`denied`），过程态用**动名词**（`processing`、`exporting`），不得混用。
3. 一态一词：同义族只留一个（见 §5）；**禁止**用 `xxx2`、`xxx-new`、`xxx-final` 这类后缀区分。
4. 业务态必须带对象名或面名时，用前缀：`todo-overdue` 而非裸 `overdue`（渲染层仍读整串）。
5. 交互态一律 `data-ui`，值可与 `data-states` 同名但不得互相引用。
6. 新增态必须先加进本表再落原型；**表外值一律视为缺陷**。

## 7. `check.mjs` 三条断言（批5 实现）

```text
A1  每页 body 必须有 data-state="default"（或 data-states 含 default）
A2  data-states 的每个值 ⊆ 本表 L1 ∪ L2 ∪ L3；表外值 → 报错并打印是哪个页面
A3  data-ui 的值不得出现在 data-states；反之亦然
A4  （可选）屏卡状态矩阵的中文态名必须能在本表找到对应 slug，否则报「未登记」
```

A2 落地时先跑一次全量，把当前 131 个值的违规清单作为基线，允许按 §5 的合并表分批清。**A1-A3 与 `check.mjs` 同批落地（批5）**：落地的同一次提交里，`docs/v2/README.md` 必须写明「**`check.mjs` 红着不许提交**」——门禁不是提示，是提交前置条件（04:06 需求方要求）。

## 9. 批5 执行顺序（四步，不跳步）

1. **冻结枚举**：L1 / L2 / L3 本表定稿（即本版），此后新增态必须先加表。
2. **同批迁原型 + 落断言**：按 §5 改 77 个原型，同一次提交里把 A1–A3 写进 `check.mjs`（表外值报错、`data-ui` 与 `data-states` 不互串）。
3. **75 张卡矩阵同步**：L1/L2/L3 行保留，L4 进交互清单；矩阵行数变化须与第 2 步的扫描结果对得上。
4. **写入口可达性抽检**（第 4 步，不新增文档）：PRD 里点名的每个「UI 写入口 / 入口隐藏」能力，在原型里必须能搜到一个 `data-hot` 名或元素 id——**「有接口没入口」是本轮最容易漏的一类缺陷**（R4-1 免打扰家庭默认、R5-2 悬空引用都是它），而 A1–A3 只管状态词、兜不住它。抽检清单先用手写：3.4.8 的设置写口、4.5.3 的导出开关、5.5.2 的认领与指派，各页 `data-hot` 名逐一对照。**同一步必须反向再走一遍（镜像规矩）**：原型上出现的每一枚标记、每一个候选值、每一段骨架，屏卡与 PRD 里都要有对应的一句话——**文档没说的，原型也不许替它说**。「文档说得到、原型做不出」与「原型画出来了、文档没写」两个方向都会骗到拆卡的人。本轮已确认的三个实例：`settings.html` 日期格式行尾的「需管理员」曾无条件渲染进管理员态（27 卡只在置灰两态写它）、同层两个候选项一度渲染同形（27 卡 ⑧ 要求「选中项即时预览示例」，同形即无法验证）、`calendar-edit.html` 的 `loading` 骨架被无 width 的包裹块压成 0 宽（卡的「骨架贴合表单行高」当帧不成立）。
