# HomeCube 需求 v2 · 以屏为单位

> 目的：需求文档能直接对着原型看。每一屏都有「效果图 / 可点击原型 + 编号热区 + 交互表 + 状态矩阵 + 字段校验」，让人不用读长文就能知道点哪里、发生什么。

## 怎么打开

直接双击 [prototypes/index.html](prototypes/index.html)（Chrome / Safari 均可，无需构建、无需起服务）。

- 每屏左上角可切换主题（跟随系统 / 亮 / 暗）与「交互标注」
- 每屏左上角的状态下拉，或 URL 加 `?state=loading` 等，可直接落到异常帧
- 分享或截图需要固定主题时加 `?theme=dark`（或 `?theme=light`）；加 `?annotate=1` 直接打开标注
- 手机上打开时工具层自动收起，屏按真实尺寸铺满
- 页脚无外部依赖，离线可用

## 约定

1. **屏卡只写交互**：屏卡写触发、反馈、去向、状态与校验；接口与数据契约另立一卷，避免两处各写一份。
2. **令牌唯一来源**：颜色、圆角、间距、字号只在 [prototypes/shared/tokens.css](prototypes/shared/tokens.css) 定义，页面只引用变量。写死色值即违规。
3. **亮/暗同构**：同一个组件、同一句文案，只换令牌值；不出现页面级主题覆盖。
4. **十个全局态共用一套组件**：未启用 / 即将上线 / 暂不可用 / 依赖未就绪 / 无权限 / 空 / 加载 / 失败 / 离线 / 冲突 / 待解锁，业务面不得自造文案。
5. **编号对应**：屏卡里的 ①②③ 与原型热区编号一一对应，改一处必须同步另一处。
6. **原型工具层不是产品 UI**：左上角主题/标注/状态控件只在原型里存在，任何屏卡与验收都不应把它当产品元素。
