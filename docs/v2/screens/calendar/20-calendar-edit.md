**一屏说清**：编辑日程与新建日程是 ㉛ 同批补进日历分包的成对页（与 `todo-create` / `todo-edit`、`reminder-create` / `reminder-edit` 完全同构）——字段顺序、按钮位置、错误呈现与新建页逐一对齐，差别只在「带 version 保存」与「进页先判来源」。经 17.4 契约由财务注册的到期型日程**不是用户可编辑的日程**：`source_system ≠ calendar` 时进页即给只读态（控件禁用 + 「前往源对象」引导，不是报错），本页绝不代他面写真值（17.2 唯一可写方）。参与人的写权与待办同构：「自己的」作用域句（5.5.7 ㉛）给待办定的是「被指派的参与人可勾选完成、可回应条目，但不可修改待办本体、截止时间与重复规则，规则与对象的写权只在创建人与管理员」——日程的参与人即同构句里的「被指派者」，同一格子（16.3 日历行成人格 M）推同一结论，本页按同构落。

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 创建人 / 管理员从详情页「编辑」或到期中心卡动作位进入 | 预填全部字段；顶部一行「上次修改 · 创建人 · 今天 09:12」——**不显示「版本 N」这类内部值** |
| 加载 | 进入瞬间详情未拉到 | 骨架贴合表单行高（详情未拉到时不进空表单，§4.4），不用 spinner 遮内容 |
| 注册型只读 | `source_system ≠ calendar`（如财务账单注册的到期日程） | 顶部引导卡「这条日程来自账单，由账单页维护时间；这里只能看摘要」+「前往源对象」；整页控件禁用、无保存与删除动作位；**是只读态、不是报错**，返回照常 |
| 内容有变动 | 保存时版本已变（409 + 双版本 payload） | 表单降透明锁定，冲突弹层置顶：修改人 / 时间 / 差异摘要 + 三条互斥出路（按钮见交互表 ⑩） |
| 保存失败 | 服务端拒绝 / 网络错误 | 顶部红色条「保存没有成功，请检查网络后重试——你改的内容都还在」+「重试」；字段值与改动全保留 |
| 离线 | 无网 | 顶栏下细条「当前离线 · 改动保存后先排队」；改动先存本机，联网后带最新服务端状态提交；期间他人已改动 → 仍走冲突弹层，不丢用户输入 |
| 已删除 | 对象已被软删（`deleted_at` 非空）后重进本页 | 「已删除」态 +「回收站」入口（仅创建人与管理员可见该入口，§2.5）+ 返回到期中心 |
| 无权限 | 非创建人的成人成员 / 儿童 / 访客直达本页 URL | 「无权访问」态 + 返回，不回显任何字段片段；正常路径下详情页不会出现「编辑」入口 |

本页**没有「无数据」空态**：对象存在的唯一形态是表单，对象不存在（已软删）的形态是「已删除」态（§4.4 状态五味在此页的落法）。

## 字段与校验（页面级硬规则）

- **version 乐观锁（3.4.4 写路径）**：提交携带进入本页时的 version；不一致返回 409 + 双方 payload，**不接受静默覆盖**；本页不自动合并字段、不后台悄悄重拉重发。
- **冲突三选一互斥**：「查看最新」= 丢弃本次改动并重拉最新；「用我的」= 以当前表单整体重发（仍冲突则再弹，不超过 2 轮）；「放弃修改」= 回详情页。三条出路文案统一（§6.5，㉛ 明写本页是这条链路的第四个写口、不得自造第三种文案）；「用我的」用中性样式——危险红只留给不可逆动作，这里的动作可再改。
- **内部值不进 UI**：头部、弹层、任何用户可见文案不得出现 version 号、`source_system` 原文、「乐观锁」等字样；修改人 + 时间按「谁 · 什么时候」呈现。
- **注册型判定**：进页先读对象的来源标记——`source_system ≠ calendar`（即由 17.4 契约注册承载的日程）时整页只读并给「前往源对象」；绕过客户端直发 `PUT` 亦被服务端拒绝；该对象的改期 / 撤销只由来源面重新注册或撤销触发（17.4）。
- **写权分层**：原生日程的改与删只在创建人（M 格「自己的」）与管理员（A 格）；被邀请 / 被指派的参与人可回应、可完成（完成类状态只进不退，3.4.4），**不可改本体、时间与重复规则**——同构依据 = 5.5.7 ㉛ 给待办定的「自己的」作用域句 + 16.3 日历行同一格的 M 语义（§12.11 ㉛ 行「他人日程不进本页」）；参与人不是第二写口的授权。
- **异常时间三句（与新建页同句）**：已是过去 → 行内提示、允许保存、服务端不再排提醒、客户端不自顺延；每月日号在该月不存在 → 当月不出现、不触发、不标错，落补只认服务端回显；节假日与调休 → 本页不判、不动用户所选的原值。触发与提醒时刻一律取服务端按家庭时区计算的回显，**客户端不得自行推算**。
- **提前提醒档位**：恰为四档封闭枚举（准时 / 提前 10 分钟 / 1 小时 / 1 天，5.5.3 第一层，只约束这个选择器）；「提前 15 分钟」这类枚举外值出现即缺陷；17.4 注册触发点（第二层）不得作为选项混入。
- **改期 / 改可见范围的收敛语义**：一次提交、服务端重裁集合（5.5.4 聚合口径、5.5.7 服务端裁剪、18.7 第 4 条）；判据行级断言由 `CAL-TIME-017` 承接，本页只判「入口形态与回落脚位」。
- **写口**：`PUT /api/calendar/events/{id}`（5.8，13 条计数不变）；管理台补录以管理员权限复用同一条路径，不存在第二个写口。

## 边界与不做

- **不可从全局「＋」进入**（「＋」只建不改，18.4）；本页入口 = 详情页「编辑」、到期中心卡动作位、`?focus=` 定位后长按（不新增路由位）。
- 删除不在本页成路由：只有「按钮 → 确认弹层 → 软删」一条形态；暂停不在日程本体（暂停是提醒页的事）。
- 不做字段级合并、差异编辑器、实时协同与占用锁（P1 无锁，靠 version 兜底）。
- 不做「另存为新日程」（§4.4 登记的可选动作，本版不做）。
- 不代他面写真值：注册型只读，任何「先改了再说」的路径都不存在。
- 不在头部或弹层显示内部值（version 号、来源字段原文、错误堆栈）。

## 待复核

- 「回收站」入口的落点路由：日历分包 11 页（§4.4）没有回收站路由位，财务有 `finance/tx/trash` 先例；本页「已删除」态的入口暂标未交付，落点待裁决。
- 被邀请参与人能否增删**自己**（退出日程）：16.3 与 5.5.7 都没有句，本版按「不可改本体」整体拒绝。
- 管理员改他人日程时，详情页「编辑」入口对管理员的渲染口径需与 10 / 11 两页卡回写对齐（§12.11 ㉛ 行）。
