# 17 · 新建提醒

| 项 | 值 |
|---|---|
| 路由 | `calendar/reminder/create` |
| 期 | ① |
| 权限 | 管理员与成人成员可新建自己的提醒；儿童可建自己的；访客入口不出现 |
| 原型 | [reminder-create.html](../../prototypes/reminder-create.html) |
| 状态帧 | [默认](../../prototypes/reminder-create.html) · [渠道降级](../../prototypes/reminder-create.html?state=fallback) · [标题为空](../../prototypes/reminder-create.html?state=error) · [时间没选](../../prototypes/reminder-create.html?state=no-time) · [保存中](../../prototypes/reminder-create.html?state=submitting) · [离线](../../prototypes/reminder-create.html?state=offline) |

**一屏说清**：新建提醒是日历面「提醒」段下的写页（导航路径：首页 C 区日历格 → 二级 Tab「提醒」→ 新建），只收六件事——标题、时间、周期（六档：不重复 / 每天 / 每周 / 每月 / 每年 / 自定义，含星期 / 日号 / 每年月日 / 自定义间隔与结束条件）、提前量、渠道，外加可选的**位置**（P6 前只有手动地点）。两条硬线：**① 每条提醒必须落一个时间档**——「不重复」要选日期 + 时刻，「每天 / 每周 / 每月 / 每年 / 自定义」要选时刻（每周至少挑一天、每月至少挑一个日号、每年要填月与日、自定义要有间隔与结束条件），时间不齐**保存直接被拦**，位置不能顶替时间；**② 提前量恰四档**，档位外不出现。提醒一律**归创建人自己**（不可指派他人；要按周期提醒他人走待办）。「保存」不等于「已上日历」：落库后由本面纳入到期，到点由底座投递，页面不承诺保存完立刻生效，也不在客户端预告触发时刻。渠道不可用时**降级、不阻断**：推送关了就走站内信，保存照常可用。**跳过 / 顺延是实例动作，本页不出现、也不预设**。

## 字段与校验（页面级硬规则）

- **标题**：必填、非空、≤60 字（与全面同口径），只做首尾空白裁剪；为空时红框 + 行内「请填写标题」，错误落在字段上，不用 toast / 弹层；绕过客户端直发时服务端按 400 拒绝。
- **时间必填**：每条提醒**必须有一个时间档**——「不重复」= 具体日期 + 时刻；「每天 / 每周 / 每月 / 每年 / 自定义」= 时刻，且每周至少选一个星期、每月至少选一个日号、每年要填月与日、自定义要有有效间隔与结束条件。**不齐即不许保存**：错误落在对应字段（「请先选好提醒的日期」「请至少选一天」「请至少选一个日号」「请把每年的月份和日号都填好」「间隔要填 1 或更大的整数」「请把结束日期或次数填好」）、不发请求；**位置字段不能顶替时间**——只填地点、没有任何时间的提醒在本页存不进来，因此列表里也不存在这类行。判据：`?state=no-time` 帧提交被拦 + 行内文案落点正确；静态扫描表单不存在「无时间也能保存」的分支。
- **周期**：**封闭枚举恰为六档——不重复 / 每天 / 每周 / 每月 / 每年 / 自定义**，提醒与待办同一套；「跳过 / 顺延」不在本页——那是编辑页对**某一次触发**的实例动作（`calendar/reminder/edit`）。**「工作日」不是第七档**：它只作为「自定义」里的快捷按钮出现，选中后落成「每 1 周 · 周一至周五」，不得与六档并列。
- **自定义**：每 N 天 / 每 N 周 / 每 N 月（N 为 ≥1 的整数）+ 结束条件三选一（永不结束 / 到某日 / 共 N 次）；到某日必须选日期，共 N 次必须填 ≥1 的次数。工作日快捷只改间隔预设，不改结束条件。
- **星期与日号**：周期为每周 → 周一~周日**多选**；为每月 → 1–31 **日号单选**；为每年 → **月（1–12）+ 日号（1–31）**都要填；取值只按用户所选，**不得用「今天的星期 / 今天的日号」兜底**；周四进本页必须能建出「每周一 08:00」。
- **每月日号在该月不存在**：每月重复取 29 / 30 / 31 日而该月没有这一天时，**该月不出现该提醒、不触发、页面不标错**；规则行保持原日号，是否落补到别日**只认服务端回显**，本页与客户端一律不推算、不自顺延（与 `19-calendar-create.md` 同句口径）。每年 2 月 29 日同理：没有这一天的年份不提醒。
- **提前量**：可选值集合**必须恰为四档**——准时 / 提前 10 分钟 / 1 小时 / 1 天，多一档少一档都不通过；「提前 15 分钟」这类枚举外值出现即缺陷。提醒不设「不设置」态（那是日程提前提醒字段的默认态，19 卡⑧），本页默认「提前 1 天」，**不因此多出第五档**。17.4 注册契约的触发点（到期前 3 天 / 每期前 3 天 / 到期前 30 天等）是**另一层**，不得灌进本选择器。提前量只影响触发时刻，不改周期。
- **节假日与调休**：本页**不判**——不顺延、不提前、不置灰、不弹确认，一律按用户所选原值（与 19 卡同口径）；服务端日后调整以保存后的服务端回显为准。
- **渠道**：推送 / 站内信 / 两者。推送不可用 → 自动落站内信并明示降级，**保存不被阻断**；渠道字段只是**投递偏好**，实际投递一律由底座完成（本面不直连推送通道）；站内信落「消息 → 提醒」分组，与推送同源不重复计数。
- **位置**：可选、≤30 字；只存用户填的地点文字，**P6 前不接地图与地理围栏、不做到达判定**，位置类提醒不计入到达率（5.5.3、5.5.8 的工程口径，不进用户可见文案）。**这一版只按时间触发**：留空即普通时间提醒；填了位置也不改变触发条件，不会因为到了某个地方就提前响或另外响。与编辑页同一字段、同一校验（`calendar/reminder/edit`）。
- **归属人**：`owner_id` = 创建人，**本页不提供指派他人、不出现归属人选择器**（㉛）；需要按周期提醒别人的场景由待办承载（`calendar/todo/create`）。
- **触发时刻不回显在表单里**：本页不显示客户端推算的「下次触发」预览行；保存后的下一次触发以列表与编辑页的服务端回显为准（与 19 卡同句）。
- **保存承诺**：提醒落库后由本面纳入到期，到点由 `calendar.reminder.fired` 交底座投递；成功文案固定「已保存」并回提醒列表，页面不承诺保存完立刻生效，不得写「已加入日历」。

## 样例与表单能力一一对应

列表页（`calendar/reminder/index`）的每条周期文案都必须能由本表单产出，逐条对得上：

| 列表样例 | 本表单的产出路径 |
|---|---|
| 妈妈体检（11 月 12 日 09:30 · 提前 1 天） | 周期「不重复」+ 日期 11 月 12 日 + 时刻 09:30 + 提前量「提前 1 天」 |
| 小满家长会（每周三 15:00 · 提前 1 小时） | 周期「每周」+ 只挑周三 + 时刻 15:00 + 提前量「提前 1 小时」 |
| 到超市买牛奶（11 月 2 日 09:00 · 提前 10 分钟 · 位置） | 周期「不重复」+ 日期 11 月 2 日 + 时刻 09:00 + 位置文字 + 提前量「提前 10 分钟」 |
| 每年 11 月 12 日 09:30 | 周期「每年」+ 月 11 + 日 12 + 时刻 09:30 |
| 每 2 周 周三 15:00 · 到 12 月 31 日结束 | 周期「自定义」+ 每 2 周 + 结束条件「到某日」+ 12 月 31 日 |
| 每周一至周五 16:00 | 周期「自定义」+ 快捷「工作日（周一至周五）」+ 时刻 16:00 |

**判据**：任一样例无法在本表单里配置出来，或本表单能配出而列表无对应呈现（如星期只能取今天、不重复没有日期入口、自定义没有结束条件），即判缺陷。

## 边界与不做

- 本页**不收**归属人 / 参与人、备注、附件；位置只收用户手填的地点文字（P6 前不接地图、不做到达判定）。
- 不做「保存并再建一条」，不做「一次建多条」。
- 不做底层重复表达式（RRULE）编辑；只出六档 + 星期 / 日号 / 每年月日 / 自定义间隔与结束条件；工作日只作为自定义里的快捷。
- 不在此页设暂停、跳过或顺延：新建出来即启用；暂停、跳过这一次与删除都在编辑页。
- 不在客户端算下次触发时间，也不显示推算预览行。

## 待复核

- 提前量对周期提醒是否同样生效（PRD 未分单次 / 周期），原型按全部生效。
- 渠道的默认值（两者 / 站内信）未定，原型默认「两者」。
- 推送不可用的判定时机（进入页面查一次 vs 保存时才发现）未定，原型按进入页面即降级。
