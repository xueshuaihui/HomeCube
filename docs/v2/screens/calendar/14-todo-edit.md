# 14 · 编辑待办

| 项 | 值 |
|---|---|
| 路由 | `calendar/todo/edit` |
| 期 | ① |
| 权限 | **只有创建人与管理员可进**（儿童仅能改自己创建的）；被指派的负责人不进本页——她/他只能勾选完成与回应（5.5.7 ㉛），详情页对其不渲染「编辑」。访客不渲染 |
| 原型 | [todo-edit.html](../../prototypes/todo-edit.html) |
| 状态帧 | [默认](../../prototypes/todo-edit.html) · [版本冲突](../../prototypes/todo-edit.html?state=conflict) · [已保存](../../prototypes/todo-edit.html?state=saved) · [离线](../../prototypes/todo-edit.html?state=offline) |

**一屏说清**：本页是日历面「待办」段下的编辑页（`calendar/todo/detail` → 本页），与新建同构，差别只在保存时要核对「我打开之后有没有别人改过」。被改过时**不悄悄顶掉对方**：弹层说清「这条待办已被他人修改」，只在「用我的 / 保留对方」之间二选一，页面不做字段自动合并，也不显示任何版本号。改成周期待办后，「跳过这一期 / 顺延一次」也在这里做——它们是**实例动作**，只改这一期，不产生新版本、不改规则本体。

## 交互表

| # | 元素 | 触发 | 反馈 | 去向 |
|---|---|---|---|---|
| ① | 返回 | 点击 | 回待办详情；**有未保存改动时先弹「放弃这次修改？」确认**（继续编辑 / 放弃），放弃后不做草稿；返回不会触发合并 | 待办详情（`calendar/todo/detail`） |
| ② | 标题 | 输入 | 必填、≤60 字；为空时红框 + 行内错误，不弹全局错误层 | 留在本页 |
| ③ | 截止时间 | 点击 | **页面内自绘的月历与时分步进**（精确到分钟，不用原生日期控件外观）；改期直写本面对象、到期项随对象更新；不发撤销事件（原生对象不经 17.4），客户端不删日历条目 | 时间选择层 |
| ④ | 保存 | 点击 | 提交时核对是否被他人改过；没被改过则保存成功进「已保存」；被改过则弹冲突层且不写入 | 冲突层 / 已保存态 |
| ⑤ | 冲突弹层 | 保存时发现已被他人改过 | 展示修改人、时间与差异摘要；二选一：**「保留对方」**（丢弃本地改动、按对方的最新内容重开本页）/ **「用我的」**（以本地字段整体写入）。不出现整条置换这类说法，也不显示版本号 | 详情 / 已保存态 |
| ⑥ | 跳过这一期 | 点击（仅周期待办） | 二次确认「跳过今天这一期？」；确认后这一期不再到期、不提醒，规则本体与其余字段不动，**不产生新版本**；页内回显「本次已跳过 · 下次 10 月 30 日 19:00」 | 留在本页 |
| ⑦ | 顺延一次 | 点击（仅周期待办） | 二次确认「顺延到明天 19:00？」；确认后这一期改到下一次的同一时刻，**只改这一期**、不产生新版本、不改规则；页内回显同上 | 留在本页 |

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 从详情进入 | 预填标题、负责人、截止、重复与备注；顶部只写「上次修改：妈妈 · 今天 09:12（截止时间）」，**不显示版本号** |
| 冲突 | 保存时发现已被他人改过 | 表单降透明锁定，弹层置顶；弹层内给修改人、旧值与新值、你改了什么，以及「用我的 / 保留对方」两个互相排斥的动作 |
| 已保存 | 用我的或正常保存成功 | 顶部绿色说明「已保存 · 到期项已按新截止更新」；不出现版本号，也不写「版本已更新为 N」 |
| 离线 | 无网 | 顶栏下细条 + 顶部说明：改动先存本机，联网后重放；那时若别人又改过，仍走冲突二选一，不悄悄顶掉对方 |

## 字段与校验（页面级硬规则）

- **保存前核对是否被他人改过**：提交时带上打开页面时的对象版本；不一致就返回冲突并给双方内容，UI 不写入、不自动合并，也不悄悄重拉覆盖用户输入。
- **冲突二选一互斥（定版）**：**「用我的」**= 以本地字段整体写入；**「保留对方」**= 丢弃本次改动、按对方最新内容重开本页。两个动作在同一层出现，不出现「稍后再说」，也不出现整条置换。**页面任何位置不显示「版本 N」**，用户只需要知道「谁在什么时候改了什么」。
- **跳过 / 顺延（实例动作，定版）**：只在**本页**触发，都是对「这一期」的动作，**不产生新版本、不改规则本体、不动其余字段**；每期只能跳过一次 / 顺延一次，二次触发沿用同一条实例不叠加。列表与详情只回显结果（「本次已跳过 · 下次 10 月 30 日 19:00」），不留跳过 / 顺延入口。非周期待办不渲染这两个入口。
- **改截止的到期项语义**：直写本面对象（`calendar_todo`），到期项随对象按新截止更新，旧项随对象失效；原生对象不经 17.4，不发 `{code}.due.registered` / `{code}.due.revoked`；客户端不直接删日历条目，页面不承诺即时生效。
- **重复规则**：档位与新建页同一套（不重复 / 每天 / 每周 / 每月 / 每年 / 自定义，工作日是自定义内的快捷），改规则同样只存规则、不预生成实例；**每月 29 / 30 / 31 日而该月没有这一天时，该月不生成、不顺延、页面不报错**。
- **不可改字段**：来源面、创建人、完成状态（完成在详情，且只进不退）；被指派者连本页都进不来。
- **标题校验**与新建一致；「上次修改」只读展示，不可手改。

## 边界与不做

- 本页**不做**字段级合并、差异编辑器与实时协同（P1 无占用锁，靠保存时的核对兜底）。
- 本页**不做**子任务与附件的维护：子任务在详情勾选与新增，附件在 P1 待办里没有字段。
- **不做删除**：待办删除只在详情的「已归档」态出现；本页不做归档。
- 冲突时不清空用户已填内容，也不在后台重试保存。
- 不做「本次及以后全部跳过」这类批量实例动作。

## 待复核

- 原型从默认态保存直接落到冲突帧，用于演示二选一；「已保存」帧由「用我的」到达。实做正常保存成功应直接进已保存态。
- 冲突层只给一行差异摘要（截止时间），未定是否展示字段级 diff。
- 顺延的目标时刻默认取「下一次同一时刻」，PRD 未写死是否允许用户改到任意时刻；本版固定为下一次同一时刻。
- 编辑保存成功后是否回到详情而不是停留在本页，未定。
