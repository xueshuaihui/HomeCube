# 14 · 编辑待办

| 项 | 值 |
|---|---|
| 路由 | `calendar/todo/edit` |
| 期 | ① |
| 权限 | 创建人、负责人与管理员可改；儿童仅能改自己创建的；其余角色详情页不渲染「编辑」 |
| 原型 | [todo-edit.html](../../prototypes/todo-edit.html) |
| 状态帧 | [默认](../../prototypes/todo-edit.html) · [版本冲突](../../prototypes/todo-edit.html?state=conflict) · [已保存](../../prototypes/todo-edit.html?state=saved) · [离线](../../prototypes/todo-edit.html?state=offline) |

**一屏说清**：本页是日历面「待办」段下的编辑页（`calendar/todo/detail` → 本页），与新建同构，差别只在「带 version 保存」。版本落后时**不静默覆盖**：弹层说清「这条待办已被他人修改」，给查看最新 / 用我的 / 放弃修改三选一，页面不做字段自动合并。

## 交互表

| # | 元素 | 触发 | 反馈 | 去向 |
|---|---|---|---|---|
| ① | 返回 | 点击 | 回待办详情；未保存改动丢弃，不做草稿；返回不会触发合并 | 待办详情（`calendar/todo/detail`） |
| ② | 标题 | 输入 | 必填、≤60 字；为空时红框 + 行内错误，不弹全局错误层 | 留在本页 |
| ③ | 截止时间 | 点击 | 改期直写本面对象、到期项随对象更新；不发撤销事件（原生对象不经 17.4），客户端不删日历条目 | 时间选择层 |
| ④ | 保存 | 点击 | 带 version 提交；版本一致则保存成功，版本落后则弹冲突层，不写入 | 冲突层 / 已保存态 |
| ⑤ | 冲突弹层 | 保存时版本不一致 | 展示修改人、时间与差异摘要；三选一：查看最新（丢弃本地改动）/ 用我的（整体替换并升版本）/ 放弃修改（回详情） | 详情 / 已保存态 |

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 从详情进入 | 预填标题、负责人、截止与备注；顶部显示「版本 3 · 上次修改：妈妈 今天 09:12」 |
| 冲突 | 保存时版本已变 | 表单降透明锁定，弹层置顶；弹层内给修改人、旧值与新值，以及三条互相排斥的动作 |
| 已保存 | 用我的或正常保存成功 | 顶部绿色说明「已保存 · 版本已更新为 4 · 到期项已更新」；版本号同步更新 |
| 离线 | 无网 | 顶栏下细条 + 顶部说明：改动先存本机，联网后带 version 重放，届时若版本已变仍走冲突三选一 |

## 字段与校验（页面级硬规则）

- **version 乐观锁**：提交携带打开页面时的 version；不一致返回 409 与双方版本，UI 不写入、不自动合并，也不悄悄重拉覆盖用户输入。
- **冲突三选一互斥**：查看最新 = 丢弃本次改动回详情；用我的 = 用本地字段整体替换并升版本（不保留对方改动）；放弃修改 = 回详情。三者在同一层出现，不出现「稍后再说」。
- **改截止的到期项语义**：直写本面对象（`calendar_todo`），到期项随对象按新截止更新，旧项随对象失效；原生对象不经 17.4，不发 `{code}.due.registered` / `{code}.due.revoked`；客户端不直接删日历条目，页面不承诺即时生效。
- **不可改字段**：来源面、创建人、完成状态（完成在详情，且只进不退）。
- **标题校验**与新建一致；`version` 与「上次修改」只读展示，不可手改。

## 边界与不做

- 本页**不做**字段级合并、差异编辑器与实时协同（P1 无占用锁，靠 version 兜底）。
- 本页**不做**子任务与附件的维护：子任务在详情勾选，附件只读。
- **不做删除**：待办只有归档；归档在详情。
- 冲突时不清空用户已填内容，也不在后台重试保存。

## 待复核

- 原型从默认态保存直接落到冲突帧，用于演示三选一；「已保存」帧由「用我的」到达。实做正常保存成功应直接进已保存态。
- 冲突层只给一行差异摘要（截止时间），未定是否展示字段级 diff。
- 「用我的」是否再加一次二次确认，PRD 未写死，本版一次确认。
- 编辑保存成功后是否回到详情而不是停留在本页，未定。
