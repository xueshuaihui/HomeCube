# 19 · 新建日程

| 项 | 值 |
|---|---|
| 路由 | `calendar/calendar/create` |
| 期 | ①（P1-M1，㉛ 补页） |
| 权限 | 成人成员（16.3 日历行 M 格，建后 `owner` = 创建人）与管理员（A 格）可建；儿童（有账号）与访客不可进本页——不渲染入口、不置灰，直达落「无权限」态 + 返回；无账号儿童仅可被选为参与人（监护人代挂） |
| 原型 | [calendar-create.html](../../prototypes/calendar-create.html) |
| 状态帧 | [默认](../../prototypes/calendar-create.html) · [保存中](../../prototypes/calendar-create.html?state=submitting) · [校验未过](../../prototypes/calendar-create.html?state=invalid) · [保存失败](../../prototypes/calendar-create.html?state=fail) · [离线](../../prototypes/calendar-create.html?state=offline) · [无权限](../../prototypes/calendar-create.html?state=denied) |

**一屏说清**：新建日程是日历面「日程」段下的写页（㉛ 补页；此前日程在客户端不可建，本页与编辑页同批补进分包）。只收六件事——标题、起止（整日 / 带时刻两类，互斥）、参与人、重复、可见范围（家庭共享 / 个人），外加可选的提前提醒。三处入口的步数预算（IA §6.3）：日程二级 Tab 右上「＋ 新建日程」= 2 步、到期中心日格热区「＋」= 2 步（日期预填）、全局「＋」→「日程」= 3 步；**家庭共享与个人两类可见范围各自都在这份 ≤3 步预算内建成**（19.4#1 的「家庭日程 / 个人日程」两个样本就是这两条链路）。保存成功 `redirectTo` 日程详情（`calendar/calendar/detail`）；本页只消费 `POST /api/calendar/events`，不为补页新增接口（5.8 计数不变）。

| 态 | 触发 | 呈现 |

## 字段与校验（页面级硬规则）

- **标题**：必填、非空、≤60 字，只做首尾空白裁剪；为空时红框 + 行内错误，不用 toast / 弹层；绕过客户端直发时服务端按 400 拒绝（必填 = `title` + `start_at`）。
- **起止**：整日（`date`）与带时刻（`date + time`）两类互斥（5.5.1），同填按 400 拒绝、页面不提交；`end_at` 选填、填了必须晚于 `start_at`，否则标红不提交、不落库（行数不变）。
- **异常时间 · 已是过去**：所选开始时间早于当前家庭时间 → 行内提示、允许保存（记录既往）、服务端不再为其排任何未触发的提醒、详情页不出现「下次提醒」；**客户端不得自行顺延成未来时间来「修正」**。
- **异常时间 · 每月日号不存在**：每月重复取 29 / 30 / 31 日而该月没有这一天时，**该月不出现该日程、不触发、页面不标错**；规则行保持原日号，是否落补到别日**只认服务端回显**，本页与客户端一律不推算、不自顺延。
- **异常时间 · 节假日与调休**：本页**不判节假日与调休**——不顺延、不提前、不置灰、不弹确认；展示与保存一律按用户所选的原值，若服务端日后调整，以再次进入页面时的服务端回显为准。PRD 对此无句，本条为本页先立的保守口径（见待复核）。
- **下次触发 / 提醒时刻一律取服务端按家庭时区计算的回显**：本页不显示任何本地推算的触发预览行；客户端不得自行推算触发时间。
- **参与人**：多选、取本家庭 `Member` 引用（5.5.1）；无账号成员由监护人代挂、写入行带 `on_behalf_of`（3.4.1）；儿童（有账号）可作参与人，但**不可作为本页创建人**（见下条权限）。
- **重复**：只存规则行 + 日程行（`calendar_event` 1 条 + `calendar_recurring_rule` 1 条），**不预生成实例行**（5.5.1:810）；档位取 5.5.3 的**六档封闭枚举（含「自定义」）**，`RecurringRule.applies_to` 的 `event` 值即本页写入（5.7）；**「跳过 / 顺延」不在本页**——它们是对某一次触发的实例动作（编辑页）。**顶层只放枚举**：把「每周三」「每月 31 日」这类实例值画成并列档位即判缺陷。
- **提前提醒**：设置后由服务端把该提醒挂到本日程（`calendar_reminder.calendar_event_id`，5.5.1）；档位选择器的可选值**恰为 5.5.3 第一层四档**，多一档少一档都不通过；17.4 注册契约的触发点（到期前 3 天 / 当天那类）属另一层，**不得混进本选择器当选项**。
- **可见范围**：`visibility` = 家庭共享 / 个人两态（5.5.1）；个人态的裁剪发生在服务端（到期中心、首页今日区与非参与人读取同受控），**客户端不出现任何权限判断分支**（18.7 第 4 条）。
- **权限**：16.3 日历行——成人成员（M 格，「创建与编辑自己的」）与管理员（A 格）可建，建后 `owner` = 创建人；**儿童（有账号）无日程创建权**（其格子只授「创建自己的待办 / 提醒」，16.3 日历行），访客同样无权——两者不渲染本页入口、直达落「无权限」态 + 返回；**无账号儿童不可创建，只能被选为参与人（监护人代挂）**。本页不存在「儿童代建日程」的第三种形态，儿童场景由待办承载（5.5.2 ㉛）。
- **写口**：`POST /api/calendar/events`（5.8 用户侧写口；本面接口计数 **14** 条——㉛ 补页一条也不新增，14 相对旧数 13 的 +1 是 `POST /api/calendar/todos/{id}/claim`（5.8:936 的认领口），与本页无关）；请求携带客户端请求标识，离线重放不产生第二条（与 17.4 契约键互不替代，5.2 工程约定）。
- **保存承诺**：成功文案固定「已保存」，`redirectTo` 详情页（§2.3 的 create 语义）；不得写「已加入日历」，不承诺即时上日历。

## 边界与不做

- 本页**不收**地点、备注、附件与提醒渠道：渠道与暂停在提醒页维护，本页只定「提前提醒的档位」。
- 不做「保存并再建一条」、不做批量建、不做草稿箱；未保存内容在「放弃？」确认后即丢弃，不写任何对象。
- 不可从本页进入日程编辑；编辑页（`calendar/calendar/edit`）也不可反向成为本页入口之外的第二建口。
- 不在客户端算任何触发 / 提醒时间，也不显示本地推算的「下次触发」预览。
- 不做重复规则的表达式编辑（不开放 cron / RRULE 文本）；档位只有六档封闭枚举，档外入口一律不出现。
- 儿童与访客不可建日程（16.3），本页不为无权限角色出现「置灰可看」形态。

## 待复核

- 节假日 / 调休口径 PRD 无句，本页先立「不判、不顺延、只认服务端回显」的保守口径；是否引入家庭工作日集合影响展示属后续裁决——待办 / 提醒系列页存在同一缺口，建议按本页口径回写。
- 5.5.3 的周期规则含「自定义」档；本页按 N7 定版落六档，自定义档的间隔（每 N 天 / 周 / 月）与结束条件（永不 / 到某日 / 共 N 次，含「工作日」快捷）都是档内取值，不再待定。
- 编辑页「另存为新日程」是 §4.4 登记的**可选**进页来源（非必经），本版不做。
- 参与人是否设人数上限、代挂是否需二次确认，PRD 未写；原型按无上限、无二次确认。
