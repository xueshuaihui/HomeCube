**一屏说清**：本页是**日历面的一级页**（面内二级 Tab「日程」），概念名「到期中心」，**用户可见标题一律是「日历」**（「到期中心」不进任何 UI 文案）。它是全平台唯一的时间聚合页：把**本面原生三对象**（`CalendarEvent` / `Todo` / `Reminder`，不经注册契约、直接由 `svc-calendar` 持有）与**各面按 17.4 注册进来的到期项**按日 / 周 / 月铺开。**P1-M1 的视图恰为日、周、月三个**；不出现第四个视图 Tab、入口或判据。本页有**三处日程新建入口**——顶栏「＋ 新建日程」（⑧）、当前视图日期条上的「＋」（⑨）与空态 CTA；**三处全部落 `calendar/calendar/create`**，不得指向旧路由。步数与 19 卡「日程二级 Tab 右上『＋ 新建日程』= 2 步、到期中心日格热区『＋』= 2 步（日期预填）」逐字对齐。它只读已出生服务（P1 = `calendar` + `finance`）的注册项——未出生、未启用的面在这里不出现、不占位，也不产生空事件。进本页的路径有**三条**：**首页 C 区日历格 → 本页**、**首页 B 今日区「日历 ›」深链**、**「我的 → 时间与提醒」深链**（IA §1.3 第 13 条，只加不减；两条深链都是指向 `calendar/calendar/index` 的定向入口、不是面切换器，§12.10 第 1 条）；自面内切到别的面恒定 3 步（回本页 → D 行「首页」→ 点目标格）。

## 字段与校验（页面级硬规则）

- **视图封闭为日 / 周 / 月三个**：与 19 / 20 卡同口径；页面不得出现第四个视图 Tab 或入口，也不得在判据里要求第四个视图。三视图共用同一份聚合数据，只换铺法。
- **新建日程三处入口同一条路由**：顶栏 ⑧、当前视图「＋」⑨、空态 CTA 全部落 `calendar/calendar/create`，不得指向旧路由或旧页面；⑧ 与 ⑨ 各自 2 步落库，空态 CTA 也是 1 步进页。
- **月视图格内条数上限与「更多」**：格内最多铺 2 条短条；第 3 条起不挤进格内，改显「+N」；点该日后的下方列表全量展开当日条目，不分页、不折叠——这就是本页的「更多」行为。格内不铺条目标题，避免 7 列宽度下信息互相遮挡。
- **周视图今天组全量展开**：今天组与其余日期组同一规则，全部条目直接列出；不折叠、不出「还有 N 项」、不把今天组做成可点开的摘要。
- **空态按当前视图解释**：月视图说「本月」、日视图说「今天」、周视图说「本周」；空态必须给可执行 CTA（新建日程 + 新建待办），不写「去别处看看」这类空话。
- **首屏失败不展示旧数据**：整页失败态只给说明、错误码与 ⑩ 重试；网格、视图切换与半截列表一律不渲染，也不拿离线缓存冒充首屏成功。
- **只聚合已出生服务**：**两类来源并存**——本面原生三对象（`CalendarEvent` / `Todo` / `Reminder`，由 `svc-calendar` 直接持有、**不经注册契约**）+ `finance` 等已出生面按 17.4 注册进来的到期项；未出生面不预建注册行、不占位，未启用或被停用面的注册项不显示、不触发。
- **本面是必选面**：面目录里日历面恒启用、管理员不得停用、客户端不渲染它的开关（18.8 ㉚）；因此本页不存在「未启用」态，只有「暂不可用」态。
- **排序**：同一视图内按到期时间升序；跨天按天分组，组内仍按时间。
- **今天**：按家庭时区判定；跨 0 点后重新取当期聚合，不靠客户端定时器重排。
- **月格短条只表示「有注册项」**：不按面分色——面的区分只在条目的来源标记上做一次；「+N」只表示超出 2 条的数量，不是优先级或加急。
- **来源标记唯一形态**：面名 + 面图标 + 面色令牌，不引入第二套「事件类型」图形，也不硬编码面清单。
- **状态词固定四种**：待处理 / 待缴 / 待提醒 / 已完成；不引入优先级、紧急度字段（与 5.5.4 到期中心同口径）。
- **完成不在列表做**：勾选与完成回写在事件详情或源对象里完成，避免本页与 `done_returns_to` 各改一次。
- **撞车软提示（不拦截、不是冲突判定）**：两人可能给同一人约同一时段。当为某成员新建日程 / 指派待办且该成员**当日已有条目**时，新建与指派页给一条软提示「TA 这天已经有 N 件事」，「继续保存」为普通中性动作、**不是拦截，也不进 409 冲突流程**。数据来源 = 服务端按该成员 + 该日聚合的当日条目计数（与本页日视图同一份聚合、同一请求口径，个人可见范围按 16.4 由服务端裁剪后再计数）；判定时点 = 选人后实时查一次 + 保存请求到达时服务端再判一次，两次都只提示、不改写用户的保存结果。本页自身不弹这条提示——提示发生在新建 / 指派动作上（⑧⑨ 的去向页与待办指派）。
- **时间的异常兜底（引用 19 / 20 卡口径、不得另算一套）**：① **已是过去**——新建 / 编辑页给行内提示但**允许保存（补录）**，本页按原值展示、不给「下次」预告；② **每月 31 日类日期在该月不存在**——该月不出现、不触发、不标错，**不自动顺延**，落补只认服务端回显；③ **节假日与调休**——本页不判、不顺延、不置灰、不弹确认，展示按用户所选原值。跨 0 点重拉当期聚合，客户端不自行推算任何触发时刻。
- **样例**：本页与详情页统一使用「小满家长会」（周三 15:00–16:00，参与人 妈妈 / 小满）与「妈妈体检」（11 月 12 日 09:30）；不再借用财务账单名做人名/事项样例，避免与财务面样例冲突。

## 边界与不做

- 本页承载**日程新建的三处入口**（⑧ 顶栏「＋ 新建日程」、⑨ 当前视图「＋」、空态 CTA → `calendar/calendar/create`，㉛）；表单不在本页——待办 / 提醒的新建走各自创建页，编辑与完成在日程详情和源对象里做。
- 不做农历、拖拽改期；P1 只有日 / 周 / 月三个视图，不提供第四个视图入口或判据。
- 不轮询各面私有库；本面是**唯一持有定时器与触发方的服务**（17.4 ㉚），其余业务面一律经注册契约进来；触发事实由 `svc-calendar` 发出（`calendar.reminder.fired`），**投递与推送仍由底座完成**，本页不直连任何推送通道。
- 空态不出现「未启用 / 即将上线」等降级词来占位；这类词只用于面级降级，不用于时间聚合。
- 本分包不得放面切换器、「开通更多面」引导位或第二处面入口（⑫ 门禁 4）。

## 待复核

- 原型里点日历格以提示返回当日条数，实做应把下方列表切到该日（同一份数据，不新增请求）；月视图「+N」的点击落点也复用这条切换。
- 样例今天取 10 月 29 日（周四），与其他原型屏保持一致；「本月 19 项」为演示数值。
- 「服务不可用」帧演示的是 `svc-calendar` 不可达时本面的降级；同一注入下首页 B 今日区与 C 区日历格应同时进入「暂不可用」，两屏用同一条时效戳（见 05 首页 ⑥⑧）。
