**一屏说清**：到期中心是**日历面的一级页**（面内二级 Tab「日程」），也是全平台唯一的时间聚合页：把**本面原生三对象**（`CalendarEvent` / `Todo` / `Reminder`，不经注册契约、直接由 `svc-calendar` 持有）与**各面按 17.4 注册进来的到期项**按日 / 周 / 月铺开。它只读已出生服务（P1 = `calendar` + `finance`）的注册项——未出生、未启用的面在这里不出现、不占位，也不产生空事件。进本页的路径有**三条**：**首页 C 区日历格 → 本页**、**首页 B 今日区「日历 ›」深链**、**「我的 → 时间与提醒」深链**（IA §1.3 第 13 条，只加不减；两条深链都是指向 `calendar/calendar/index` 的定向入口、不是面切换器，§12.10 第 1 条）；自面内切到别的面恒定 3 步（回本页 → D 行「首页」→ 点目标格）。

## 字段与校验（页面级硬规则）

- **只聚合已出生服务**：**两类来源并存**——本面原生三对象（`CalendarEvent` / `Todo` / `Reminder`，由 `svc-calendar` 直接持有、**不经注册契约**）+ `finance` 等已出生面按 17.4 注册进来的到期项；未出生面不预建注册行、不占位，未启用或被停用面的注册项不显示、不触发。
- **本面是必选面**：面目录里日历面恒启用、管理员不得停用、客户端不渲染它的开关（18.8 ㉚）；因此本页不存在「未启用」态，只有「暂不可用」态。
- **排序**：同一视图内按到期时间升序；跨天按天分组，组内仍按时间。
- **今天**：按家庭时区判定；跨 0 点后重新取当期聚合，不靠客户端定时器重排。
- **月格的点只表示「有注册项」**：两项以上用短条，不按面分色——面的区分只在条目的来源标记上做一次。
- **来源标记唯一形态**：面名 + 面图标 + 面色令牌，不引入第二套「事件类型」图形，也不硬编码面清单。
- **状态词固定四种**：待处理 / 待缴 / 待提醒 / 已完成；不引入优先级、紧急度字段（与 5.5.4 到期中心同口径）。
- **完成不在列表做**：勾选与完成回写在事件详情或源对象里完成，避免本页与 `done_returns_to` 各改一次。

## 边界与不做

- 本页**只读**：新建在 `＋` / 待办 / 提醒，编辑与完成在详情与源对象，本页不放写入口。
- 不做年视图、农历、拖拽改期；P1 只有日 / 周 / 月三视图。
- 不轮询各面私有库；本面是**唯一持有定时器与触发方的服务**（17.4 ㉚），其余业务面一律经注册契约进来；触发事实由 `svc-calendar` 发出（`calendar.reminder.fired`），**投递与推送仍由底座完成**，本页不直连任何推送通道。
- 空态不出现「未启用 / 即将上线」等降级词来占位；这类词只用于面级降级，不用于时间聚合。
- 本分包不得放面切换器、「开通更多面」引导位或第二处面入口（⑫ 门禁 4）。

## 待复核

- 原型里点日历格以提示返回当日条数，实做应把下方列表切到该日（同一份数据，不新增请求）。
- 样例今天取 10 月 29 日（周四），与其他原型屏保持一致；「本月 19 项」为演示数值。
- 周视图「今天组只展开前两条」为原型选择，是否改为全展开待定。
- 二级 Tab 的「设置」在 18.3 定版的四项里（日程 / 待办 / 提醒 / 设置），但**不在日历面 P1 的 9 页路由位内**（实建 9 = 日历 2 + 待办 4 + 提醒 3）；已由 IA §4.4 的 Tab 账法裁决为跨包指向主包 `homeos/settings/index`（§1.2 L2 行：允许跨包、不得新增路由位），原型已改为真实链接、不再是未交付项。
- 「日历 · 日程」在 P1 的 9 页路由位里没有独立新建页：全局「＋」热区 ③ 把它指向本页的到期中心日格承接（见 `../homeos/20-quick-add.md` 待复核），是否为日程补独立新建路由位待定。
- 「服务不可用」帧演示的是 `svc-calendar` 不可达时本面的降级；同一注入下首页 B 今日区与 C 区日历格应同时进入「暂不可用」，两屏用同一条时效戳（见 05 首页 ⑥⑧）。
