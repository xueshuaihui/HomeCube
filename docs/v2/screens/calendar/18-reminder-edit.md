**一屏说清**：本页是日历面提醒的编辑页（`calendar/reminder/index` → 整行进本页），字段与新建同构，多四件事——**暂停即时生效**（停触发、留规则）、**跳过这一次**（只让下一次不响，规则不动，可撤销）、**改动范围二选一**（改时间 / 周期 / 提前量时，先问「仅这一次」还是「之后全部」；只有「之后全部」才改规则本体，「仅这一次」是实例动作）、**保存带 `version`**，内容有变动就三选一，不自动合并且**任何用户可见文案不出现版本号与「覆盖」字样**。保存成功回提醒列表并高亮这条——提醒没有详情页（P1 不建 `calendar/reminder/detail`），列表行就是「该对象」的落位。**删除整条提醒要二次确认**，并在两层都说明已排期的触发会一并取消。

## 字段与校验（页面级硬规则）

- **保存带 `version`**：对象级乐观锁（3.4.4）；409 时弹三选一，不自动合并字段、不悄悄重拉重发；`version` 号是内部值，**不得出现在任何用户可见文案**。
- **冲突三选一互斥**（§6.5，与财务面同口径）：「查看最新」= 丢弃本次改动并重拉、「用我的」= 以当前表单整体重发、「放弃修改」= 离开本页；文案与按钮不出现「覆盖」二字；「用我的」用中性样式——红色危险钮只留给不可逆动作。
- **暂停即时生效**：独立写路径，不等保存；只停触发，不改周期、不清历史、不产生新版本号。
- **跳过这一次（实例动作）**：只作用在**下一次未触发的实例**上——该次不再触发，规则行与之后的每一次都不变；**即时生效、不等保存、不产生新版本号**（与暂停同口径）。**顺延到哪**：由服务端按原规则算出的下一个触发点回显（每周三 15:00 跳过 11 月 4 日那次 → 下次显示 11 月 11 日 15:00），客户端不推算、不自行顺延。**可撤销**：被跳过的那一次尚未到点时可撤，撤销后该次恢复触发；已到点则撤销入口消失，不追溯历史。**跳过是唯一的「只影响一次」动作**：删除只删整条，不提供「只删这一次」。**判据**：`?state=skipped` 帧给「本次已跳过 · 下次 <服务端回显>」，「撤销跳过」回到的下一次值可测。
- **改动范围（重复项的两档语义）**：这条是重复提醒且改了时间 / 周期 / 提前量任一项时，保存前**必须**给范围二选一——**「仅这一次」**= 实例动作，只有那一次按新值走，规则行与以后每次不变，列表里那一次带「本次已单独调整」标记；**「之后全部」**= 改规则本体，规则行整条更新（`version` +1），旧到期项随对象失效、新排期由服务端重算回显。**默认选「仅这一次」**（较轻的一档）；**取消范围层不提交、改动留在表单**。判据：同一处改动分别选两档，落库差异可测（一档只影响单次触发、一档影响规则行）；不重复的提醒**不出这层**。
- **删除语义（二次确认，删整条）**：第一层确认给条目摘要 +「已排期的触发会一并取消」+「继续删除」；第二层再确认「删除后已经排好的下一次和以后每次都不会再响」+「确认删除」。删除的是**整条提醒**（规则与全部未来触发），确认后由服务端级联失效其到期项、**已排期的触发一并取消**，**不可恢复、无回收站**；不提供「只删这一次」（那件事由「跳过这一次」承担）。默认焦点落在「取消」，危险钮不作默认焦点；已发出的站内信不撤回（投递归底座）。本面原生对象**不发** `{code}.due.revoked`（该事件只属于他面注册项）。
- **字段校验与新建一致**：标题必填 ≤60 字；时间按家庭时区解释且**时间档必须齐备**（不重复 = 日期 + 时刻；每天 / 每周 / 每月 / 每年 / 自定义 = 时刻，每周至少一天、每月至少一个日号、每年要填月与日、自定义要有有效间隔与结束条件）；周期**六档**（不重复 / 每天 / 每周 / 每月 / 每年 / 自定义）+ 星期多选 / 日号 / 每年月日 / 自定义间隔与结束条件，**不用今天的星期与日号兜底**；「工作日」只作为自定义里的快捷，不与主档并列；提前量四档封闭；渠道三选一并支持推送不可用降级。
- **每月 / 每年日号在该月不存在**（与 `19-calendar-create.md` 同句口径）：每月重复取 29 / 30 / 31 日而该月没有这一天时，**该月不出现该提醒、不触发、页面不标错**；每年 2 月 29 日遇到没有这一天的年份同理。规则行保持原日号，是否落补到别日**只认服务端回显**，本页与客户端一律不推算、不自顺延。
- **节假日与调休**：本页**不判**——不顺延、不提前、不置灰、不弹确认，一律按用户所选原值（与 19 卡同口径）；服务端日后调整以再次进入页面时的回显为准。
- **改时间 / 周期 / 提前量（选「之后全部」时）**：直写更新本面对象，整条到期项随对象更新，旧项随对象失效，不发撤销事件（原生对象不经 17.4），不由客户端删日历条目。
- **位置**：可选，≤30 字；只存用户填的地点文字，**P6 前不接地图与地理围栏、不做到达判定**，位置类提醒不计入到达率（工程口径，不进用户可见文案）。**这一版只按时间触发**：留空即普通时间提醒；填了位置也不改变触发条件，不会因为到了某个地方就提前响或另外响；**位置不顶替时间档**，本页不存在「只有地点、没有时间」的对象。新建页同字段同校验。
- **他人提醒只读**：`owner_id` ≠ 本人且非管理员时进本页落只读态——控件禁用 + 一句人话说明，**不是报错**，返回照常；管理员读写全部（16.3 日历行）。

## 边界与不做

- 本页**不改**归属人（`owner_id`）：提醒归属创建人，P1 不提供转移，也不提供「指派给家人」——要按周期提醒别人请建待办（`calendar/todo/create`，㉛）。
- 不做「另存为新提醒」「复制周期」；不做提醒触发历史列表。
- 删除不提供回收站、不可撤销：误删只能重建；跳过只留一次痕。
- 不做地图选点、半径与到达判定（P6 地图 SDK 出生期随该面复验时再开放，20.1）；位置**只接受手动文字**。
- 不在本页显示版本号、事件名、RRULE 原文与到达率口径。

## 待复核

- 暂停是否需要「暂停到某日自动恢复」：PRD 只写暂停，原型不做定时恢复。
- 「仅这一次 / 之后全部」的实例改动与「跳过本次」是否需要给历史留痕（本版只在列表下一次触发上带跳过标记，不做历史页）。
- 删除后是否留在列表并给出 toast，PRD 未写；原型直接回列表，建议实做补一条「已删除」提示。
- 版本冲突时的差异字段由服务端给出还是客户端对比未定，原型取服务端双版本 payload。
