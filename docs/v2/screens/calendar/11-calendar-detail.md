**一屏说清**：日程详情把一条条目还原成「什么时候、来自哪里、对应哪个对象、谁参与」。本页是日历面「日历」列表（`calendar/calendar/index`）的下钻页（导航路径：首页 C 区日历格 → 日历列表 → 本页），整页只读摘要，动作按来源分层：**注册型条目**（财务账单等经 17.4 注册的对象）保留「前往源对象」动作位，且**进页先给只读引导卡**（口径与 20 卡「注册型只读」态逐字一致——引导 + 前往，不是报错态）；**注册型条目只读，不渲染编辑与删除**。**日历原生对象不占源对象动作位**——原生日程由右上「编辑」承接（仅创建人与管理员，→ `calendar/calendar/edit`，㉛），原生待办在页底给「查看这条待办」回本面对象页。旧通知打开一条已软删或被撤销的条目时落「该日程已不存在」态，给「返回日历」动作、不渲染任何半截字段。

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 注册型（默认） | 财务来源等经 17.4 注册的到期项（样例：妈妈体检，11 月 12 日 09:30） | 大时间 + 标题 + 来源 / 状态徽标；④ 只读引导卡 + 关联对象带金额；主按钮「前往源对象」指向来源页；**无「编辑」入口、无删除入口** |
| 日历面原生待办 | 本面原生待办对象（样例：接女儿放学 16:30） | 标题、时间、来源、关联对象与提醒随之切换；页底动作「查看这条待办」进 `calendar/todo/detail`；无「前往源对象」、无「编辑」入口 |
| 日历面原生日程 | 本面原生日程对象（样例：小满家长会，周三 15:00–16:00，参与人 妈妈 / 小满） | 右上「编辑」仅对创建人与管理员渲染 → `calendar/calendar/edit`；非创建人不渲染入口、页底只有摘要；不出现「前往源对象」与财务深链；与另一条时间重叠时只显示柔性提示「与「妈妈体检」时间重叠」，不阻塞、不改写时间 |
| 源面不可用 | 源面服务不可达 | 按钮置灰禁用，按钮上方说明「该来源暂时不可用，先看摘要；恢复后可从这里前往」；摘要、时间、参与人照常 |
| 离线 | 无网 | 顶栏下细条 +「摘要为缓存 · 截至 HH:mm」；按钮保持可用性判断，不因离线改写来源 |
| 条目已不存在 | 服务端返回该对象已软删、已撤销或 id 失效——旧通知深链打开的条目悬空时 | 整页态：图标 +「该日程已不存在」+ 一句解释（可能被创建人删除或已完成清理）+ ⑧「返回日历」；**不渲染半截字段、不白屏、不弹错误层**，其余条目不受影响 |

## 字段与校验（页面级硬规则）

- **源对象动作位按来源分层**：注册型条目（来源面不是日历，如财务账单）渲染「前往源对象」，由来源面 + 对象 id 决定定位，客户端不按标题、金额反推；未出生面只提示后续交付，不伪造路由。日历原生待办渲染「查看这条待办」；日历原生日程不占这个动作位。
- **注册型条目只读**：注册型日程不渲染「编辑」与「删除」，也不出现任何写入口；进页给只读引导卡「这条日程来自账单，由账单页维护时间；这里只能看摘要」+「前往源对象」；**是只读态、不是报错**，返回照常；本页绝不代来源面改任何值。
- **编辑入口渲染条件**：仅创建人（16.3 日历行 M 格「创建与编辑自己的」）与管理员（A 格）可见，仅日历原生日程可见；与 20 卡权限句逐字对齐——非创建人的成人成员、儿童与访客「详情页不渲染『编辑』入口、直达编辑页落『无权限』态 + 返回」；参与人可回应 / 可完成，但不可改本体、时间与重复规则。**本页不渲染删除。**
- **条目已存在的判定只认服务端**：是否「已不存在」以服务端响应（对象缺失 / 已软删 / 注册已撤销）为唯一判据；客户端不得拿缓存摘要冒充可继续操作的现状，也不得据此发起写请求。
- **源面不可用不白屏**：禁用按钮 + 一句可读说明，摘要至少包含标题、时间、来源、关联对象摘要。
- **参与人只读**：来自注册时快照；改名只改成员档案，不回写已注册项的历史参与人。
- **提醒设置只读**：时间、提前量、渠道只在日历面提醒页维护（`calendar/reminder/edit`）；本页展示的提前量档位**恰为四档封闭枚举（准时 / 提前 10 分钟 / 1 小时 / 1 天）**（5.5.3 第一层，㉛）——挂在日历对象上的提醒只出这四档，注册型条目展示的是其所属那一层的值，两层不得混排、UI 不得出现所属集合外的档位；本页不提供编辑，也不承诺「保存即生效」。
- **时间重叠只做柔性提示**：详情里出现「与「妈妈体检」时间重叠」这类提示时，只说明两条安排撞在同一时段，**不阻塞查看、不弹确认、不改写时间、不出现冲突判定词**；两条日程都保留，用户自行决定是否去编辑页调整。
- **时间的异常兜底（引用 19 / 20 卡口径、不得另算一套）**：① **已是过去**——新建 / 编辑页给行内提示但**允许保存（补录）**，本页按原值展示、不出现「下次提醒」预告；② **每月 31 日类日期在该月不存在**——该月不回显条目，本页不补位、不标错、**不自动顺延**；③ **节假日与调休**——本页不判、不顺延，展示按用户所选原值。大时间与「下次」类信息一律取服务端按家庭时区回显，客户端不自行推算。
- **状态与完成**：本页不设完成按钮；完成在源对象或待办详情里走 `done_returns_to` 回写，回写失败不影响本页展示。
- **样例**：默认条目「妈妈体检」是财务账单经 17.4 注册的**账单**（11 月 12 日 09:30）；日历原生日程样例为「小满家长会」（周三 15:00–16:00，参与人 妈妈 / 小满），原生待办样例为「接女儿放学」；不再借用财务账单名做人名/事项样例。三帧彼此独立、不共用同一条对象。

## 边界与不做

- 不做完成、归档、删除与表单编辑：编辑走 ②（→ 20 页），其余动作属于源对象或待办，详情只读；**注册型条目连编辑与删除入口都不渲染**。
- 不做评论、附件、@：留言板（底座）与源对象负责，本页不复制入口。
- 不做「重复规则编辑」：周期只在日历面提醒页改；他面注册项的改期由来源面按 17.4 重新注册；日历原生日程的改期、暂停与删除只走编辑页直写本面对象并由服务端级联失效其到期项，**不发** `{code}.due.revoked`（17.4 末注）。
- 不展示 L3 内容；被服务端裁掉的字段整行不渲染，不显示「无权限查看」。
- 本分包不得放面切换器（⑫）；回首页只走 ① 返回或 D 行「首页」。
- 重叠提示不改变任何动作：不因重叠禁用「编辑」、不禁用「前往源对象」、不弹二次确认；提示只出现一次，不堆叠多条。
