**一屏说清**：提醒列表是**日历面提醒的唯一入口**（面内二级 Tab「提醒」；导航路径：首页 C 区日历格 → 日历面 → 二级 Tab「提醒」→ 本页）。进本面的三条入口**只加不减**：首页 C 区日历格、首页 B 今日区「日历 ›」深链、「我的 → 时间与提醒」深链（IA §1.3 第 13 条）；两条深链都是指向 `calendar/calendar/index` 的定向入口、不是面切换器（§12.10 第 1 条）。一屏内看完每条的时间、周期、下次触发与启停。**开关即时生效、不弹确认**；位置提醒在 P6 前只有手动地点，顶部一行常驻说明不保证触达。

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 进入页面 | 顶部位置说明 + 汇总句 + 五条提醒：每天 / 每周 / 不重复 / 每月各有一条，另有一条已暂停；开关、周期、下次触发齐备 |
| 空 | 零条提醒 | 隐藏汇总与列表，给「还没有提醒」+「新建提醒」；位置说明仍保留 |

| 离线 | 无网 | 顶栏下细条 +「显示本机缓存 · 截至 HH:mm」；开关仍可操作，提示「联网后同步」 |

## 字段与校验（页面级硬规则）

- **一条提醒一个归属人**：`owner_id` 决定谁可改；他人提醒对非管理员只展示「已暂停 / 由某某创建」，开关置灰。
- **周期描述只用人话**：每天 08:00 / 每周一至周五 16:00 / 每月 1 日 09:00 / 不重复；不显示 RRULE 原文。
- **下次触发**：由服务端按家庭时区算出后下发，客户端不自行推算；已暂停的条目改显示「暂停中，不触发」。
- **开关即时生效**：切换即发写请求（带 `version`），不需要保存按钮；失败回滚开关并 toast。
- **位置提醒标记唯一形态**：「位置 · 手动地点」+ 地点文字；P6 前不出现地图、半径、到达判定。
- **排序**：启用在前、暂停在后；同组按下次触发时间升序。

## 边界与不做

- P1 **不建 `calendar/reminder/detail`**：单条规则在列表内展开，编辑走编辑页；不做提醒详情路由（日历面实建 9 页的账里不含它）。
- 本页不做批量启停、滑动删除、下拉刷新；删除在编辑页的弹层里。
- 不在这里显示「已触发 N 次」等统计：触发记录在底座消息页的 `reminder` 分组——**触发由 `svc-calendar` 发出（`calendar.reminder.fired`），投递与红点仍归底座**，本面不得自建站内信与推送。
- 不提供位置提醒的独立入口：新建与编辑同一套表单，位置是可选字段（`calendar/reminder/create` / `edit`），P6 前只收手动地点。
