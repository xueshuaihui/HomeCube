**一屏说清**：提醒列表是**日历面提醒的唯一入口**（面内二级 Tab「提醒」；导航路径：首页 C 区日历格 → 日历面 → 二级 Tab「提醒」→ 本页）。进本面的三条入口**只加不减**：首页 C 区日历格、首页 B 今日区「日历 ›」深链、「我的 → 时间与提醒」深链（IA §1.3 第 13 条）；两条深链都是指向 `calendar/calendar/index` 的定向入口、不是面切换器（§12.10 第 1 条）。一屏内看完每条提醒的**标题、周期、下次触发（含提前量）、创建人、渠道**——「谁建的、走哪条路」在本页可读，不必逐条进编辑页。**开关即时生效、不弹确认**；提醒一律**按时间到点响**，位置只是行上多带的一句补充地点，顶部一行常驻说明讲清这件事（位置不参与触发，P1 不接地图与地理围栏）。

## 字段与校验（页面级硬规则）

- **一行五件套**：标题 / 周期 / 下次触发（含提前量，如「提前 1 天」）/ 创建人 / 渠道——**五项缺一即缺陷**；「谁建的、走哪条路」不得靠进编辑页才知道。
- **创建人（归属）**：提醒对象**恒归创建人、不可指派他人**（要按周期提醒别人走待办）。本人创建的行显示「我创建」，他人创建的行显示「由某某创建」。**他人提醒对非管理员可见**，判据三条：**可见、开关置灰、带创建人**；管理员可改家庭内全部（16.3 日历行）。
- **渠道**：行上取「推送 / 站内信 / 推送 + 站内信」三值之一，取对象投递偏好的服务端回显；站内信落「消息 → 提醒」分组。渠道只是偏好，实际投递一律由底座完成，本面不直连任何推送通道。
- **每条提醒必须有一个时间档**：提醒是到点响的对象，位置只是附加上下文。列表内不存在「只有地点、没有时间」的行；**没有时间的提醒在保存那一步就被拦下**（见 `calendar/reminder/create` 字段校验），本页无需为它设计呈现。
- **周期描述只用人话**：每天 08:00 / 每周一至周五 16:00 / 每月 1 日 09:00 / 每年 11 月 12 日 09:30 / 每 2 周 周三 15:00 / 11 月 12 日 09:30；不显示底层重复表达式原文，不显示「周一、周二」式的原始枚举串。
- **下次触发**：由服务端按家庭时区算出后下发并回显，客户端不自行推算；已暂停的条目显示「暂停中，不触发」；**本次已跳过**的条目显示「本次已跳过 · 下次 <服务端回显>」（跳过动作与呈现形态只在编辑页，`calendar/reminder/edit` 的 `?state=skipped` 帧）。**提前量**随下次触发一起回显为「· 提前 1 天」这类短后缀，四档之外不出现。
- **开关即时生效**：切换即发写请求并携带 `version`，不需要保存按钮。**失败回滚（整句）**：请求非 2xx / 超时 → 开关退回原状态、整行还原原样（灰态、「已暂停」标记与下次触发文字一并还原）、toast「没有改成功，这条提醒还是原来的样子」；**不得留下「看着已暂停、其实还在响」或反过来的中间态**。离线时先改本机、入待同步队列并在行上标「联网后同步」，联网重放失败按同一句回滚。
- **位置提醒标记唯一形态**：「位置 · 手动地点」+ 地点文字；P6 前不出现地图、半径、到达判定；**位置不改变触发条件**，到点仍按时间响。
- **排序**：启用在前、暂停在后；同组按下次触发时间升序。
- **不显示的内部值**：`version` 号、对象编码、事件名、RRULE、到达率口径一律不进用户可见文案。

## 边界与不做

- P1 **不建 `calendar/reminder/detail`**：条目**整行进编辑页**看全字段、改规则与删除，列表不做行内展开（定版，与 12–15 的同族表单一致）；不做提醒详情路由（日历面实建页的账里不含它）。
- 本页不做批量启停、滑动删除、下拉刷新；删除与「跳过本次」都在编辑页的弹层里。
- 不在这里显示「已触发 N 次」等统计：触发记录在底座消息页的 `reminder` 分组——**触发由 `svc-calendar` 发出（`calendar.reminder.fired`），投递与红点仍归底座**，本面不得自建站内信与推送。
- **待办的截止不会自动产生提醒投递**：提醒是本面唯一由日历触发、由底座投递的通道，列表里不会出现「由待办自动生成」的提醒行。
- 不提供位置提醒的独立入口：新建与编辑同一套表单，位置是可选字段（`calendar/reminder/create` / `edit`），P6 前只收手动地点。
