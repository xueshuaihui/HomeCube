**一屏说清**：详情页回答「这笔什么时候到期、注册到日历没有、缴了之后钱记到哪」。`due_at` 用大号字（`10 月 31 日` + 周六 20:00 + 还剩 2 天 11 小时），其上只有状态（待缴 / 已缴）与 `version`；紧接着一张**只读的注册卡**，如实显示「已注册到家庭日历 / 尚未注册 / 已撤销」。底部「标记已缴」先弹确认层，确认后**本地立即置已缴**并显示「已缴 · 回写已提交」+ 已生成流水的去向，不等日历面结果；跨服务未收敛时只显示时效提示，不报错、不重复扣款。

## 字段与校验（页面级硬规则）

- **`due_at` 展示**：按家庭时区格式化为「M 月 D 日」，副行给星期 + 固定 20:00 + 相对剩余时间；剩余时间由服务端时间算，前端不用本地时钟倒计时；已缴后显示缴纳时刻与原到期日两个值。
- **注册状态三态只读**：已注册 / 尚未注册 / 回写已提交待撤销；状态由服务端结果决定，前端不得自推成「已上日历」或「已撤销」；提交与撤销的语义见 17.4。
- **回写与幂等**：标记已缴由 `svc-finance` 写状态并生成流水，再发 `finance.bill.paid` 给日历面置完成、撤销注册项；幂等键保证重复点击不生成第二条流水；页面只等本地结果，跨服务收敛 P95 ≤5s。
- **金额**：以「分」存储，展示 `-¥380.00`（负号在 `¥` 前）；已缴后改金额或到期日**不追溯已生成的流水**，文案要说清这一点，不能让用户以为改账单会改流水。
- **确认层不可省**：底部按钮不直接改状态；弹层里重复账单名、到期日与金额，确认按钮用 primary，取消用 secondary。
- **附件**：最多 3 张、单张 ≤5MB、jpg/png/webp（与设置页同一口径）；附件只存 `file_id`，文件本体归 HomeOS。
- **版本**：顶栏 `版本 4` 与编辑页的乐观锁同源；保存冲突返回 409，走编辑页的「这条记录已被修改」弹层。

## 边界与不做

- 不在本页改金额与到期日（编辑页负责）；本页只做「标记已缴」这一个写动作。
- 不做页内附件预览、在线编辑、OCR 识别；P1 只下载原文件。
- 不做「撤销已缴」「跳过本期」「改缴纳金额」：缴了就是一笔已生成流水，改金额会与流水对不上。
- 不展示日历事件 id、注册项 id 等技术字段；不提供「去日历看」的跨面跳转（切面只能回首页矩阵）。
- 不做发票信息（P1-M2）；不做多次部分缴纳。

## 待复核

- 已缴后编辑：原型允许进编辑页改备注与后续期次，金额 / 到期日的改动不追溯流水；若定版要求缴后锁定金额与日期，需在编辑页补 paid 只读态。
- 未注册的成因未分类（首次提交失败 / 日历面尚未消费 / 服务未出生），文案统一按「可能稍晚」处理，是否需要分型提示待定。
- 「重新提交」是否需要冷却与次数上限（避免用户连点产生多份请求），原型未加。
- 已缴横幅里的「通常 5 秒内」是否对用户可见：当前写进说明；注册卡不再写「已撤销」而写「等待日历撤销」，避免把未收敛的跨服务结果说成已完成。
