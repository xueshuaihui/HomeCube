**一屏说清**：一笔分账的完整证据链——原始金额、付款人、逐人分摊与净额、**`Σ净额 = 0` 的可见校验**、余数规则与关联流水。金额是共享流水的全额，不是我的分摊；状态只看各参与人净额是否全为 0，不用单独的开关维护。

## 字段与校验（页面级硬规则）

- **净额口径**：`净额 = 已付 − 分摊`；付款人已付为全额，其余为 0；同一分账 `Σ净额 = 0`，且 `Σ分摊 = 原始金额`（19.3#6）。
- **校验可见**：`净额合计 ¥0.00` 是页面上的断言行，不是仅服务端校验；以「分」整数相加，不靠四舍五入凑 0。
- **方向表达**：净额正为应收、负为应付，符号在 `¥` 前；同时给「应收 / 应付」文字，不只靠颜色。
- **个体结清与整体结清**：某人净额为 0 即该人已结清；全部为 0 才是分账已结清。已结清后金额、参与人、关联流水均只读。
- **余数**：沿用新建时的固定顺序（我 → 妈妈 → 爸爸），详情只回放、不重算；同一笔分账在任意端看到的逐人金额必须一致。
- **关联流水**：一对一引用原共享流水，金额与日期以流水为准；流水被改或删会同步影响分账，已结清的分账不能被编辑。
- **离线**：显示本机缓存的分摊与结清状态；结算动作仍走待同步队列，不把离线确认当成已写入。

## 边界与不做

- 不在详情页做行内改参与人、改金额或单独结清某人；结算统一进结算中心。
- 不复制流水、不生成第二笔原始支出；分账只是对同一笔共享流水的分摊视图。
- 不做分账物理删除；已结清只能整笔作废后重建，历史结清流水保留。
- 不展示「谁看过」或催收话术；结清是记账动作，不涉及真实资金划转。

## 待复核

- 已结清时间取最后一笔结清流水时间，还是分账 `settled_at`，待服务端字段口径确认。
- 个体结清后是否隐藏该人的「分摊」只留「已结清」，原型保留分摊以便回看，需视觉复核。
- 付款人之外的参与人「已付 ¥0.00」是事实展示，但可能被误读为未付款，是否改为「由我代付」，待文案确认。
- 分账与结算中心对「已结清」的刷新时序：结算后返回详情应实时归零，原型用状态帧演示，未做跨页轮询。
