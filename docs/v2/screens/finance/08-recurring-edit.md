## 字段与校验（页面级硬规则）

- **`version` 必带**：读取时展示「版本 N」，保存、暂停、删除都带当前 `version`；409 只给两条出路，不静默重试、不合并字段。
- **金额**：以「分」存储，正数录入；展示负数在 `¥` 前；改金额不回改历史流水，只影响下一期起的自动入账。
- **历史不受影响**：修改、暂停、删除都不改已生成流水；文案必须写明「照常参与报表、预算与账户余额」。
- **暂停语义**：`is_active=false`，`next_at` 停止推进；恢复后从下一个周期继续；暂停不删除规则、不清历史。
- **删除语义**：只删规则本体，不删流水；不可恢复；已生成流水仍在流水列表与报表里。
- **起止条件**：编辑只允许延长或提前结束，不改写历史入账；期数与「最后一笔」由服务端按 `next_at` 推算。
- **离线**：顶栏细条「保存后排队，已入账流水不受影响」；写操作带幂等键与 `version`，恢复联网后按序提交。
- **分类与账户**：改分类只影响之后的流水统计，已生成流水仍按原分类；账户只能换到未归档账户。

## 边界与不做

- 不做「立即入账 / 补跑上一期」，也不做「跳过本期」；这些会把规则与流水的事实关系弄乱。
- 不做删除后的撤销与回收站：规则删除不可逆，历史流水本身不受影响。
- 不做规则复制、批量暂停、跨账本迁移。
- 不在本页改账户余额或分类字典；也不在弹层里嵌套第二层确认。
- 不显示 RRULE 原文与逐期日历；周期只用人话。

## 待复核

- 暂停 / 删除是否也走 `version` 乐观锁（PRD 只写了编辑保存带 `version`），原型按全部写操作带 `version` 处理。
- 冲突文案里的版本号与金额示例：原型用版本 4（¥4,200.00）对版本 5（¥4,350.00），若后端冲突载荷只回版本号，需要补金额对比。
- 成人成员对他人规则是否可见：原型按「可见但只读」呈现；若按 `owner_id` 过滤需补无权态。
- 「用我的」后版本号是否一定 +1 到 6，取决于服务端合并策略，原型按 +1 展示。
