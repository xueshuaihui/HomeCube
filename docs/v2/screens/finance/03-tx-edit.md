| 权限 | 管理员 A（可改全部）；成人成员 M（仅限本人创建的流水，他人流水可看不可改）；儿童、无账号成员、访客无写权限（16.3 财务行、16.4） |

**一屏说清**：编辑流水与记一笔同构（二级页，navbar 返回），区别只有三件：**所有字段预填原值**、**提交带 `version`**、**右上角由「保存」换成「删除」**。金额型数据不接受静默覆盖：服务端返回 409 时弹「这条记录已被修改」，并排给出「我的修改 / 服务端最新」两个版本，只给「查看最新」与「仍按我的修改保存」两条出路。编辑只改这一笔——由周期规则自动入账的流水，改完也不会回改规则。

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 从详情页点「编辑」 | 顶部灰条「编辑中 · 版本 3 · 爸爸 10 月 28 日 19:26 最后修改」；类型分段为只读（支出选中，收入 / 转账置灰）；金额、分类、账户、日期、成员、账本、标签、备注、附件全部预填原值；底部说明「保存带版本 3，冲突不会被静默覆盖」 |
| 409 冲突 | 保存时服务端返回 409，或深链 `?state=conflict` | 弹层「这条记录已被修改」：并排两张版本卡（我的修改 `-¥138.00` / 服务端最新 `-¥128.00 版本 4`），说明不静默合并、同一冲突最多连弹 2 次；两条出路「查看最新」（丢弃改动并重拉）与「仍按我的修改保存」（以版本 4 为底写成版本 5）；正文与按钮均不出现「覆盖」字样；底层表单降透明度 |
| 删除确认 | 点顶栏「删除」 | 弹层「删除这笔流水？」：说明软删进回收站、30 天内可恢复、周期规则不受影响；带一行摘要（餐饮 · 晚餐 / 10 月 28 日 19:20 / `-¥128.00`）；主按钮「删除，进回收站」，次按钮「取消」 |
| 已保存 | 保存成功后，或深链 `?state=saved-toast` | 页面顶部出现成功横幅「已保存 · 版本 4」并说明家人端 5 秒内看到新金额、周期规则本身不变；底部弹出 toast「已保存 · 版本 4，家人端 5 秒内看到新金额」；再点「保存修改」回详情 |

## 字段与校验（页面级硬规则）

- **`version` 必带**：进入本页即持有该笔的 `version`（原型为 3），保存、删除都以它做乐观锁；不带 `version` 的写一律拒绝。
- **409 的处置**：双版本 payload 并排展示，只给「查看最新 / 仍按我的修改保存」；不自动合并、不按时间戳决胜；同一冲突连弹不超过 2 次，仍冲突则提示稍后再试。
- **金额型不接受静默覆盖**：冲突时不得后台重试写入，必须由用户显式选一条出路（3.4.4 对象分类表）。
- **编辑不回改来源**：由周期规则自动入账的流水，编辑只改这一笔；`generated_by` 与规则本身只读，规则下月仍照原样入账。
- **金额与分类**：以「分」存储、按家庭币种显示，负号在货币符号之前；改金额与分类会重算这笔的收支、预算与报表归集。
- **账户与归档**：只能换成未归档账户；已归档账户不出现在选择器里，但它过去的流水照常计入统计与净资产。
- **可见性不变**：编辑不改变谁能看到这笔流水；家庭流水全员可见，私密行只有作者与管理员可改。
- **删除是软删**：进回收站、30 天可恢复；转账删除必须成对，不做单边删除。
- **离线**：保存先入待同步队列并显示离线细条；重放冲突同样走本节 409 口径，被拒绝的写不静默丢弃。

## 边界与不做

- 不在本页改类型：支出 / 收入 / 转账的类型分段只读（改类型请删除后重记，避免跨类型换算对不上账）。
- 不做字段级「手动合并」编辑器：P1 的冲突处置只有「查看最新 / 仍按我的修改保存」两条出路。
- 不做自动保存与草稿；返回即丢弃未保存改动。
- 不做「编辑历史 / 版本回溯」视图，只在页内显示当前版本号与最后修改人。
- 不做附件上传后的裁剪、压缩与 OCR 重跑（重拍在记一笔与详情页）。
- 不在本页改账本定义、分类字典与账户属性，这些在「账户与设置」。

## 待复核

- **类型只读**属原型决策：PRD 未明确编辑页可否改类型，为守住「金额型不做跨类型换算」暂按只读呈现，若定版允许改类型需改造金额符号与成对逻辑。
- PRD §6.5 的第三条出路「手动合并（留在编辑页、字段级标红差异）」本批未做，屏卡与原型只给两条出路；是否在 M1 补第三条待定。
- 冲突重试上限 2 次来自 §6.5，但「第 3 次仍冲突」的兜底文案（稍后再试 / 转人工）未定义。
- 删除确认里「周期规则不受影响」的措辞依赖 `generated_by` 字段语义，若后续要求「删除并停用规则」需另设入口。
