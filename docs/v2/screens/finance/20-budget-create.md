**一屏说清**：新建预算只填四件事加一个开关——**范围**（总预算 / 指定分类）、**金额**、**周期**（M1 只有月）、**阈值**（默认 100%，可选 80% 预警）、**是否固定**；再加一行只读的生效周期（2026 年 11 月起 · 每月）。**范围在创建时定死**，保存后不能改成总预算或换分类，要换请删除后新建。金额必须大于 0；季 / 年按钮置灰带「②」，点了只给未交付提示，不落半成品数据。保存成功回预算列表；**本期已开始（10 月 29 日）时新建预算默认从下一个整期生效**，避免半程预算把进度拉低。

## 字段与校验（页面级硬规则）

- **范围不可改**：`scope`（总预算 / 分类）在创建时确定，编辑页只读；要换范围只能删除后新建（避免在两条预算之间搬金额）。
- **分类唯一**：同一分类同一 `period` 至多一条预算；已存在时页面置灰并引导去列表编辑，**不做静默覆盖**（否则等于绕过 `version` 覆盖家人的配置）。
- **金额**：以「分」整数存储，`> 0` 才可提交；展示千分位 + 两位小数、等宽数字；不提供负数与 0。
- **阈值**：默认 100%；80% 为可选提前预警，两条线各提醒一次，同预算同周期不重复；`= 100%` 不算超支（19.3#4 边界值）；提醒由 `finance.budget.exceeded` → HomeOS `budget_alert` 下发，本面不自建定时器。
- **周期**：M1 只有月；季 / 年为 ②（M2），按钮置灰、不可选中、不写入。
- **固定预算**：打开后每期自动带出，金额沿用本期；固定的是预算金额，不是流水，仍可记账。
- **生效周期**：只读，取自服务端计算的「下一个整期」；本期已开始则不从当天起算，避免半程预算把进度拉低。
- **离线**：保存先排队并带幂等键；超支提醒随家庭消息下发，页面不承诺即时到达。

## 边界与不做

- 不做季 / 年预算、不做结转、不做模板（均 ②）。
- 不做成员预算（4.5.2 列出，P1 基线未含）。
- 不做批量新建、不做从历史流水反推建议金额（属 P6 的预测能力）。
- 不锁定记账：预算只是进度与提醒，超支后照常可以记。
- 不在本页改已发生流水或改账户，金额与预算互不影响。
- 不提供自定义阈值百分比（只有 100% 与 80% 两档），避免出现「95% 提醒」这类无法在验收里取边界值的配置。

## 待复核

- **生效周期从下一个整期起的口径是我补的**：PRD 只写「按周期归零」，未写月中途新建从何时生效。原型取「下个整月」以免半程进度失真；若定版允许当月立即生效，需同时说明「本期已用按当月已有流水汇总」，不能写 0。
- 已存在同分类预算时是「置灰引导编辑」还是「允许新建并合并」：原型按前者（不覆盖），需与 4.8 `POST /budgets` 的冲突码对齐。
- 阈值是否允许 80% 与 100% 同时挂两条提醒：原型按「各一次、互不替代」处理；若产品只允许一条，需删掉一条线。
- 固定预算与周期记账规则的关系：原型按两条独立对象处理（固定预算不生成流水，只自动带出额度）。
- 金额是否需要上限（如按家庭币种最大位数）：原型只校 `> 0`，上限留给服务端。
