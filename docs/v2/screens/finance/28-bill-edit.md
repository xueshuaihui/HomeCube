**一屏说清**：编辑页带 `version`，回答「改这一期还是改以后」。字段与新建一致，但多两条硬规则：**改到期日会重新提交到期注册**（旧注册项按幂等键被替换，页面只提示「日历可能稍晚」）；**删除会连注册项一起撤销**（发 `finance.due.revoked`），已缴生成的流水不删、余额不动。保存带版本号，409 只弹「这条记录已被修改」，给「查看最新 / 覆盖保存」两条出路，绝不静默覆盖家人的修改。

## 字段与校验（页面级硬规则）

- **乐观锁**：保存必须带进入时的 `version`；服务端返回 409 时只弹冲突层，**不静默覆盖、不自动重试**；覆盖保存会写成新版本并重发注册。
- **改期即重发注册**：以 `(source_system, source_id, kind)` 为幂等键覆盖原注册项，不产生第二条到期项；只提示「日历可能稍晚」，不给「已生效」的确定答复。
- **改期的边界**：只影响未缴的当前期与之后期次，**已缴过的那一期不跟着改**；已缴流水仍按原日期与原金额。
- **重复互改**：一次性 ↔ 每月只影响之后；已生成的待缴与流水保留；改成一次性后原注册项在最后一期缴完后失效。
- **提前量**：当天 / 1 / 3 / 7 天，默认 3 天；改它同样触发注册重发；当天固定 20:00 再提醒一次。
- **删除**：删除账单 + 撤销注册是一个动作；已缴流水与账户余额不受影响；删除不可恢复，不提供回收站。
- **金额**：以「分」存储，展示两位小数；改金额不追溯已生成的流水。
- **离线**：保存先入队列并标注「联网再提交注册」，不显示已成功；冲突判定在联网提交时进行。

## 边界与不做

- 不做「只改这一期」的例外编辑（分期级覆盖属 M2）；本页改的是账单规则，对未缴期次统一生效。
- 不做删除回收站与批量删除；删除走确认弹层，一次一条。
- 不做「重新提交注册」的独立按钮：注册随保存或改期自动重发，详情页只给未注册态的重试入口。
- 不在本页改来源账户的余额，也不做账户归档；账户编辑在账户域。
- 不做字段级历史对比与撤销：冲突层只给「查看最新 / 覆盖保存」。

## 待复核

- 缴后改金额 / 到期日是否要锁：原型允许改且不追溯已生成流水；若定版要求锁定，本页需对已缴记录置灰这两个字段并给说明。
- 409 冲突层「覆盖保存」是否要二次确认：金额型数据风险高，原型未加第二层。
- 改期后旧注册项的撤销与新注册是否必须在同一事务内完成（避免短暂双到期项），17.4 未写明，原型按幂等覆盖处理。
- 删除是否要保留软删记录供审计（19.3 要求删除与撤销同断言），原型按不可恢复呈现。
