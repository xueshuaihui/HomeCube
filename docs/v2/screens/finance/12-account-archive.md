# 12 · 归档与恢复

| 项 | 值 |
|---|---|
| 路由 | `finance/account/archive` |
| 期 | ① |
| 面 | 财务 |
| 权限 | 管理员（归档与恢复为家庭配置写操作）；成人成员只读；儿童、访客不进财务面 |
| 原型 | [finance-account-archive.html](../../prototypes/finance-account-archive.html) |
| 状态帧 | [默认](../../prototypes/finance-account-archive.html) · [余额非 0 被拒](../../prototypes/finance-account-archive.html?state=balance-block) · [恢复确认](../../prototypes/finance-account-archive.html?state=restore-confirm) · [空](../../prototypes/finance-account-archive.html?state=empty) |

**一屏说清**：归档页一屏分两段——上方「已归档」（可恢复），下方「可归档账户」（仅余额为 0 可归档）。页首常驻「**归档不等于删除**」：**归档账户不出现在默认账户位，也不进账户汇总，但历史流水仍计入报表与净资产**；归档可逆，随时可以恢复。余额非 0 的账户归档按钮禁用并就地说明「请先把余额转到其他账户」，服务端同样拒绝，前端不得伪造可归档或把余额清零。

## 交互表

| # | 元素 | 触发 | 反馈 | 去向 |
|---|---|---|---|---|
| ① | 返回 | 点击 | 回账户列表；归档与恢复都不改历史流水，返回后列表与汇总按最新状态重算 | `finance/account/index` |
| ② | 恢复 | 点已归档行的「恢复」 | 弹恢复确认层「恢复这个账户？」，显示账户名与余额；说明恢复后重新出现在账户列表与记账选择器、余额按历史流水立即生效、不会重复累计、报表不需重算 | 留在本页（`sheet-restore`） |
| ③ | 归档 | 点可归档行的「归档」 | 仅余额为 0 的账户可点；归档后移入上方「已归档」，不再出现在默认账户位与记账选择器，历史流水仍计入报表；余额非 0 时按钮禁用 | 留在本页 |
| ④ | 归档被拒说明 | 查看余额非 0 行 / 服务端拒绝后 | 行内提示「请先把余额转到其他账户」；服务端拒绝时页内红条「归档被拒绝 · 微信零钱余额 ¥2,140.00 不为 0」，说明先转账或记一笔调整流水把余额调为 0，再回来归档 | 不跳转 |
| ⑤ | 确认恢复 | 点弹层「确认恢复」 | 关闭弹层并留在本页，账户从「已归档」移回可归档 / 账户列表；不恢复任何默认标记，需要时去编辑页重设；失败时不动本地状态 | 留在本页（刷新两段列表） |

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 进入本页 | 「归档不等于删除」说明 + 已归档 2 个（建设银行储蓄卡、京东小金库，余额合计 ¥0.00，各带「恢复」）+ 可归档 3 个：招商银行信用卡 -¥3,250.00（禁用 + 提示）、微信零钱 ¥2,140.00（禁用 + 提示）、饭卡 ¥0.00（可归档）；底部说明归档与恢复都写 `version` |
| 余额非 0 被拒 | 归档余额非 0 / 服务端返回业务错误 | 可归档段顶部展开红条「归档被拒绝 · 微信零钱余额 ¥2,140.00 不为 0」，对应行仍禁用并保留提示；账户状态不变，不清零余额 |
| 恢复确认 | 点任一「恢复」/ 深链 | 底部弹层「恢复这个账户？」+ 账户摘要（建设银行储蓄卡 · ¥0.00）+「确认恢复」「取消」；背后列表压暗 |
| 空 | 无已归档账户 | 「已归档」段显示「0 个」与虚线空框「还没有归档的账户。归档后的账户会出现在这里，可随时恢复」；可归档段照常列出候选；两段互不替代 |

## 字段与校验（页面级硬规则）

- **归档前置条件**：余额必须为 0；非 0 时按钮禁用 + 就地说明，服务端同样拒绝（4.5.9、19.3#10）；不得在前端把余额清零或伪造可归档。
- **归档后的口径**：`is_archived=true` 的账户移出默认账户位与账户汇总、移出记账选择器；**历史流水仍计入报表与净资产**；归档不影响历史归属。
- **余额与恢复**：恢复不改余额、不重算历史；余额按流水重新呈现，不重复累计；恢复不自动恢复默认标记。
- **`version`**：归档与恢复都带 `version`；失败（409）时不动本地状态，提示刷新后重试。
- **列表分两段**：已归档（按归档时间倒序，显示归档日期与余额）与可归档（仅未归档账户）；余额为 0 的可归档，非 0 的也列出但禁用，便于知道「差在哪」。
- **金额**：一律等宽数字，负数在 `¥` 前（`-¥3,250.00`）；归档账户余额恒为 ¥0.00。
- **离线**：归档与恢复只排队，不假装完成；返回列表时以服务端状态为准。

## 边界与不做

- 不做物理删除账户，也不做「归档并清零」；余额问题必须先转账或记调整流水。
- 不做批量归档 / 批量恢复，也不做滑动操作。
- 不在本页做转账或调整流水；只给文案与入口提示，实际记账在记一笔里完成。
- 不做归档账户的详情页；需要改名等操作先恢复，再回列表编辑。
- 不提供「归档后自动取消默认」的显式开关：默认标记的处理由服务端保证唯一。

## 待复核

- 默认账户能否直接归档：PRD 只要求余额为 0，未说默认位，原型未拦截；若定版要求先取消默认需补禁用态。
- 归档 / 恢复是否与编辑保存共用 `version` 口径，PRD 只写账户有 `version` 字段，原型按写操作全带。
- 空态是否保留「可归档账户」段：原型保留（仍有候选），只把已归档段置空。
- 归档失败的业务错误码与文案未定版，原型用「归档被拒绝 · 余额不为 0」示例。
