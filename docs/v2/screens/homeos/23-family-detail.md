# 23 · 成员治理

| 项 | 值 |
|---|---|
| 路由 | `homeos/family/detail` |
| 期 | ① |
| 权限 | 仅管理员；非管理员不可达（治理动作全部在此页，含转让管理员） |
| 原型 | [family-detail.html](../../prototypes/family-detail.html) |
| 状态帧 | [默认](../../prototypes/family-detail.html) · [角色变更确认弹层](../../prototypes/family-detail.html?state=roleconfirm) · [移除弹层](../../prototypes/family-detail.html?state=remove) · [转让确认弹层](../../prototypes/family-detail.html?state=transfer) · [最后一名管理员](../../prototypes/family-detail.html?state=lastadmin) · [加载](../../prototypes/family-detail.html?state=loading) · [首屏失败](../../prototypes/family-detail.html?state=error) |

**一屏说清**：这是「对这个成员做什么配置」的唯一页面——角色、该成员的面可见性授权、数据范围、代管关系与移除，**并且是转让管理员的唯一权威写入口**（「我的」页与成员列表的「先转让」都指到这里）。它与成员公开页是两屏：这里能写，公开页只读。角色可见性授权是 `scope=module` 的逐成员授予，**不是**家庭启用哪些面。

## 交互表

| # | 元素 | 触发 | 反馈 | 去向 |
|---|---|---|---|---|
| ① | 返回 | 点击 | 回家庭成员；未确认的改动不落库 | 家庭成员（`family.html`） |
| ② | 成员头 | 点击 | 进只读公开页；治理页与公开页不合并，一个答「这个人是谁」，一个答「对他配置什么」 | 成员主页（`member-detail.html`） |

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 治理一位成人成员 | 成员头 + 角色 + 逐面授权 + 数据范围 + 代管关系 + 移除，六段完整 |
| 角色变更确认弹层 | 选了「成员」或「只读」这两档 | 说明新角色能力、变更前后与生效时机；确认按钮不置危险色（非破坏性） |
| 移除弹层 | 点「移除成员」 | 危险确认：历史内容保留、作者显示已退出成员；个人偏好与私密账本随退出删除 |
| **转让确认弹层** | 在**别的成员**页把角色选成「管理员」 | 标题：『把妈妈设为管理员？』；差异行写清**双方**：你（管理员）→ 成员、妈妈（成员）→ 管理员；一句说明 TA 将能做什么；不可回退说明：『转让后你将不能再改家人的角色，要改回来需要请妈妈在成员页操作』；确认按钮用危险色（它同时撤掉自己的写权限） |
| 最后一名管理员 | 治理自己且是唯一管理员 | 降级被拦并给提示，「成员」「只读」两档不可选；移除按钮显示为「不能移除自己」；文案指向**真实入口**：回成员列表点开要接任的那位家人，把角色设为管理员（就是 ③ + ⑩）。转让不在本人这一页发起——这里没有接任对象 |
| 加载 | 首屏请求中 | 成员头与分节骨架；不显示任何可写控件 |
| 首屏失败 | 治理数据请求非 2xx 或超时 | 整页失败态 + ⑪ 的「重试」；不渲染任何角色位与开关，也不回落成本地记住的上一次值 |

## 字段与校验（页面级硬规则）

- **角色三档**：管理员 / 成员 / 只读（用户可见用词与成员列表徽章、权限设置页矩阵行名同一套）；任何变更都走二次确认，确认后下一次请求即按新角色判定。
- **家庭至少一名管理员**：最后一名管理员不能降级、不能移除自己；换管理员必须先转让——转让的真实入口就是本页的 ③ + ⑩。
- **转让管理员（唯一权威写入口 = 本页；「我的」页与成员列表只作指向，不各写一份）**：
  - **谁能发起**：只有当前管理员本人；非管理员不可达本页，因此不存在第二条发起路径。
  - **从哪里发起**：在**要接任的那位成员**的治理页把角色选成「管理员」。本人自己的治理页不提供转让（那里没有接任对象）。
  - **服务端前置校验（缺一即整笔拒绝，拒绝不落任何角色变更）**：① 目标成员属于本家庭（跨家庭访问一律拒绝并落审计）；② 目标**必须有账号**（`user_id` 非空）——无账号被记录成员不可登录，接任等于把家庭交出去没人接；③ 目标当前角色是成人成员档，只读档（儿童、老人、访客）不可接任；④ 写后家庭管理员数必须 ≥1（转让是移交不是新增，原管理员同批降为成员）；⑤ 写的一刻发起者仍是该家庭的管理员——两笔转让并发时只有先落库的一笔生效，后一笔因发起者已非管理员而被拒。
  - **确认层必展示的四件事**：对象（头像 + 家庭内称谓 + 当前角色）、**本人转让后变成什么**（管理员 → 成员，写在差异行里，不能只写对方）、对方将获得什么（管理成员与邀请、调整开通清单）、不可回退说明（本人降为成员后自己改不回来，只有新管理员能改）。
  - **成功口径**：写成功后**离开本页回成员列表**（本页的进入前提是管理员写权限，转让后不再成立），列表徽章即新角色；轻提示文案：『已把管理员交给妈妈，你现在是成员』。**不弹成功页、不要求重新登录**，下一次请求按新角色判定。
  - **失败与回滚**：前置校验不过或请求失败 → 弹层不关闭、双方角色与徽章一律不动、客户端不预写；页面给一句可重试的说明，用户可见文案：『转让没有成功，管理员还是你』；重试仍走同一入口，不得出现「TA 已是管理员而本人也仍是管理员」的中间态。
- **逐成员授权 ≠ 家庭挂载**：这里只授予「TA 能看到哪些面」（`scope=module`）；家庭启用哪些面的唯一入口是 `homeos/family/modules`，本页不出现家庭级面开关。
- **逐成员授权优先于角色默认表**：本页收回某人的某面之后，权限设置页那张表仍会按角色默认显示该面可见——本页开关位是**结果**、那张表是**默认档**；25 的图例句与本页开关同时在场才算一致，逐格判据写在 25。
- **可收回的范围**：本页只为「本家庭已挂载且可以按人收回」的面渲染开关（P1 = 财务）。**始终开启的日历面不提供逐成员收回**：它的可见性只由角色默认决定（16.3 面配置行），本页把它呈现为一条只读状态行、不放开关。
- **不可授予的面**：本家庭未启用的面**整行不出现在授予列表里**（可授予集 = 挂载集合 = registry ∩ `homeos_family_module` ∩ 服务已出生，18.8）；服务未出生的面以**只读「即将上线」说明行**出现、**不渲染开关，也不渲染置灰开关**（「置灰位」这一类导航形态已随定版模型废除，㉙ 四词二分：未启用 ≠ 即将上线 ≠ 暂不可用 ≠ 依赖未就绪）。不隐藏、不改写规则。
- **数据范围**：P1 只读，取角色默认；不为没有写路径的覆盖层提前做控件。
- **受限表达二分（与成员列表同一条口径）**：① 只读但有信息价值的家庭级值（本家庭启用哪些面、该面的启用时长）——**展示服务端实值**并写明唯一修改去处；该值需要管理员才能改时，在值后跟一句『需管理员修改』的纯文案；② 纯无权限项（本家庭未挂载的面）——**整行不渲染**，不是置灰、不是加锁、不是点了报错。
- **代管关系**：无账号被记录成员由 `guardian_id` 指向的监护人代管，代写携带 `on_behalf_of`；代管数据归属被记录成员。
- **移除**：软删 + 该成员令牌即刻失效 + 落审计；其历史内容保留在家庭，作者显示「已退出成员」；个人偏好与私密账本内容随退出删除。
- **首屏失败不展示旧数据**：失败与重试期间整页只呈现失败态或骨架；角色位、开关与代管关系一律不回落成上一次读到的值。

## 边界与不做

- 与 `homeos/member/detail` **不合并**：公开页全角色只读，本页仅管理员。
- 本页**不做**家庭面挂载开关，也不做「哪些面可用」的家庭级配置。
- 本页**不做**退出家庭与解散家庭；**转让管理员已实做**，入口与判据就是 ③ + ⑩，本页是唯一权威写入口。管理员要退出家庭，前置的「先转让」走的就是这个入口。
- 本页**不做**逐成员数据范围自定义，也不做对象级 ACL。
- 本页**不做**监护对象的增删（代管关系只读）。
- 移除**不做**在按钮上直接执行，必须弹层确认；转让同样必须弹层确认。

## 待复核

- 角色变更是否需要额外验证（PRD 只要求确认弹层，本屏未加密码）。
- 数据范围是否允许 P1 逐成员配置（本屏按只读处理）。
- 监护对象能否在本页增删（PRD 未定，本屏只读）。
- 移除成功后是回列表还是留在本页（原型 toast 后回列表）。
- 角色变更对「最后一名管理员」的判定是否也覆盖访客与儿童档（本屏只覆盖降级）。
- 退出家庭与解散家庭落哪一页：3.7 有 `family/leave` 与 `family/disband` 两条写口，导航文档 §4.6 的 12 页里没有对应页面；卡在这两条写口是否算 P1 未交付，本页只承接「先转让」这一条前置，不代替它们。
