## 字段与校验（页面级硬规则）

1. **开关渲染条件（页面级硬规则，本轮定版）**：设 `N` = 本家庭**已启用的可选面**数（可选面 = 挂载集合里除必选面日历以外的面；P1 的挂载集合 = 财务 + 日历 ⇒ `N = 1`）。**`N ≥ 2` ⇒ 每个已启用可选面渲染可操作开关；`N = 1` ⇒ 该行不渲染开关，只渲染状态标签 + 一句说明**（用户可见文案：『至少要保留一个，现在只有这一个』）。
   - **恢复可关的时机**：当管理员开通第二个可选面（`N` 变 2）后，两个已启用可选面的开关一起恢复渲染、一起可关；此后 `N` 回到 1 时，剩下那一行再次收掉开关。同一条规则也解释引导态——引导态的可选项是「选」不是「关」，不受本条影响。
   - **判据不动**：「至少保留一个可选面」与「按可选面集合判、原断言不放宽」（18.8 ㉚ + 导航文档 §6.11）一字不改；本条只把**注定被服务端拒绝的那一次交互**从界面上拿掉，不新增、不放宽、不收窄任何判据。
   - **负样本账不变**：19.2#9① 的 8 次「停用最后一个可选面被拒」与 8 次「尝试停用日历面被拒（必选面）」原样判定，样本数与分母不减；两者的构造方式同支——**客户端不渲染开关，请求由验收脚本直发接口**，服务端必须拒绝并落审计（18.8 ㉚ 已为必选面确立这一形态）。
2. **不渲染 = 不置灰**：`N = 1` 与必选面日历两处都**不得出现「置灰的开关」「拨了被弹回的开关」**；呈现是状态标签 + 说明文字，整行点击无动作、不报错（与 21/23/24/25 的受限表达二分同一条口径）。
3. **三态互斥**：已启用 = 本家庭启用且服务已出生；可开通 = 已出生未启用；即将上线 = 未出生（只有徽章与期数）。同一面只出现在一组。
4. **必选面只有恒启用**：日历面在本页不出现开关、不出现在「可开通」段、也不作为「即将上线」呈现；`FamilyModule` 对它只有「启用」一态，服务端拒绝任何停用请求并落审计（18.8 ㉚）。它的用户可见标签与说明同 ② 与 ⑤，**不得把「必选面」这类工程词写进引号内的文案**。
5. **停用语义固定**：入口消失、数据保留、重新开通可恢复；停用不改变跨面归集、AA、备份与动态流的口径。
6. **写路径唯一**：开通 / 停用只走本页开关（带 `version` 乐观锁）；首页、顶栏、「＋」都不提供面开关。**P1 期间本页没有任何可写开关在场**，写路径依然唯一——它在下一次开通第二个可选面时仍然只在这里恢复。
7. **非管理员不渲染开关**：不是置灰、不是点进去报错；只读态照常展示清单与生效状态；非管理员看到的状态标签与管理员看到的一律同词（『始终开启，不能关闭』/『已开启』）。
8. **引导态限制**：无返回、无停用、可选项只列已出生面；未选满 1 项按钮禁用并给出原因文案『至少要选一个才能继续』。
9. **未出生面不可点**：不给试用入口，不触发分包下载与接口请求。
10. **首屏失败不展示旧数据**：失败与重试期间整页只呈现失败态或骨架；开通状态不回落成上一次读到的值——治理页展示过期开通状态会被当成当前配置。

## 边界与不做

- 不在首页、顶栏或「＋」里常驻未启用面的占位入口。
- 不出现 0 面家庭：必选面日历恒在，最后一个可选面的停用会被拒，页面不呈现空矩阵态。
- 不做付费墙、试用与面内订阅。
- 不在本页做成员角色与权限（在成员治理页与权限设置页）。
- 不把「即将上线」做成可点预览，也不与「未启用」混用两个词。
- 不做「先拨开关、再被拒回位」的交互：注定失败的开关不在 P1 出现。
