**一屏说清**：全量面清单与「本家庭启用哪些面」的唯一写入口，一页两用途——治理态改配置，引导态完成新家庭创建的强制选面；不另开第二条路由。定版 ㉚ 后本家庭 P1 的已启用集合 = **2 面（财务 + 日历）**，其中**日历面是必选面**：恒启用、无开关、停用请求由服务端拒绝（它是其余六面到期语义的依赖，停用即全平台提醒静默失效）。

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 治理-默认 | 管理员从「我的 → 开通更多面」进入 | 已启用 2（日历 = 必选面、无开关；财务 = 带开关）/ 可开通 0（空说明）/ 即将上线 5（徽章 + 期数）+ 规则卡 |
| 治理-停用确认 | 点可选面（财务）的开关 | 二次确认弹层：入口消失、数据保留、重新开通可恢复；停完后本家庭仍有必选面日历在位；若这是最后一个可选面则附「至少保留一个可选面」并被拒 |
| 引导-未选 | 创建家庭提交后进入 | 顶部「选择你们要用的服务」；无返回、无停用；日历不在勾选清单：单列「必选面 · 已默认开通」只读行，无勾选框，财务可选未选，底部按钮禁用并显示「至少选 1 个可选面」 |
| 引导-已选 | 勾选至少 1 项可选面 | 该行高亮打勾，底部显示「已启用 2 面（含必选面日历）」，按钮可点，进入首页 |
| 非管理员 | 成人成员进入 | 只读提示条 + 已启用面用「已启用」标签代替开关（日历面同样是「必选面」标签）+ 即将上线徽章；无任何开关 |

## 字段与校验（页面级硬规则）

- **三态互斥**：已启用 = 本家庭启用且服务已出生；可开通 = 已出生未启用；即将上线 = 未出生（只有徽章与期数）。同一面只出现在一组。
- **必选面只有恒启用**：日历面在本页不出现开关、不出现在「可开通」段、也不作为「即将上线」呈现；`FamilyModule` 对它只有「启用」一态，服务端拒绝任何停用请求并落审计（18.8 ㉚）。
- **停用语义固定**：入口消失、数据保留、重新开通可恢复；停用不改变跨面归集、AA、备份与动态流的口径。
- **至少保留一个可选面**：停用最后一个可选面时服务端拒绝，客户端提示「至少保留一个可选面」并把开关复位；与引导态「至少选 1 项可选面」是同一条约束。必选面日历恒在，因此「0 面家庭」在本条定版后不可能出现（原「不允许出现 0 面家庭」的边界断言不删，改由「尝试停用日历面被拒（必选面）」+「停用最后一个可选面被拒」两条共同承担，负样本数不减）。
- **写路径唯一**：开通 / 停用只走本页开关（带 `version` 乐观锁）；首页、顶栏、「＋」都不提供面开关。
- **非管理员不渲染开关**：不是置灰、不是点进去报错；只读态照常展示清单与生效状态。
- **引导态限制**：无返回、无停用、可选项只列已出生面；未选满 1 项按钮禁用并给出原因文案。
- **未出生面不可点**：不给试用入口，不触发分包下载与接口请求。
- **客户端不渲染必选面的停用路径**：不给「置灰的开关」，不给「点了报错的开关」——必选面就是一行带「必选面」标签的已启用条目。

## 边界与不做

- 不在首页、顶栏或「＋」里常驻未启用面的占位入口。
- 不出现 0 面家庭：必选面日历恒在，最后一个可选面的停用会被拒，页面不呈现空矩阵态。
- 不做付费墙、试用与面内订阅。
- 不在本页做成员角色与权限（在成员治理页与权限设置页）。
- 不把「即将上线」做成可点预览，也不与「未启用」混用两个词。
