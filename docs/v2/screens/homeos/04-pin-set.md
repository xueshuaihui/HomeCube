# 04 · 设备锁 PIN

| 项 | 值 |
|---|---|
| 路由 | `homeos/auth/pin-set` |
| 期 | ① |
| 权限 | 本人（开启 L3、从「我的 → 安全」进入，或进入 L3 前被拦下） |
| 原型 | [pin-set.html](../../prototypes/pin-set.html) |
| 状态帧 | [设置](../../prototypes/pin-set.html) · [确认](../../prototypes/pin-set.html?state=confirm) · [两次不一致](../../prototypes/pin-set.html?state=mismatch) · [锁定中](../../prototypes/pin-set.html?state=locked) · [忘记口令·手机号重验](../../prototypes/pin-set.html?state=reset) · [重验暂不可用·说明态](../../prototypes/pin-set.html?state=reset_offline) |

**一屏说清**：6 位设备锁用两步设置（输入 → 再输一次），散列只存本机、不上传服务端。它是本地能力，不是接口。**忘记口令的路径必须落在本页、本轮可达**——锁定是本机唯一的、不随设备继承的状态，若重验入口不在本页，本机 L3 内容就永久打不开。

## 交互表

| # | 元素 | 触发 | 反馈 | 去向 |
|---|---|---|---|---|
| ① | PIN 点阵 | 满 6 位自动提交 | 输入过程不回显数字；提交时不设「确认」按钮 | 设置 → 确认；确认一致 → 完成 |
| ② | 数字键盘 | 点击数字 | 每次输入点亮一枚圆点；自定义键盘，不调系统键盘 | — |
| ③ | 删除 | 点击 | 单次删除一位；无输入时不响应 | — |
| ④ | 忘记口令 | 点击（**锁定态下同样可点，不受退避计时限制**） | 进入本页的重置流程：向本账号**已验证手机号**发送验证码，验证前不解除本机锁定、不显示任何 L3 内容 | 手机号重验态（`?state=reset`）；重验链路当期未就绪 → 说明态（`?state=reset_offline`） |
| ⑤ | 手机号重验 | 输入验证码并提交 | 校验通过 → 清除本机 PIN 散列与**加密缓存、未提交草稿**（3.4.8 的明示项），进入「重设 6 位设备锁」；校验失败 → 留在重置态并提示，连续 3 次失败转说明态 | 设置态（重设新 PIN） |
| ⑥ | 找家庭管理员协助 | 点击（说明态的兜底动作位） | 打开一段只读说明，用户可见文案：『这台手机上的口令只能在本机重置，需要输入你本人的手机号验证码。如果暂时收不到验证码，可以请家庭管理员在你这台手机上帮你完成上面的重置。管理员不能远程替你重置，也没有你的口令。』；**不给任何「远程解锁」「客服代填」的假入口** | 留在本页（说明态内） |

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 设置 | 首次进入 / 重置成功后 | 标题「设置 6 位设备锁」，点阵为空 |
| 确认 | 第一次输入完成 | 标题「再次输入确认」，点阵清空 |
| 两次不一致 | 确认输入与第一次不同 | 红字「两次输入不一致，请重新设置」，回到设置态 |
| 锁定中 | 连续 5 次错误 | 点阵与键盘置灰，显示「请在 30 秒后重试」；之后依次 1 分钟、5 分钟。**锁定只禁本机输入，④「忘记口令」入口保持可点**——这是本机 L3 内容唯一的出路 |
| 忘记口令·手机号重验 | 点 ④ | 重置表单：已验证手机号（掩码显示、不可改）+ 验证码 + 获取验证码 + 主按钮「验证并重设」；同页一句明示重置会清除本机加密缓存与未提交草稿 |
| 重验暂不可用·说明态 | 重验接口未就绪，或 ⑤ 连续 3 次失败 | 说明态：本机口令暂时无法完成手机号重验，**这台手机上的私密内容保持不可读，家庭数据不受影响**；给「稍后再试」与 ⑥「找家庭管理员协助」两个动作，不给假入口、不假装已重置成功 |

## 字段与校验

| 字段 | 规则 | 失败文案 |
|---|---|---|
| PIN | 6 位数字 | 「两次输入不一致，请重新设置」 |
| 锁定 | 连续 5 次失败 | 「已锁定，请在 30 秒后重试」 |
| 重验手机号 | **只取本账号已验证手机号，掩码显示、不可输入别的号码**；PIN 不出端，所以重置的判据只能是「这个人持有该号码」 | 用户可见文案：『只能重置到你自己的手机号』 |
| 重验验证码 | 6 位数字；一次有效、验证成功即作废；连续 3 次错误转说明态 | 「验证码不正确，请重新获取」 |
| 重置的破坏性 | 提交前二次确认，明示「将清除本机的加密缓存与未提交的草稿」（3.4.8）；确认后不可撤销 | 用户可见文案：『重设口令后，这台手机上没来得及保存的内容会被清除』 |

## 边界与不做

- **PIN 不是接口**：散列只存本机，服务端不接收、不校验、不存库。
- **锁定的作用域是本机**：换设备不继承锁定状态，也不会把锁定同步给其他设备。
- **忘记口令只有这一条路，且必须在本页可达**：手机号验证码重验后重置，不设「密保问题」，不做邮箱链接，不做「管理员远程解锁」（PIN 不出端，任何角色都不掌握他人口令）。后端未就绪时**给说明态 + 管理员现场协助的兜底说明**，不给假入口、不把本页做成死路。
- 原型限制：确认步的第一次输入不跨页面保存，刷新后确认态任意 6 位都会通过；真实实现需在内存或本地临时态里保留第一次的散列。
