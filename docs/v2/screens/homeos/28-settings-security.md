# 28 · 安全与设备锁

| 项 | 值 |
|---|---|
| 路由 | `homeos/settings/security` |
| 期 | ① |
| 权限 | 本人；登录设备按本人会话；权限版本只读自查 |
| 原型 | [settings-security.html](../../prototypes/settings-security.html) |
| 状态帧 | [默认](../../prototypes/settings-security.html) · [设备锁关闭](../../prototypes/settings-security.html?state=lockoff) · [下线确认](../../prototypes/settings-security.html?state=unlink) · [加载](../../prototypes/settings-security.html?state=loading) |

**一屏说清**：这是设备锁与账号安全的唯一入口。PIN 只以不可逆散列存本机、不上传服务端；权限版本只做自查，让用户确认「角色变了，权限已经跟着变」。

## 交互表

| # | 元素 | 触发 | 反馈 | 去向 |
|---|---|---|---|---|
| ① | 设备锁开关 | 开 / 关 | 开启走两步设置；关闭需先验证 PIN，关闭后本机不再要求解锁 | 开 → pin-set；关 → 本页 |
| ② | 设备锁 PIN | 点击 | 已设置先验原 PIN 再改；未设置直接进入设置流程 | [pin-set.html](../../prototypes/pin-set.html) |
| ③ | 下线其他设备 | 点「下线」 | 弹层显示目标设备与最近活跃；确认后该设备需重新登录，本机与其他设备不受影响 | 弹层，留在本页 |
| ④ | 修改密码 | 点击 | 先向绑定手机号发验证码，验证通过才进入改密 | 短信验证（后续） |
| ⑤ | 修改手机号 | 点击 | 旧号 + 新号两步验证；改号后旧号失效，其他设备需重新登录 | 短信验证（后续） |
| ⑥ | 权限版本自查 | 点「重新校验」 | 比对 `pver`：一致提示「已是最新」，不一致自动失效本机缓存并在下一次请求刷新 | 本页 |

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 进入页面 | 设备锁开启、PIN 已设置；3 台登录设备，当前设备带标记且无「下线」；`pver 12` |
| 设备锁关闭 | 开关关闭 | 标题变「设备锁未开启」，说明改为仅会话内二次确认；PIN 行显示「未设置 · 现在去设置」 |
| 下线确认 | 点某台设备的「下线」 | 弹层展示设备名与最近活跃，「确认下线」为危险主按钮，取消可关闭 |
| 加载 | 拉取设备与权限版本 | 骨架屏三段贴合卡片与列表，不用 spinner 遮内容 |

## 字段与校验（页面级硬规则）

- **PIN 不出端**：只以不可逆散列存设备本地，服务端不接收、不校验、不存库；页面任何位置不展示 PIN 明文。
- PIN 6 位数字（原型按两步「输入 → 再确认」）；连续 5 次失败锁定本机 L3，退避 30 秒 / 1 分钟 / 5 分钟。
- 关闭设备锁必须验证原 PIN；忘记口令唯一恢复路径是手机号重验，重置会清除本机加密缓存与未提交草稿。
- 权限版本 `pver` 随角色或权限变更自动 +1；客户端缓存 60 秒 TTL + 收到权限更新事件即失效，生效口径为「下一次请求」。
- 登录设备列表只显示近 30 天活跃设备、最多 10 台；下线只结束该设备会话，不删除家庭数据。

## 边界与不做

- 不做「查看 PIN」、不做 PIN 找回的密保问题。
- 不做设备重命名、登录历史导出与「一键下线全部设备」；P1 一次下线一台。
- 修改密码 / 手机号只做入口与验证说明，不写接口契约。
- 权限版本只读自查，不提供权限编辑（编辑在成员治理页）。
