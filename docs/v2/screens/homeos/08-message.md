**一屏说清**：站内通知的唯一 App 内落点（`Notification` 与投递记录归底座，日历面只发「该触发了」的事实 `calendar.reminder.fired`，不在本面投递）。条目只能按 `budget_alert` / `system` / `reminder` 三分型分组，未读只有服务端一个口径；进入本页即视为已读，顶栏红点与底栏「消息」计数同时熄灭。

## 字段与校验（页面级硬规则）

- **分型固定三类**：`budget_alert` / `system` / `reminder`，顺序即此；业务面不得自建通知类型，也不得有各面独立消息中心。
- **未读一个口径**：服务端 `read_at IS NULL` 按 `member_id` 聚合；首页 `home/summary` 带出、本页与「全部已读」由 `notifications` 返回同一字段。客户端只持有 shell 的一份 `unread`，不自行相减、不缓存第三份。
- **两处呈现分工**：顶栏位只显红点不显数字；底栏「消息」显红点 + 计数，>0 才渲染、上限 `99+`。`unread` 与首页格子的 `badge`（待处理数）是两件事，不共用字段。
- **进入即已读**：打开本页即把可见通知置读，不需要逐条点开；「全部已读」只是批量兜底，走统一确认弹层。
- **免打扰只静音**：时段内红点照常显示、计数照常累计，只是不发声；免打扰设置不在本页改。
- **空分组不占位**：某型零条时整组（标题 + 计数）不渲染，不显示空组标题。
- **相对时间**：`N 分钟前` / `今天 HH:MM` / `昨天 HH:MM` / `MM 月 DD 日 HH:MM`，按家庭时区格式化；服务端给绝对时间。
- **金额口径**：预警正文里的金额用 `.amount`，符号在货币符号之前（`-¥128.00`）。
- **L3 不外露**：通知正文不承载 L3 明文，红点也不按 L3 分级。

## 边界与不做

- 本页**不做**消息搜索、按面筛选、未读筛选、按组折叠；分组只是视觉锚点。
- 本页**不做**单条删除、撤销订阅、关闭某类通知（设置页负责）。
- 「全部已读」弹层**不提供**「全部删除」：通知只置读、不删除。
- 本页**不做**推送开关与推送授权引导，也**不做**留言板内的未读。
- 一级页顶栏**不做**返回：底栏「消息」就是入口本身。
