**一屏说清**：家庭内部的轻量留言板，从「消息」二级进入。留言与评论落 HomeOS，产生的家庭动态**只经事件总线写入**——本页与任何业务面都不直写 `Dynamic`。

## 状态矩阵

| 态 | 触发 | 呈现 |
|---|---|---|
| 默认 | 列表成功 | 顶部日期分隔「今天 · 10 月 29 日」；条目 = 头像 + 姓名 + 时间 + 气泡正文，@ 成员高亮；底部常驻输入条；已发出的条目无状态标记 |
| 空态 | 本家庭零条留言 | 「留言板还空着」+「说点什么」；日期分隔与列表不渲染，输入条保留 |
| 待发送 | 离线发送或队列未回填 | 本条虚线气泡置底 + 首部标记用户可见文案：「待发送」；联网或队列回填后自动转「发送中…」 |
| 发送中 | 队列回填、正在发出（含在线直发） | 虚线气泡 + 「发送中…」，发送按钮转圈且不可重复点；其余条目不动 |
| 发送失败 | 发出超时或被拒 | 虚线气泡 + 红字标记用户可见文案：「发送失败 · 重试」，点重试沿用同一条目重发、不产生第二条；重试成功回填时间、标记消失 |
| 操作层 | 长按或右滑自己的留言（原型点击唤起） | 上拉弹层恰两项：编辑 / 撤回；他人留言不出现此层 |
| 已撤回 | 撤回确认后 | 原位置虚线占位气泡，用户可见文案：「该留言已撤回」+ 撤回时间；正文不再对任何人显示；占位不可编辑、不可再撤 |
| 离线 | 无网 | 顶栏下常驻细条「当前离线 · N 条留言待同步」，输入条上方提示「发送的留言会先进入待同步队列，联网后自动发出」；列表显示本机缓存；离线期间发出的条目一律带「待发送」标记 |

## 字段与校验（页面级硬规则）

- **落点与写路径**：留言/评论写入 HomeOS（`BoardMessage` 一类协作对象），产生的动态由事件总线生成；客户端与业务面都不得直写 `Dynamic`，也不得自建第二份留言表。
- **正文**：纯文本、≤200 字、不折叠；首尾空白去除，纯空白视为空内容不可发。
- **@ 成员**：以成员引用存储、以 `relation`（家庭内称谓）显示；@ 只影响通知，不改变可见性——留言对孩子、对访客同样可见。
- **@ 通知**：被 @ 者收到一条 `system` 类站内通知，进入消息页才置读；本页不显示未读、不做已读回执（未读只属通知口径）。
- **顺序**：按发送时间正序，旧在上、新置底；插入新条不重排历史，滚动贴着最新一条。
- **时间**：显示 `HH:MM`，跨天以日期分隔；一律按家庭时区。
- **离线**：草稿与待发留言进入本机队列，带幂等键，恢复后补发且不产生重复条目。
- **发送四态一律可见**：留言从点击发送到落库只有四种状态，每条至多呈现一个标记——「待发送」（队列未回填前**必显**，含离线期间）→「发送中…」（回填后正在发出）→ 已发出（服务端回填发送时间、标记消失）→「发送失败 · 重试」（点重试沿用同一条目与同一幂等键，不产生第二条）。不允许出现无标记又无时间的中间样子。
- **只可编辑/撤回自己的留言**：入口 = 长按或右滑自己的留言唤起操作层（恰两项编辑 / 撤回）；他人留言不渲染该入口，服务端同时校验发送人、非本人操作一律拒绝（16.3）。
- **编辑/撤回时间窗**：发送时间起 **10 分钟**内可编辑或撤回自己的留言（可测阈值：服务端按 `发送时间 + 600 秒` 判定是否可操作，客户端按服务端给出的可操作性隐藏对应项，提交时仍以服务端校验为准）。
- **撤回的呈现是占位、不是消失**：撤回后原位置保留虚线占位气泡，用户可见文案：「该留言已撤回」（附撤回时间），正文对任何人不再显示。选择占位而非整条消失的理由：留言板按时间顺序读上下文，整条消失会让后续「@某人接哪条」的回应悬空、时间线看起来被篡改；占位保序保位，且不撤回动态与已发出的通知（留言已读与否不受撤回影响）。占位不可编辑、不可二次撤回、不产生新动态。

## 边界与不做

- 本页**不做**楼中楼、单条回复串、点赞、表情回应、图片与附件（P1）。
- 本页**不做**删除留言（撤回不是删除：占位保留在时间线上，见字段与校验）、不编辑不撤回他人留言，也不做管理员批量清理。
- 本页**不做**公告置顶、已读回执、未读筛选；群公告若将来出现，另立能力，不塞进留言板。
- 本页**不做**投票入口：`vote/detail` 随 P3 出生，P1 不出创建入口。
- 留言板**不新建**一套消息中心：@ 与提醒统一落到消息页，红点归 shell。

## 待复核

- 200 字上限与「单行输入」为保守推导，PRD 未写死；超出时按截断而非换行处理。
- 编辑/撤回窗取 10 分钟为保守阈值（发送时间 + 600 秒，服务端判定、客户端隐藏超时项），PRD 未写死；若要放宽或改为服务端可配，需同步本页交互表与状态矩阵，由日历底座接口方在服务端定值后回写。
- 自己的留言是否右对齐：定版按全左对齐（每条都带成员头像 + 姓名 + 时间），与「家庭成员共享一块板」的心智一致。
- 一条留言 @ 多人时是否合并为一条通知（原型按每条通知一条、以 `dedupe_key` 去重），待消息页走查确认。
- 日期分隔原型只画「今天」一条；跨天时按天插入，是否再按月分组 PRD 未定。
- 演示数据 4 条，发送中帧追加第 5 条虚线气泡。
