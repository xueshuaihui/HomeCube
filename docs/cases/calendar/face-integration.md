## CAL-FACE-001 · 日程/待办/提醒创建 ≤3 步、端到端 P95 ≤2s（19.4#1）

## CAL-FACE-008 · 日历面跨服务五步（注册→写→只读→事件→提醒）
- 关联需求：PRD 19.2 附加门禁①（㉚ 后为「财务面与日历面各走通跨服务五步」）、15.5 第 8 项、3.8（底座骨架自检：当期三服务 `svc-homeos` + `svc-finance` + `svc-calendar`）、5.5.5（注册与撤销经事件）、5.5.6（完成回写）、5.5.8（触发出口）、5.8
- 类型：功能 | 优先级：P0 | 建议归属 Sprint：S5
- 前置条件：三服务与 NATS JetStream、Postgres、Nginx 一条命令同栈起停；一个已挂载 `calendar` + `finance` 两面的家庭；事件目录已登记 `finance.due.registered` / `calendar.todo.completed` / `calendar.reminder.fired`
- 步骤：
  1. **注册**：`svc-finance` 在自己的写事务内登记账单到期意图，经 outbox 发 `finance.due.registered`，确认由 `svc-calendar` 消费并落 `calendar_due_registration`
  2. **写**：本面创建原生对象（日程 / 待办 / 提醒各一条），确认唯一可写方是 `svc-calendar`
  3. **只读**：`GET /api/calendar/events` 返回跨来源聚合项且带 `source_system`/`source_id`；首页今日区由 `svc-homeos` 调本接口合成，不出现第二条读口
  4. **事件**：到期中心勾选完成 → 本面发 `calendar.todo.completed` → 归属服务消费并回写对象状态
  5. **提醒**：到点触发 → 本面发 `calendar.reminder.fired` → `svc-homeos` 消费后落 `reminder` 分型站内信与红点
- 预期结果：
  - 五步逐条走通，任一步断裂即判附加门禁①不过；不得以「其余五面未出生」放过本面这一支
  - 注册、回写、触发一律经事件异步，请求链路上不出现同步跨服务写调用（17.3、15.7）
  - 财务面五步与日历面五步**分别出结论**，不得合并写成「一次五步全通」
  - 本面全链路零直连推送通道：出现任何指向推送 SDK 的接口即判架构缺陷（5.5.8、19.1）
- 实现现状（快照）：未实现（判据来源 PRD 19.2 附加门禁① 与 15.5 第 8 项；`svc-calendar` 与其分包不存在）
- 执行状态：未执行
