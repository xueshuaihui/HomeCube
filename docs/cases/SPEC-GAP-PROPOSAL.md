## SPEC-GAP-01 · 验证码发送的频控阈值

**PRD 现状**
`3.7:417` 写「验证码发送按 22.4 限流」。而 `22.4:2546` 全节是「日志与数据保留」（业务审计 2 年、登录会话 6 个月…），**全文没有任何限流窗口、次数上限或超限错误码**。检索 `限流`/`频控`/`rate limit` 在 PRD 中仅此一处提及。

**建议口径**

| 维度 | 建议值 | 说明 |
|---|---|---|
| 单号冷却 | **60 秒/次** | 同一手机号 60s 内重复请求直接拒绝，不重发 |
| 单号日上限 | **10 次/日**（自然日，按 `Asia/Shanghai`） | 超过后当日不再发送 |
| 单 IP 日上限 | **100 次/日** | 防批量轰炸，超限不影响正常用户 |
| 超限响应 | **429** + `Retry-After: <秒>` + body `{"code":"rate_limited","retry_after":n}` | 用 HTTP 标准语义 |
| 枚举防护 | **不区分**「号码已注册/未注册」，一律返回同一响应 | 与 `3.7:417` 的「统一已发送」一致 |
| 计次口径 | 成功受理才计次（下游通道失败不计入用户额度） | 避免通道抖动惩罚用户 |

**依据**
- 60s 是短信验证码的通用下限：低于此值无法防重放，高于 120s 会让「输错重发」体验断裂。
- 10 次/日给「多次输错 + 换设备 + 网络重试」留足余量，同时把单号成本上界锁死在可控范围。
- 429 + `Retry-After` 是 RFC 6585 定义的标准语义，客户端可直接读头重试，不必猜。
- 「不区分注册状态」直接由 `3.7:417` 的「返回统一的已发送响应」推出，本项只是把它写成可断言的形式。

**落 PRD 后，HOM-SESS-001 的判据改为**
> 首次请求受理成功，返回统一「已发送」响应（不区分号码是否注册）。
> 同一号码 60 秒内二次请求被拒，返回 429 且带 `Retry-After`。
> 同一号码当日第 11 次请求被拒；次日零点后额度重置。
> 验证码落库为不可逆散列，明文只出现在投递通道。

## SPEC-GAP-02 · token TTL 与 refresh 有效期

**PRD 现状**
`3.7:417` 只写「refresh 轮换」，`16.6:2002` 只写「据 `pver` 做缓存比对」。全文检索 `TTL`、`过期`、`有效期`、`expire` **零命中**。所以「refresh 多久失效」「旧 refresh 换新后立即失效还是有宽限」全无判据。

**建议口径**

| 项 | 建议值 | 说明 |
|---|---|---|
| access token 有效期 | **2 小时** | 与 `pver` 缓存比对配合：权限变更后最迟 2h 内自然过期，另加主动失效 |
| refresh token 有效期 | **30 天**（滑动：每次轮换重置） | 家庭记账属低频应用，30d 避免频繁登录 |
| 轮换宽限 | **60 秒**：旧 refresh 在换新后 60s 内**仍可用一次** | 防「网络超时重试」被误判为重放攻击 |
| 宽限后行为 | 旧 refresh 立即失效，再次使用 **401 + 落审计**（`22.5` 的「登录」类） | 宽限外使用 = 明确的异常信号 |
| access 失效响应 | **401** + `{"code":"token_expired"}`，**不降级为匿名可读** | 与 `3.7` 的「全文无免鉴权例外」一致 |
| 会话记录保留 | 6 个月（`22.4:2556`），与 refresh 30d 是两回事 | 前者是审计留存，后者是凭据寿命 |

**依据**
- `16.6:2002` 要求中间件「据 token 内 `pver` 做缓存比对」——这暗示 access 生命周期内靠 `pver` 兜权限变更，因此 access 不宜过长（>4h 会让 `pver` 比对窗口过宽）。
- 30d refresh + 滑动重置，与「家庭记账每日打开」的使用频率匹配；再短会让低频用户反复登录。
- 60s 宽限解决一个真实故障：客户端已发出 refresh 请求但响应丢失，重试时旧 token 已失效 → 用户被踢。宽限只放宽「时间窗」，不放宽「次数」（同一旧 token 只能用一次）。

**落 PRD 后，HOM-SESS-002/003 的判据改为**
> 登录返回 access + refresh；claims 必须含 `family_id`、角色快照、`pver` 三项。
> refresh 换新后，旧 refresh 在 60s 内仍可用**一次**，第二次使用返回 401 并落审计。
> 越过宽限后旧 refresh 立即失效。
> access 过期访问受保护接口返回 401 + `token_expired`，不返回匿名数据。

## SPEC-GAP-06 · 通讯录邀请

**PRD 现状**
`3.4.1:254` 把邀请列为**四态**：「链接、二维码、邀请码、**通讯录**」。但技术方案的 S3 卡只写「邀请码/链接/二维码三态」（`docs/p1-tech-plan.md:455`），**通讯录邀请未进入任何 Sprint**。

**建议口径**

| 维度 | 建议 | 说明 |
|---|---|---|
| 期次 | **P1-M2** | 与三态邀请分离，不阻塞 M1 |
| 授权范围 | **只读**，不申请通讯录写入 | 最小权限 |

| 撤回 | 用户关闭授权后，已上传哈希 7 日内清除 | 可撤回是 `21.3` 的要求 |

- 定 M2 的理由同 SPEC-GAP-05。
