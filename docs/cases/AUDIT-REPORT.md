## 8. Round 4 · 口径校正（case 是需求基线，不是实现镜像）

### 8.1 触发的口径问题

前三轮把「实现现状」当成 case 有效性的度量，导致两个方向性隐患：

1. **度量反了**：总表以「自动化占比 41.1%」为主要健康指标——这实质是"代码完成度"，会让"实现没做"看起来像"case 质量差"，进而诱导裁 case。
2. **缺口被行为描述掩盖**：case 只写行为、不写接口契约，`PRD 153 个接口`里 **72 个无法被 case 文本检索到**，无法机械证明"全量覆盖"。其中**登录/验证码/refresh 三个接口与 demo-items 两个接口是真正的 0 条 case**（不是"有行为没写路径"）。

### 8.2 本轮改动

| 改动 | 内容 | 效果 |
|---|---|---|
| **度量分层** | 主指标改为「需求覆盖率」（`traceability.md`，脚本生成）；「实现覆盖度」降为副指标快照 | 分母不再随实现变动 |
| **列名校正** | 全量 `- 自动化状态：` → `- 实现现状（快照）：`（188 条） | 语义上不再暗示"case 质量" |
| **补 2 个真缺口文件** | `homeos/session.md`（6 条：验证码/登录/refresh/切换重签/会话保留/无账号禁登录）、`finance/demo.md`（2 条：五步链路 / S19 删除） | 188 条 case，`S3` 与 `S19` 从 0 条变为有承接 |
| **新增追溯矩阵** | `traceability.md` + `gen_traceability.py`（含 `--check`） | PRD 接口 → case 可机械校验；非一期接口单列不混入分母 |
| **新增反向开发清单** | `BACKLOG.md`：L1 需求缺口 4 项 / L2 实现缺口 20 项 / L3 验证缺口 | 每条 case 都能查到"还差什么才能过" |
| **lint 增 G-E** | 追溯门禁 + 生成文件时效 + BACKLOG 引用有效性 | 3 类退化被拦：漏接口、矩阵过期、清单引用幽灵 case |

### 10.5 证据体检收口（STALE 0 / DRIFT 0）

首跑 280 OK / 4 STALE / 7 DRIFT 之后，逐条核过一轮，**边界是「检查器的假阳性」还是「case 的证据错」**——这一步不能省，否则要么把工具噪音当问题改 case，要么把真错当噪音放过：

| case | 首判 | 复核结论 | 处置 |
|---|---|---|---|
| `HOM-CMP-006` | STALE | **真错**：`obs/metrics.go:96` 暴露 `/metrics`、`serve.go:245` 注册，`prometheus` 命中 5 个文件 | 证据改为「端点与 `code` 标签已有，九类指标缺八类 + `family_id` 未上 series + 无 `alerts.yml`」，仍判 `未实现` |
| `FIN-SPLIT-002` | DRIFT | **假阳性**：证据写 `:1565`、`:1716`，短写 `:1716` 才是 `NetAmountZero` 不变量所在 | 改进检查器（支持短写指针），不改 case |
| `FIN-SPLIT-005` | DRIFT | **假阳性**：同上，`:1923`/`:1995`/`:2051`/`:2089` 是同一文件的短写续指 | 同上 |
| `HOM-ARCH-013` | DRIFT | **假阳性**：`registry.go:1` 是「整个文件」的习惯写法，域表在 30 行以后 | 检查器对 `:1`/`:2` 放开到全文件 |
| `HOM-ARCH-018` | DRIFT | **假阳性**：`healthz`/`metrics` 在 `serve.go` 而证据混写了 `metrics.go:244` | 同上（短写归属修正） |
| `HOM-SUM-006` / `HOM-SESS-006` | DRIFT | **假阳性**：一条证据里引了多处 `文件:行号`，A 处的标识符被拿去证明 B 处 | 检查器改为「前后相邻指针之间」的双向窗口 |
| `HOM-SUM-007` | DRIFT | **真错**：证据写 `PeriodIllegal400`，全仓无此标识符；实际测试名是 `TestHomeSummaryPeriodIllegalIsFourHundredAndNeverFallsBack` | 改成真名 |

**检查器的三处修正**（`audit_baseline.py`）：

1. **短写指针 `:1716` 归属「位置最近的前一个全写指针」的文件**——一条证据常跨两个文件（`a.go:10`、`:20`，`b.go:30`、`:40`），只记全局 last-file 会把 a 的行号算到 b 头上（首版就因此把 `finance_tag_test.go` 判成 8 处越界）。
2. **标识符窗口改为「相邻两指针之间」，`文件:1` 放开到全文件**——只向前取会漏掉「`TestFoo` 见 `file:line`」写法；用整条证据的标识符去验任一处，两边都不可信。
3. **路径标识符允许末两段匹配**——case 写全路径 `/api/homeos/family/switch`，代码里是 `Group("/api/homeos")` + `POST("/family/switch")`，字面不同、语义同一。

> 这一步的产出比数字重要：**「检查器说 X 有问题」和「X 有问题」是两件事。** 7 条 DRIFT 里 5 条是工具错、2 条是真错——如果不做这轮复核，工具的可信度会在两周内归零（大家发现它总在报假警就不看了）。
