# HomeCube P1 一期 Case 管理总表

> **定位（先看这条）**：本 case 集是**需求基线**，由 `docs/prd-homecube.md` 派生，**不是**对现有代码的回归清单。
> 开发方向是**从 case 反推交付物**——缺什么补什么（见 `BACKLOG.md`）；**不因实现缺席而删 case、不改判据、不把条目移出分母**。
> **范围**：一期（P1）落地面 = HomeOS（底座）+ Finance（财务）+ Calendar（日历，定版 ㉚ 从底座析出的业务面），覆盖 S1–S19 全部功能点。
> 其余五面（purchase/diet/trip/kin/growth）属 P2–P6 出生期，**不在本表分母**。
> **权威源**：`docs/prd-homecube.md`（唯一需求源）、`docs/p1-tech-plan.md`（Sprint 表 §十一）、`docs/p1-page-structure-navigation.md`（定版记录）。
> **组织**：按功能模块/域分文件，每文件一份 case 集；本表为覆盖矩阵总表。
> **语言**：中文；状态枚举见下方。

## 状态枚举

- **类型**：功能 / 边界 / 异常 / 安全 / 性能
- **优先级**：P0（核心主路径）/ P1（重要）/ P2（次要边界）
- **实现现状（快照，8 值）**——只记录"现在做到哪"，**不参与 case 是否成立的判定**：
  - `已实现(HTTP)`：handler 层有 HTTP 测试，**必须带 `文件:行号` 证据**
  - `已实现(分层)`：仅 repo/service/单测层有覆盖，HTTP 层未测
  - `契约偏差`：**代码主体在，但 HTTP 面（路径/方法/响应）与 PRD 不符，或路由未挂载**。必须带 `文件:行号` **且** `- 偏差登记：DEV-NN`（见 `DEVIATIONS.md`）；`执行状态` 只允许 `未执行` / `失败`，**禁止「通过（除路径外）」**
  - `待自动化`：有实现、无测试（或仅有桩）
  - `未实现`：PRD 要求但代码不存在（归线 B）
  - `纯手动`：需真机 / 人眼 / 多端协同
  - `引用脚本`：指向真实 make target 或 `deploy/scripts/*.sh`
  - `CI门禁`：由 CI 静态检查保证
- **执行**：`未执行` / `通过` / `失败` / `阻塞(原因)`
- **建议归属 Sprint**：`S1`~`S6` / `S7-S8` / `S9-S10` / `S11-S12` / `S13` / `S14` / `S15-S16` / `S17-S18` / `S19` / `未点名(P1-M1)` / `未点名(P1-M2)`
  > **不得写 S7/S8/S9/S10/S11/S12/S15/S16/S17/S18 单值**——技术方案 §十一 只有 `S7-S8`/`S9-S10`/`S11-S12`/`S15-S16`/`S17-S18` 合并行，单值无原文依据。

## 审核口径（每轮按此判定）

| Gate | 判定内容 | 通过标准 |
|---|---|---|
| **G-E 需求覆盖率**（首要） | PRD 一期接口 → 是否有 case 承接 | **100%**：`traceability.md` 无未承接项；生成器 `--check` 退出码 0；生成文件不滞后于 case 变动 |
| **G-A 引用真实性** | 章节号、接口路径、文件名 | 章节号在 `prd-homecube.md` 存在；接口路径在 PRD 中存在；引用的文件真实存在 |
| **G-B Sprint 依据** | 建议归属 Sprint | 只能取白名单值；`S7/S8/S9/S10/S11/S12/S15/S16/S17/S18` 单值一律拦（技术方案 §十一 只有合并行） |
| **G-C 实现现状证据** | 实现现状（快照） | `已实现(*)` 必须带 `文件:行号`；`未实现` 必须写缺失物依据；`引用脚本` 必须指向真实脚本 |
| **G-D 结构一致性** | ID / 字段 / 统计 / 覆盖 | ID 唯一；字段齐全；本表行数 = 模块文件之和；统计数字与实测一致；crosscutting 与 BACKLOG 引用的 case 必须存在 |
| **G-G4 偏差闭环** | `契约偏差` ⇔ `DEV-NN` | 标 `契约偏差` 必须带 `文件:行号` + `- 偏差登记：DEV-NN`；DEV 必须在 `DEVIATIONS.md` 在册且状态为「开」；DEV 关闭后 case 不许仍是 `契约偏差`；`契约偏差` 的执行状态禁止 `通过` |
| **G-E4 编号在册** | crosscutting 引用的 IMPL/DEV | 已撤销或已迁移的编号（如登录链路三张卡、迁移到 DEV 的标签卡）不得再被当作依赖引用 |

校验脚本：`bash docs/cases/lint.sh`（G-A~G-F + G-G4 + G-E4）· 重新生成矩阵：`python3 docs/cases/gen_traceability.py` · 证据体检：`python3 docs/cases/audit_baseline.py --audit`

> **判定顺序的意义**：先查 G-E（"该有的 case 有没有"），再查 G-A~G-D（"写对没写对"）。
> 若把 G-C 放在首位，就会退化成"按实现现状裁剪 case"——那正是本体系明确不采用的口径。

## 使用约定

1. **新增 case**：在对应模块文件追加 `Xxx-NNN`（`NNN` 顺延），然后**重跑** `python3 docs/cases/gen_index.py` 生成矩阵与统计——**数字不手写**，手写的会被 `lint.sh` 判为漂移。
2. **执行回填**：跑完一条即更新「实现现状 / 执行」两列；失败/阻塞须写明原因，不得合并为"完成"。
3. **验收追溯**：19.2 / 19.3 / 19.4 逐条映射见 `crosscutting/acceptance-19.2-19.3.md`，本表 case 与该文件双向可查。
4. **禁止虚假修复**（见 `p1-dev-brief.md` §6）：不得放宽判据、不得桩冒充、不得静默改文档迁就代码。
5. **未实现项**：case **保留在分母内**、状态标 `未实现`，并在 `BACKLOG.md` 登记其交付物；**不得以「待自动化」或「纯手动」掩盖，更不得删除该 case**。
6. **需求缺口**：判据无法从 PRD 得出时，写 `待 PRD 补齐` 并登记 `SPEC-GAP`，**不得自行编造阈值**，也不得因此把 case 判为“不适用”。
