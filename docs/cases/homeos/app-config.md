## HOM-APP-001 · 设置必须是活配置（写即生效）
- 关联需求：PRD 3.3（设置必须是活配置，禁止只做静态展示层）、3.4.8（三级授权与免打扰两层归口 Q12）、3.7 `PUT /api/homeos/settings`
- 类型：功能 | 优先级：P0 | 建议归属 Sprint：未点名(P1-M1)
- 前置条件：**四类角色账号各一**——管理员、成人成员（非管理员）、儿童（有账号）、访客；**同一账号在两台设备登录**（设备 A 用于设本机覆盖、设备 B 用于「已设覆盖不受影响」那一支）；服务端 `GET/PUT /api/homeos/settings` 与审计查询口可达；抓包与审计条数均可计数
- 步骤：修改某设置项 → 立即读回；**三类写口各走一遍**：① 本人级（主题）改后立即生效且不传播；② 家庭级仅管理员（日期格式）管理员改 → 全家庭下次渲染读回新值；③ **家庭级成人可改（免打扰家庭默认）：成人成员从 `27-settings` 免打扰时段选择层的「设为家庭默认」（⑩）写 → 家庭默认读回新值，另一台已设本机覆盖的设备仍显自己的值，未设覆盖的设备下次同步按新默认（3.4.8 Q12 ②③）**
- 步骤续（**本轮补齐的 ⑨/⑩ 两支，判据可测**）：
  1. **⑨「保存」（本机覆盖）逐角色各点一次**：管理员 / 成人成员 / 儿童（有账号）/ 访客各在设备 A 的免打扰时段选择层点「保存」改本机时段；每次点前后抓包并数审计条数——**要求这三件事同时成立：服务端请求数 = 0、审计新增条数 = 0、该角色按钮可点且本机行尾值即时更新**（3.4.8 Q12 ①「本机覆盖是设备级设置，不上服务端、不占 16.3 的矩阵格、不写审计」+ ⑨「设备级、不判权、不发服务端请求、不写审计，任何在用这台设备的成员（含儿童与访客）都可改」；客户端不得出现权限分支，18.7 第 4 条）
  2. **⑩「设为家庭默认」正样本**：成人成员与管理员在设备 A 选好起止后点「设为家庭默认」→ 数抓包与审计：**`PUT /api/homeos/settings` 请求数 = 1、状态码 2xx、审计新增条数 = 1**，且家庭默认值读回为新值（⑩ 是 P1 家庭默认值的**唯一写入口**，无第二条路径）
  3. **⑩ 的角色不渲染断言**：儿童（有账号）与访客进入同一层——**「设为家庭默认」这颗按钮不渲染**：可点元素集合里搜不到它、也不可通过 Tab/无障碍聚焦到它（PRD 3.4.8「非成人角色不渲染该动作」；原型侧的对照实现是 `docs/v2/prototypes/settings.html:73` 在 `body[data-state="minor"]` 下隐藏 `#dnd-set-family`，可作可达性的抽检对象，**但判据以「不渲染/不可达」为准，不以 `display:none` 为准**）；同层内说明文字改为「家庭默认时段由家里的成人维护」一支一并断言
  4. **⑩ 的越级负样本（绕过客户端直发）**：用儿童（有账号）与访客的合法 token **直接** `PUT /api/homeos/settings` 写家庭默认时段，**≥100 次**（样本量取 19.2#6 的越权写判定口径）；三件事逐条数得出：**请求数 ≥100、状态码 = 403（越权成功 0 次）、审计新增条数 = 请求条数（被拒 100% 落审计，16.6）**；且家庭默认值**一条都未变**
  5. **③ 家庭默认被改后的两支**：成人成员经 ⑩ 改家庭默认后——(a) **未设本机覆盖**的成员（设备 B 未点过 ⑨）下次同步即读到新家庭默认；(b) **已设本机覆盖**的成员（设备 A 点过 ⑨）仍读自己的本机值、不受影响
  6. **② 清除本机覆盖的回落**：在设备 A 清除本机覆盖 → **立即回落当前家庭默认值**，断言取的是「此刻服务端家庭默认」而非本机旧缓存（构造：设本机值 X → 管理员把家庭默认改成 Y → 清除本机覆盖 → 期望读到 **Y**、读到 X 即不通过）
  7. **④ 本机覆盖不进家庭级统计**：设备 A 设过本机覆盖后，复跑 19.2#9「停用前后统计一致」那一支——**本机覆盖不得改变任何家庭级验收统计的数值**（3.4.8 Q12 ④）
- 预期结果：写入即生效，非静态展示；**⑩ 的写落在 `PUT /api/homeos/settings` 且落审计**（请求 1 次 / 2xx / 审计 1 条三数同真）；本机覆盖（⑨ 保存）**不出现在任何服务端写请求里、不产生审计条目**（请求数 = 0 且审计条数 = 0），且**任何在用这台设备的成员（含儿童与访客）都可点**；**非成人账号绕过客户端直发该写口一律 403 且逐次落审计（≥100 次 → 403 数 = 请求数、审计新增数 = 请求数、越权成功数 = 0）**；非成人角色页面上**不渲染** ⑩；③②④ 三支按上面步骤 5/6/7 的期望值成立；finance 设置同口径（4.8）
- 实现现状（快照）：未实现（全仓无 `/api/homeos/settings` 路由与 handler，PRD 3.7:413-413 要求 GET/PUT）
- 执行状态：未执行
