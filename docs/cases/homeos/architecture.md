## HOM-ARCH-001 · 模型按领域分层：身份域与财务域不同包、有 service 层、展示字段不靠 ORM 旁路拼装

- 关联需求：PRD 3.2:218（模型按领域分层（身份域与财务域不同包），有 service 层；展示字段不靠 ORM 旁路（如 `gorm:"-"`）在 handler 里拼装）
- 类型：边界 | 优先级：P0 | 建议归属 Sprint：S1
- 前置条件：代码库可静态扫描；`server/services/svc-homeos`、`server/services/svc-finance` 已建包
- 步骤：
  1. 扫描两个服务 `internal/` 下的包目录，列出领域包清单，检查身份域与财务域是否落在不同包
  2. 检查每个领域包是否存在 service 层（`internal/service` 或等价层），且 handler 是否直接调用 repo 绕过 service
  3. 扫描全部 `gorm:"-"` 出现点，逐个判定用途：是「查询结果的派生字段」（允许）还是「handler 里拼装的业务展示字段」（禁止）
  4. 抽查 3 个列表接口的响应组装路径，确认展示字段来自 service/repo 而非 handler 现场计算
- 预期结果：
  - 身份域与财务域不同包；`svc-finance` 不 import `svc-homeos` 的 `internal`（Go 编译器会拒绝，正确做法是共用包下沉到 `packages/`）
  - 每个领域包有 service 层；handler 层不含业务计算
  - `gorm:"-"` 仅用于查询投影结构上的派生字段，**handler 内 `gorm:"-"` 拼业务展示字段命中数 = 0**
  - 判定口径必须写进检查脚本注释，避免把 `repo/homeos_projection.go` 这类「Raw SQL 扫描结构 + 派生字段」误判为违规
- 实现现状（快照）：待自动化（无静态检查脚本；已知 `server/services/svc-homeos/internal/repo/homeos_projection.go:61` 的 `AsOf *time.Time \`gorm:"-"\`` 属查询投影派生字段，按上述口径不构成违规，但当前无脚本固化该判定）
- 执行状态：未执行

- 实现现状（快照）：待自动化（无路由静态扫描脚本；当期业务路由尚未出生，只有两个运维端点，断言无对象可判）

- 关联需求：PRD 3.2:209（**P1-M1 交付事件总线骨架**（事件定义/发布/订阅/日志/幂等/重试/死信/版本））、10.1 事件命名、10.2 事件结构
