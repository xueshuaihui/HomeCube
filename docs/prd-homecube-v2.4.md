## 一、产品概述

### 1.1 产品背景

家庭日常生活涉及钱、物、吃、行、人、成长六大核心场景，但现有工具高度碎片化：记账用记账 App，购物用清单 App，菜谱用菜谱 App，提醒用日历 App，家庭成员信息分散在微信、备忘录、相册中。家庭缺少一个统一入口，也缺少面与面之间的自动流转。

家立方 HomeCube 以“一个家，六个面”为核心理念，把家庭生活管理拆成六个完整业务系统，每面独立完整，面间通过底层能力拉通，形成家庭生活闭环。

### 1.2 产品定位

- **一句话定位：** 全家生活一站式管理 App。
- **品牌 Slogan：** 全家生活，立体管理。
- **六面一句话：** 钱有账，物有库，吃有谱，行有程，人有录，长有迹。
- **产品形态：** 移动端为主，支持多端同步，后续扩展 Web、平板、智能家居。
- **目标用户：** 有家庭生活管理需求的个人与家庭，覆盖无娃家庭、有娃家庭、有老人家庭、养宠家庭。

### 1.3 设计原则

1. **每面独立完整**：每一面是一个完整业务系统，内部高内聚，外部低耦合。
2. **交互因面而异**：不追求六面交互一致。财务偏数据报表，采购偏清单勾选，饮食偏图片卡片，出行偏时间线地图，家人偏档案标签，成长偏记录打卡。
3. **底层拉通**：时间、日历、提醒、待办、人员、权限、通知、同步、动态、搜索、AI 归类，全部下沉为底层基础能力。
4. **面间联动**：通过底层事件总线与规则引擎，不直接耦合。
5. **去 MVP 化**：不以最小可用为目标，每面按完整业务域分波次交付。
6. **Agent 驱动**：需求、设计、开发、测试、部署、文档、复盘由 Agent 协作推进，人类负责目标、优先级、验收与伦理。

### 1.4 名词定义

| 名词 | 定义 |
|---|---|
| 面 | 六大业务域之一，如财务面、采购面 |
| 系统 | 一个面即一个完整系统，如财务系统 |
| 底层 | 六面共用的基础系统 HomeOS |
| 事件总线 | 系统间联动的基础设施 |
| 规则引擎 | 系统间自动流转的配置中心 |
| Wave | 迭代波次，按依赖关系分波推进 |
| Agent | 参与研发全流程的智能体 |


## 二、系统总览

### 2.1 系统分层

家立方由 **7 个系统**组成：

| 层级 | 系统 | 定位 |
|---|---|---|
| 底层 | 家庭操作系统 HomeOS | 六面共用的基础系统 |
| 业务层 | 财务系统 | 管钱 |
| 业务层 | 采购系统 | 管物 |
| 业务层 | 饮食系统 | 管吃 |
| 业务层 | 出行系统 | 管行 |
| 业务层 | 家人系统 | 管人 |
| 业务层 | 成长系统 | 管长 |

一句话：

> **一个底层系统 + 六个业务系统。**
> **底层管连接，六面管生活。**

### 2.2 系统关系图

```
                    ┌─────────────────────┐
                    │   家庭操作系统       │
                    │  HomeOS             │
                    │  人员·权限·时间·通知  │
                    │  同步·搜索·AI·事件   │
                    └──────────┬──────────┘
                               │
        ┌──────────┬───────────┼───────────┬──────────┬──────────┐
        │          │           │           │          │          │
   ┌────▼───┐ ┌───▼────┐ ┌────▼───┐ ┌────▼───┐ ┌────▼───┐ ┌────▼───┐
   │ 财务系统│ │ 采购系统│ │ 饮食系统│ │ 出行系统│ │ 家人系统│ │ 成长系统│
   └────────┘ └────────┘ └────────┘ └────────┘ └────────┘ └────────┘
```

### 2.3 系统设计原则

1. **一面一系统**：每个面是一个完整系统，内部高内聚，外部低耦合。
2. **系统有边界**：每个系统明确“做什么、不做什么”。
3. **数据有归属**：每个数据对象只有一个归属系统，其他系统通过事件引用。
4. **能力不重复**：时间、权限、通知、同步等能力只在底层实现。
5. **交互可异构**：每个系统按自己的业务逻辑设计交互，不强制统一。
6. **联动靠事件**：系统之间不直接调用，通过底层事件总线通信。
7. **系统可独立**：每个业务系统可独立运行、独立交付、独立验证。


## 三、底层系统：家庭操作系统 HomeOS

### 3.1 系统定位

HomeOS 是六面共用的基础系统，负责**连接、协调、支撑**，不直接面向家庭业务。它相当于家庭生活的“操作系统”，六面是运行其上的“原生应用”。

### 3.2 系统边界

**做：**
- 家庭、成员、角色、权限
- 时间、日历、提醒、待办、周期任务
- 通知、消息、动态、协作
- 数据同步、备份、加密、导出
- 全局搜索、语音、拍照、AI 归类
- 事件总线、规则引擎
- 设置、主题、账号、安全

**不做：**
- 不做记账、清单、菜谱、行程、档案、成长记录等业务
- 不存储业务数据，只做索引与引用
- 不定义业务规则，只提供规则执行能力

### 3.3 系统职责

| 职责 | 说明 |
|---|---|
| 身份与权限 | 谁是谁、谁能看什么、谁能改什么 |
| 时间与提醒 | 所有系统的时间触发统一由底层处理 |
| 通知与协作 | 所有系统的消息、动态、投票统一由底层处理 |
| 数据与同步 | 所有系统的数据同步、备份、加密统一由底层处理 |
| 智能与搜索 | 所有系统的搜索、语音、拍照、AI 归类统一由底层处理 |
| 事件与规则 | 所有系统之间的联动统一由底层事件总线与规则引擎处理 |
| 设置与安全 | 全局设置、账号、安全、隐私统一由底层处理 |

### 3.4 详细需求

#### 3.4.1 家庭核心
- 创建家庭、加入家庭、切换家庭、解散家庭
- 邀请成员：链接、二维码、邀请码、通讯录
- 成员管理：添加、编辑、移除、转让管理员
- 角色：管理员、成人成员、儿童/老人、访客
- 权限：模块级、数据级、操作级
- 隐私：字段级可见性、财务隐私、健康隐私、儿童保护

#### 3.4.2 时间系统
- 日历：家庭共享、个人、多视图（日/周/月/年）
- 提醒：单次、周期、位置、到期
- 待办：创建、分配、完成、归档、子任务
- 周期任务：每天/周/月/年、自定义、跳过、顺延
- 到期中心：聚合六面所有到期事项
- 通知：推送、站内信、@、免打扰、分组

#### 3.4.3 协作系统
- 动态流：六面所有变更、完成记录
- 留言：家庭留言板、模块内评论
- 投票：单选、多选、匿名、截止时间
- @提醒、已读状态、家庭公告

#### 3.4.4 数据系统
- 多端同步：实时、离线、冲突解决（LWW + 业务合并）
- 备份恢复：自动每日、手动、版本回滚
- 加密：传输 TLS 1.3、存储 AES-256、敏感端到端
- 导出：Excel、PDF、CSV、图片
- 迁移：导入、导出、跨设备

#### 3.4.5 智能系统
- 全局搜索：跨六面、自然语言
- 语音输入：记账、添加、提醒
- 拍照识别：OCR 小票、条码、菜谱、证件
- AI 归类：内容识别 → 归入对应系统
- 智能建议：基于家庭数据的主动建议
- 产品内 Agent：家庭助手、问答、主动提醒

#### 3.4.6 事件系统
- 事件定义、发布、订阅、日志
- 幂等、重试、死信、版本管理

#### 3.4.7 规则系统
- 规则配置、默认规则、自定义规则
- 优先级、冲突处理、模拟测试、执行日志

#### 3.4.8 设置系统
- 主题、通知、账号、安全、帮助、关于
- 多语言、时区、货币、日期格式

### 3.5 交互设计

- **首页**：家庭切换器、动态流、快捷入口、到期中心
- **导航**：底部 Tab（首页、动态、+、消息、我的）
- **全局 +**：语音、拍照、文字、模板
- **设置**：分组列表、搜索、帮助
- **风格**：中性、克制、系统感，不抢业务系统视觉

### 3.6 数据模型

| 实体 | 关键字段 |
|---|---|
| Family | id、name、avatar、timezone、currency、created_at |
| Member | id、family_id、user_id、name、role、birthday、avatar、status |
| Role | id、name、permissions |
| Permission | id、scope、resource、action、condition |
| Event | id、type、source、payload、version、created_at |
| Rule | id、name、condition、action、priority、enabled |
| Notification | id、member_id、type、content、read_at |
| Dynamic | id、family_id、source、action、payload、created_at |
| Todo | id、family_id、member_id、title、due_at、status、source |
| Reminder | id、owner_id、type、trigger_at、repeat、status |
| File | id、owner_id、type、url、size、hash |

### 3.8 验收标准

- 家庭创建、邀请、权限生效 ≤ 2 秒
- 提醒、待办到达率 ≥ 99.9%
- 同步延迟 ≤ 1 秒，冲突可解决
- 搜索响应 ≤ 500ms，跨六面命中
- 事件幂等、可重试、可追溯
- 权限变更实时生效
- 敏感数据加密存储
- 崩溃率 ≤ 0.1%


## 四、财务系统

### 4.1 系统定位

家庭财务管理系统，管钱。

### 4.2 系统边界

- 做：收支、账户、预算、报表、账单、借贷、储蓄目标、共享账本。
- 不做：不做采购执行、不做饮食消费决策、不做投资理财建议。

### 4.3 系统职责

- 记录家庭所有资金流动
- 管理家庭账户与资产
- 控制预算与支出
- 生成财务报表
- 支持家庭共享与分账

### 4.4 核心能力域

| 能力域 | 内容 |
|---|---|
| 记账 | 收支、转账、借贷、报销、多账本、多币种、标签 |
| 账户 | 现金、银行卡、第三方支付、信用卡、资产总览 |
| 预算 | 总预算、分类预算、成员预算、超支提醒 |
| 报表 | 趋势、分类、成员、商家、净资产、导出 |
| 账单 | 周期账单、待缴、已缴、逾期、发票 |
| 借贷 | 借入、借出、还款计划、结算 |
| 目标 | 储蓄目标、家庭共同目标 |
| 共享 | 家庭账本、多人记账、AA 分账、权限 |

### 4.5 详细需求

#### 4.5.1 记账
- 快速记账：金额、分类、账户、备注、拍照
- 多账本：日常、旅行、装修、孩子、项目
- 分类：一级/二级、自定义图标、颜色
- 账户：现金、银行卡、支付宝、微信、信用卡、公积金、外币
- 收支类型：支出、收入、转账、借入、借出、报销
- 标签：项目、成员、地点、商家
- 周期记账：房租、房贷、工资、订阅
- 模板记账、语音记账、拍照记账、OCR
- 流水：按日/周/月/年、分类、账户、成员
- 搜索筛选、编辑删除、批量、回收站

#### 4.5.2 预算
- 总预算、分类预算、成员预算
- 周期：月/季/年
- 进度、超支提醒、结转、模板
- 预算与实际对比

#### 4.5.3 报表
- 趋势、分类、成员、商家、净资产、资产负债
- 月报、年报、自定义
- 导出 Excel/PDF

#### 4.5.4 共享账本
- 家庭共享、多人记账、权限
- AA 分账、共同支出分摊
- 结算中心：谁欠谁、一键结清

#### 4.5.5 账单
- 周期账单、提醒、自动扣款标记
- 待缴、已缴、逾期、发票

#### 4.5.6 借贷
- 借入、借出、还款计划、提醒、逾期、报表

#### 4.5.7 目标
- 储蓄目标、进度、自动存入、家庭共同目标

#### 4.5.8 账户资产
- 余额、流水、信用卡账单、还款日、资产/负债总览

### 4.6 交互设计

- **首页**：净资产卡片 + 本月收支 + 预算进度 + 快捷记一笔
- **底部 Tab**：流水、报表、预算、账本、我的
- **记账入口**：悬浮 +、语音、拍照
- **流水**：按日分组、滑动编辑、长按批量
- **报表**：图表切换、时间筛选、下钻
- **风格**：数据感、清晰、克制

- 记账 ≤ 3 步完成，≤ 5 秒
- 流水加载 ≤ 300ms（1000 条）
- 报表生成 ≤ 1 秒

## 五、采购系统

### 5.1 系统定位

家庭采购与库存管理系统，管物。

### 5.2 系统边界

- 做：购物清单、库存、补货、采购记录、比价。
- 不做：不做支付、不做物流、不做电商交易。

### 5.3 系统职责

- 管理家庭购物需求
- 管理家庭物品库存
- 管理保质期与补货
- 记录采购历史
- 支持家庭协作采购

### 5.4 核心能力域

| 能力域 | 内容 |
|---|---|
| 清单 | 多清单、共享、认领、常买、模板、语音添加 |
| 库存 | 物品档案、位置、入库出库、批次、保质期 |
| 补货 | 消耗记录、低库存提醒、自动加购 |
| 记录 | 采购历史、价格、商家、统计 |
| 比价 | 优惠券、价格跟踪、促销提醒 |
| 协作 | 家庭共享、任务分配、完成动态 |

### 5.5 详细需求

#### 5.5.1 购物清单
- 多清单：日常、超市、网购、旅行、节日

{
  "event_id": "uuid",

  "version": "1.0",

- 日志：全量记录，可追溯


## 十一、迭代规划与 Agent 推进机制

### 11.1 去 MVP 化原则

- **不设 MVP**：不以“最小可用”为目标，不以残缺功能上线。
- **每面完整闭环**：每一面都按完整业务域设计。
- **分波次交付**：不是砍功能，而是按依赖关系分 Wave 推进。
- **底层先行**：家庭核心、时间、权限、通知、同步、搜索、AI 归类先建成底座。
- **六面并行**：业务面可并行迭代，底层能力统一提供。
- **联动后置**：先让每面独立可用，再通过事件总线与规则引擎拉通。
- **Agent 全流程参与**：需求、设计、开发、测试、部署、文档、复盘均由 Agent 协作推进，人类负责目标、优先级、验收与伦理。

### 11.2 迭代分层

| 层级 | 内容 | 目标 |
|---|---|---|
| L0 底层底座 | 家庭核心、时间系统、协作系统、数据系统、智能系统、设置系统 | 六面共用基础设施 |
| L1 六面完整闭环 | 财务、采购、饮食、出行、家人、成长 | 每面可独立使用 |
| L2 六面深度能力 | 每面达到独立 App 完整度 | 专业、完整、可替代单点工具 |
| L3 跨面联动 | 事件总线、规则引擎、数据同步 | 面与面自动流转 |
| L4 智能化 | AI 建议、预测、自动归类、产品内 Agent | 主动服务家庭 |
| L5 开放生态 | 开放 API、智能家居、社区服务、第三方集成 | 家庭生活平台 |

### 11.3 迭代波次规划

| Wave | 周期 | 目标 | 范围 | 交付物 | 验收标准 |
|---|---|---|---|---|---|
| Wave 0 | 8-12 周 | 建成底层底座 | 家庭组、成员、权限、日历、提醒、待办、通知、动态、搜索、同步、备份、安全 | 底层服务、SDK、管理后台 | 六面可接入，权限与同步稳定 |
| Wave 1 | 12-16 周 | 六面完整闭环 | 财务记账、采购清单、饮食菜单、出行行程、家人档案、成长记录 | 六面第一版完整业务闭环 | 每面可独立完成核心任务 |
| Wave 2 | 16-24 周 | 六面深度能力 | 预算报表、库存补货、菜谱食材、车辆旅行、偏好照护、课程习惯 | 每面达到独立 App 完整度 | 可替代对应单点工具 |
| Wave 3 | 12-16 周 | 跨面联动 | 菜单→采购、采购→财务、生日→提醒、课程→日历、出行→费用 | 事件总线、规则引擎、联动配置 | 联动成功率≥99% |
| Wave 4 | 12-20 周 | 智能化与 Agent | AI 记账、AI 补货、AI 菜谱、AI 行程、AI 照护、AI 成长报告 | 产品内 Agent、智能建议 | 建议采纳率、自动化率达标 |
| Wave 5 | 持续 | 开放生态 | 开放 API、智能家居、社区服务、第三方接入 | 开放平台、插件体系 | 第三方可接入，生态可扩展 |

### 11.5 Agent 体系设计

### 11.6 Agent 工作流

1. **人类设定目标**：确定 Wave 目标、优先级、验收标准。
2. **Orchestrator 拆解**：生成任务卡、依赖图、排期。
3. **Product Agent 细化**：输出用户故事、验收标准。
4. **Architect Agent 设计**：输出架构、数据模型、API。
5. **UX/UI Agent 原型**：输出交互稿、视觉稿、组件。
6. **Frontend / Backend Agent 开发**：并行编码，提交 CI。
7. **Test Agent 测试**：单元、集成、回归、自动化。
8. **Security Agent 审计**：权限、隐私、加密、漏洞扫描。
9. **DevOps Agent 部署**：灰度、监控、回滚。
10. **人类验收**：关键节点审批，确认业务价值。
11. **Docs Agent 更新**：文档、帮助、更新日志。
12. **Review Agent 复盘**：输出迭代报告，进入下一波。

### 11.7 迭代节奏与看板

- **Sprint 周期**：2 周。
- **Wave 周期**：8-24 周，视范围而定。
- **每日站会**：Agent 报告进度、阻塞、风险。
- **看板列**：需求池 → 已拆解 → 设计中 → 开发中 → 测试中 → 待验收 → 已发布 → 复盘。
- **并行策略**：底层串行，六面并行，联动后置。
- **版本节奏**：每 4 个 Sprint 发布一个大版本。

### 11.8 验收与度量

| 维度 | 指标 |
|---|---|
| 功能完整度 | 每面独立可用性评分 |
| 业务闭环 | 核心任务完成率 |
| 跨面联动 | 联动成功率、数据一致性 |
| 质量 | 缺陷密度、自动化覆盖率 |
| 安全 | 漏洞数、隐私合规率 |
| 效率 | Agent 任务完成率、一次通过率、人类返工率 |
| 用户价值 | 留存、活跃、任务完成率、建议采纳率 |

### 11.9 风险与治理

- **Agent 幻觉**：关键需求、架构、安全节点必须人类审批。
- **代码质量**：CI 强制检查，Test Agent 与 Security Agent 双重审计。
- **隐私安全**：家庭数据分级、加密、权限最小化。
- **多 Agent 冲突**：Orchestrator 统一调度，冲突升级人类决策。
- **架构漂移**：Architect Agent 定期评审，版本冻结。
- **人类监督**：产品负责人、技术负责人、家庭用户代表参与验收。
- **回滚机制**：灰度发布，一键回滚，数据备份。
