## 一、导航骨架

### 1.1 骨架（全 App 唯一）

```
┌──────────────────────────────────────────────────────┐
│ 顶栏一行（HomeOS shell）                             │
│  [示例家庭 ▾]                            🔍  🔔·     │ ← 左：家庭切换器｜中：**空**（不放面切换器，⑫）｜右：两个动作位（全局搜索、消息入口带未读红点）
├──────────────────────────────────────────────────────┤
│ 时间窗条（状态由主包 store 持有，各面消费）〔①〕     │ ← 月 / 季 / 年三档（⑬）；**首页与财务面都渲染**，不占顶栏
├──────────────────────────────────────────────────────┤
│ L2 面内二级 Tab（该面拥有，在内容区内，不叠加底部栏）│
│   财务：流水 / 报表 / 预算 / 账本 / 账户与设置       │ ← ⑫ 之后它兼作「我在哪个面」的唯一位置感
├──────────────────────────────────────────────────────┤
│                                                      │
│                 L3 内容区（页面栈）                  │ ← 每条路由一个页面
│                                                      │
├──────────────────────────────────────────────────────┤
│ D 行（HomeOS shell） 首页   动态   ＋   消息   我的  │ ← 恒定五项，切面不改变；非原生 tabBar；「首页」是唯一的切面枢纽位
└──────────────────────────────────────────────────────┘
```

- **顶栏是一行**（定版，17.1）：家庭切换器在左 + 右侧两个动作位（全局搜索、消息入口）同处一栏，**中间不放任何东西**。顶栏的高度与结构和面的数量、面名长度彻底无关；家庭名过长时截断显示——早期那条「家庭名不给 chip 让位」的排序规则随 ⑫ 一起失效，顶栏不再有两组东西争宽度。
- **面切换器已从顶栏移除（定版 ⑫，取代 12.1 ① 的后一半）**：面入口**只有首页 C 区服务矩阵一处**（§1.4）。
  - **代价**：面内切面 = 返回该面一级页 → D 行「首页」→ 点目标格，**恒定 3 步**；这条进 §6 的步数预算与 18.2#9 的走查断言。消息入口留在顶栏而面入口不留，是因为未读是被动信息（随时要看），切面是主动动作（本来就该先回全景页）。
  - **红利**：面集合的客户端消费者从六处减为**五处**（首页矩阵、「＋」目标、搜索分组、到期中心注册项、动态流筛选）；面图标不必压到 14px，用途回到首页矩阵、开通页与「＋」目标列表；「一处可点而另一处不可点」这类分歧在结构上不存在了。
- **消息入口位的唯一理由**：二级页压栈后 D 行被内容区盖住，未读仍要一步可达（17.1 第 1 条）。它在一级页与 D 行「消息」构成刻意冗余，**两处读同一份未读状态、同时熄灭**；顶栏位只显红点不显数字，D 行位显红点 + 计数（3.4.2）。
- **时间窗条首页也渲染（定版 ⑬）**：首页 C 区财务格的状态句读 `period`，所以「时间窗条只在业务面出现」的旧写法不成立；档位恒为**月 / 季 / 年三档**，编码 `YYYY-MM` / `YYYY-Qn` / `YYYY`（§6.4）。
- **一级导航（顶栏、时间窗条、D 行）全部由 HomeOS shell 组件提供**，业务面只消费、不实现、不改写（17.7 第 3、8 条）。
- **L2 是面内导航**，形态为内容区顶部的横向 Tab；Tab 本身不是路由，**每个 Tab 项落到一条 `list`（`index`）路由**（17.1 末条）。二级 Tab 之下不再有第三层常驻栏；**末位 Tab 不叫「我的」**（17.3 定版）。
- **未挂载的面（未启用或未出生）在首页矩阵与其余四个消费位都不出现**，不留描边、不留置灰位（17.8）；它们只在「我的 → 开通更多面」的目录页里可见。

### 1.2 区域所有权

| 区域 | 拥有方 | 业务面可以做什么 | 校验点 |
|---|---|---|---|
| 顶栏·家庭切换器（左） | HomeOS shell | 只读当前 `fid`/角色/币种/时区，不得替换或自建入口 | 分包内出现切换家庭的调用即门禁 4 失败 |
| 顶栏·搜索（右一） | HomeOS shell | 不得自建第二处全局搜索入口 | 分包内出现非 `/api/homeos/search` 的搜索调用即失败（17.6） |
| 顶栏·消息入口（右二，带未读红点） | HomeOS shell | 不得自建消息中心、通知入口或未读计数（17.7 第 1 条） | 顶栏红点与 D 行红点读 shell 的同一份 `unread`；**分包内出现自建未读计数即门禁 4 失败**（17.1） |
| 时间窗条 | HomeOS shell（状态在主包 store） | 消费当前 `period`，不得各面自存一份月份 | 分包内出现自造时间窗状态即 §6.4 的断言失败 |
| **首页 C 区面矩阵（全 App 唯一面入口，⑫）** | HomeOS shell（页面在主包） | 声明本面图标与标题（registry 域表提供）、提供该面的 `headline`/`badge` 数据 | 矩阵集合 = `FamilyModule` 已启用 ∩ 已出生；分包内硬编码面清单、**或自建第二处面入口（面切换器、「开通更多」悬浮位）即门禁 4 失败**（17.8、⑫） |
| D 行五项 Tab | HomeOS shell | 不得增删、不得改顺序、不得注册原生 `tabBar` | CI 检查 `pages.json` 无 `tabBar` 字段（§2.4） |
| L2 面内二级 Tab | 该面 | 自定义数量与标题（17.3 财务面五个） | 只允许在该面分包内定义；末位不得命名「我的」 |
| L3 内容区 | 该面 | 任意 | 只调 `/api/{code}/*` + 显式声明的只读接口（17.7 第 4 条） |
| 主题令牌（贯穿所有区域） | HomeOS shell（主包出一份，亮/暗两套值） | 只引用令牌变量，不得写死色值、不得自建页面级主题 | 分包内出现硬编码色值即门禁 4 失败（17.9、18.2#10）；**灰阶第四级（浅于达标线的浅灰）只用于描边与占位图形，用它承载文字即走查失败**（17.9 对比度行） |

### 1.3 导航不变量（每条都可写成 CI 断言或集成用例）

1. **页面全部是独立路由**，一条路由 = 一个页面 = 一个职责 = 一个埋点 `page_path`（17.7 第 6 条）。
2. **不注册原生 `tabBar`**：一级五项由 shell 自定义组件承载；一级页之间**无栈互切**，二级页压栈、返回即出栈。
3. 切换面**不改变** D 行五项，也不清空其他面已压入的栈（面内栈各自保留）。
4. 任何面**不得**新增一级导航、自建消息中心、自建推送、自建全局搜索入口（17.7 第 1 条）。
5. 用户上次所在面在**会话内**保持；**会话起始与「返回上一级到底」都落在 `pages/homeos/home/index`**（⑫ 之后首页是唯一切面枢纽，17.1）。
6. **导航集合 = 本家庭已启用面 ∩ 服务已出生面**（17.8）：**首页矩阵、「＋」目标对象、搜索分组、到期中心注册项、动态流筛选**读同一个集合（⑫ 后由六处减为五处），该集合由 `GET /api/homeos/family/modules` 与首页聚合接口给出，前端不硬编码、不补齐、不占位。
7. **未挂载的面在客户端零请求、零分包下载**（18.2#9）：不建空分包、不给可点深链目标、不出现在任何列表里——「描边格 / 置灰位 / 即将上线占位」这一类导航位**在定版模型里已废除**。
8. **停用某面 = 入口消失 + 数据保留并继续参与统计**（17.8）：五个消费位同时消失、深链返回「未启用」，但该面的历史流水、动态流、跨面归集与对账数值**不变**。回归必须断言「停用前后同一时间窗的统计值逐值一致」。
9. 跨面跳转**只走深链** `homecube://{code}/{entity}/{id}`，分包之间不得互相 import（17.7 第 4 条）。
10. 全局「＋」是独立路由页 `pages/homeos/quick-add/index`，**取消即返回进入前的页面**，未提交草稿不落任何业务对象（17.4）。
11. 客户端只对一个 base URL，路由前缀 `/api/{code}/*` 与页面所属分包一一对应（17.7 第 5 条）。
12. 破坏性动作（删除、撤销、结清、恢复、退出家庭、解散家庭）**不占路由**，一律走统一确认弹层；空态是页面的一个状态，不是页面；列表内多选是列表页的操作态（17.7 第 7 条）。
13. 到期中心（日历/待办/提醒）**没有一级 Tab**（定版）：入口 = 首页 B 区 + 「我的 → 时间与提醒」，这是 D 行五项恒定换来的唯一代价。
14. 全局面（登录、创建/加入家庭、**选面引导**、PIN、＋、搜索、深链落地、错误页）都在主包，任何面的页面都不在全局面里被复制一份。
15. 面的前端代码**按需加载**：首次进入该面（或该面被本家庭启用）时按 `app/bundles` 清单拉取并校验；**校验失败、超时、版本不兼容都不进白屏**——该面转「暂不可用」态，基座与其他面照常可用（17.8、§6.11）。
16. **未读只有一个数**：顶栏消息入口的红点与 D 行「消息」的红点（含计数）读 shell store 里同一份 `unread`，来源只有 `home/summary`（首屏）与 `notifications`（列表与全部已读）两个出口，且两处返回的是服务端同一个聚合值（3.6）；**客户端不缓存第三份、不自行相减**，分包自建未读计数即门禁 4 失败（17.1）。**`unread` 与 C 区格子的 `badge` 是两个语义**（未读 vs 待处理），不得互相顶替。
17. **主题只有一份令牌**：亮/暗/跟随系统三态（17.9）由主包出一份 CSS 变量，分包只引用变量；切换主题**不改变路由、不丢页面栈、不清 `period`、不重新登录**（18.2#10 逐三项断言）。
18. **面入口全 App 只有一处**（定版 ⑫）：首页 C 区服务矩阵。顶栏中段为空，任何面不得在自己的页面里放「切到别的面」的控件、也不得放「开通更多面」的引导位——**分包内出现第二处面入口即门禁 4 失败**。面内切面**恒定 3 步**（返回该面一级页 → D 行「首页」→ 点目标格），这条步数进 18.2#9 的走查断言。
19. **时间窗只有三档**（定版 ⑬）：`YYYY-MM` / `YYYY-Qn` / `YYYY`，P1-M1 即全部开放；**首页也渲染时间窗条**。「按周」「全部」不在这份档位里，加一档必须同时改 4.5.3、18.3#9 与 `period` 校验，不得由某个分包先支持。

### 1.4 面入口的唯一性与五处同源断言

**⑫ 之后不存在「两处入口的分工」**——原「顶栏 chip 管位置感 + 首页矩阵管全景感」的两处并存模型已作废（12.1 ① 的后一半被 ⑫ 取代，前一半「顶栏一行制」仍然有效）。合并后：

| 入口 | 职责 | 呈现的信息 | 交互 |
|---|---|---|---|
| 首页 C 区面矩阵（17.2） | **同时承担位置感与全景感**：这个家开通了哪几面、每面今天要办什么 | 图标 + 面名 + **一句状态句** + 待处理角标 | 点击进入该面 `list` 页 |

「我现在在哪个面」的位置感改由**该面 L2 二级 Tab 栏**承载（⑫ 之后它兼作唯一的位置提示），代价是切面要走 3 步。

**同源断言**（写进契约测试，不只写进文档）：五处消费者都从「面目录 + 家庭面配置」派生，客户端只消费服务端算好的集合。

- **集合是变量，不是常量 6**：`faces[]` 只包含本家庭已启用且服务已出生的面——开通三面即三项，开通一面即一项。顺序恒为 registry 登记顺序。
- 服务端返回的面若本地尚无对应分包，走 §6.11 的按需加载；**加载失败时该格转「暂不可用」而不是从列表里偷偷删掉**——否则用户看到的集合会与服务端不一致。
- **五处同源**：矩阵、`+` 目标、搜索分组、到期中心注册项、动态流筛选在同一份 `faces[]` 上渲染，共用同一个 store 与同一个渲染函数。「一处可点而另一处不可点」这类分歧在结构上已不存在。
- 新增一个面在客户端只有三处变化：registry 条目变实、`pages/{code}` 分包出生、该家庭启用它之后 `faces[]` 多一项。**不改导航结构、不加新的代码分支**。

## 二、页面模型：独立路由

### 2.1 三段式命名（17.7 第 6 条）

| 对象 | 规则 | 示例 |
|---|---|---|
| 分包目录 | `pages/{code}/` | `pages/finance/` |
| 页面路由 | `pages/{code}/{feature}/{action}` | `pages/finance/tx/create` |
| `feature` | 该面的功能域，与服务端业务域**同义**（可为缩写，如 `tx` ↔ `finance_transaction`；对应关系记在深链映射表 §2.5，CI 据此校验不出现第三种叫法） | `tx` `account` `category` `budget` `ledger` `bill` `report` |
| `action` 封闭集 | 五个通用动词：`index`（该域主入口列表）/ `list`（同域的第二列表）/ `detail` / `create` / `edit` | `finance/tx/create` |
| 具名动作段 | 封闭清单：`login` `family-create` `family-join` `modules` `pin-set` `board` `invite` `permission` `security` `trash` `export` `archive` `sort` `settlement` | `homeos/auth/pin-set`、`homeos/family/modules`、`finance/tx/trash` |
| 页面标识（埋点 `page_path`） | 与路由同值，不另造 ID | `pages/homeos/home/index` |
| 深链 | `homecube://{code}/{entity}/{id}`，可选 `?from=` 仅作来源标记（不改三段主体，22.2 第 8 条） | `homecube://finance/transaction/0193…` |
| API 前缀 | `/api/{code}/*`（资源式路径，**不套用页面的三段式**） | `/api/finance/transactions`、`/api/homeos/home/summary` |
| 面内二级 Tab key | `{code}.tab.{n}` | `finance.tab.flow` |

**动作段是封闭表**：五个通用动词 + 上表的具名动作段，**且路径恒为三段，不得出现第四段**（`pages/finance/tx/detail/attachment` 这类写法在 CI 里失败）。新增具名动作段必须同时改本表与深链注册表，二者缺一在契约测试里失败——这是「全部独立路由」不滑向页面数失控的唯一约束。

页面标识 = 路由 = 埋点 `page_path` 三者同值，是为了让「某个页面有多少入口路径」这类问题在埋点里可直接回答，不必维护映射表（19.5）。

### 2.2 成页与成弹层的判定（17.7 第 7 条）

| 判定 | 对象 | 理由 |
|---|---|---|
| **成页** | `list` / `detail` / `create` / `edit` 各占一条路由 | 四类都有独立的输入/输出与返回预期，压栈语义符合用户直觉 |
| **成页（具名）** | `trash`（软删列表）、`export`（筛选与参数确认）、`archive`（归档与恢复视图）、`sort`（拖拽排序）、`settlement`（结算中心）、`modules`（面目录与开通，同页复用为创建引导） | 它们是「一类数据的浏览与操作」，不是对单个对象的一次动作 |
| **成弹层** | 删除、撤销、结清确认、恢复、停用、退出家庭、解散家庭、全部已读、批量改分类 | 破坏性/一次性确认，需要的是就地完成 + 影响说明 + 落审计，不需要页面栈 |
| **成弹层（面板）** | 家庭切换、账号切换、分享、图片预览、筛选条展开 | 就地改变上下文，不产生新职责 |
| **不成页也不成弹层** | 空态、加载中、失败、离线、无权限、暂不可用 | 是页面的状态（第八章同一组件库） |
| **不成页** | 列表内多选操作态、流水行的滑动/长按手势 | 是列表页的一个操作态 |

**明确的例外与代价**：家庭切换是面板不是页面（它改变整个会话上下文，做成路由页会让每次切换都压一条栈并在页面转换里重签发 token）；「＋」**是**页面（17.4 已定版，理由是要同时承载四种输入形态、目标对象选择器与识别预览）。这两条形态相反，判定依据都是「进入后是否产生一个独立职责」。

### 2.3 切换语义（不注册原生 tabBar 后的三条规则）

| 场景 | 语义 | 页面栈 |
|---|---|---|
| D 行五项之间、首页矩阵 → 某面 `list` 页 | **无栈互切**（`reLaunch` 类语义，由 shell 统一封装） | 每次切换后栈深恒为 1；各面的「上次所在页」由 shell 记录，回到该面时恢复到它的 `list` 页而非三层深的具体页。**⑫ 之后进入一个面的唯一路径就是这一条**：面内切面 = 返回该面 `list` → D 行「首页」→ 点目标格，恒定 3 步 |
| 一级页 → 面内二级页（`detail`/`create`/`edit`/具名页） | **压栈**（`navigateTo`） | 返回即出栈，回到进入它的那条路由 |
| ＋ → 目标对象 `create` → 保存成功 | 压栈进表单，保存后 **`redirectTo` 到该对象 `detail`** | 不出现「返回又看到空白表单」；失败则留在 `create` 页保留输入 |
| 登录成功 / 家庭切换 / 深链冷启动 | **重置栈**（无栈替换） | 栈为 `[目标面 list 页]` 或 `[目标 detail 页]`（深链场景栈底为该面 `list`） |

**页面内状态的归属**：跨页共享的状态（当前家庭、角色快照、时间窗 `period`、离线队列游标、免打扰）**一律由主包 shell 级 store 按 `(code, feature)` 或 `family_id` 持有**；分包不得持有跨路由的会话级状态，页面局部状态（表单草稿、筛选展开态）随页面销毁。这样无栈互切不会累积陈旧状态。

### 2.4 `pages.json` 形状（P1）

```jsonc
{
  "pages": [                                  // 主包：shell + HomeOS 全部页面
    { "path": "pages/homeos/home/index" },
    { "path": "pages/homeos/auth/login" },
    { "path": "pages/homeos/quick-add/index" }
    // …余下 HomeOS 页面见第四章
  ],
  "subPackages": [
    { "root": "pages/finance", "pages": [ /* 见第五章 */ ] }
    // P1 到此为止：purchase / diet / trip / kin / growth 五个 root 不得出现
  ]
  // 注意：本文件没有 "tabBar" 字段。一级导航由主包组件 components/shell/nav-bar 渲染，不是路由。
}
```

CI 对 `pages.json` 做三查（门禁 4 的前端项）：

1. **无 `tabBar` 字段**——出现即失败（原生 tabBar 会与 shell 的 D 行组件抢占，是 family-ledger 四反例之一（见 §11.3））。
2. **分包集合 = 已出生域**——`subPackages[].root` 必须与 registry 中「出生期 ≤ 当期」的域集合相等；**家庭未启用的面不另建分包、不做条件编译**（启用与否是运行时配置与按需下载，不是构建期裁剪）。
3. **每条路由都是三段式**——`pages/{code}/{feature}/{action}`，`{action}` ∈ §2.1 的封闭动作表、**无第四段**；同目录内不得出现两个页面承担同一动作。

三查只管 `pages.json` 的形状；**七条前端同源检查**扫的是分包源码，同属门禁 4 的前端项：分包内无切换家庭调用、无硬编码面清单、搜索只调 `/api/homeos/search`、无自造时间窗状态、**无硬编码色值**（17.9）、**无自建未读计数或消息入口**（17.1）、**无第二处面入口或自建面切换器**（17.1、⑫）。逐项落点见 §1.2 与 22.5 第 4 道。

### 2.5 深链落地映射

| 到达 | 结果 |
|---|---|
| 已出生面 + 有权 + 对象存在 | 该对象的 `detail` 页，栈为 `[该面 list 页, detail]` |
| 已出生面 + 无权 | 「无权限」态 + 返回该面 `list`，落审计（21.5） |
| 已出生面 + 对象已软删 | 「已删除」态 + 回收站入口（仅作者与管理员可见该入口） |
| 未出生面（P1 收到 `purchase`/`diet`/…） | 「即将上线」态页，不请求任何服务、不下载分包 |
| 家庭未启用的面 | 「未启用」态页；管理员另见「去开通」引导直达 `homeos/family/modules`，不下载分包（17.8） |
| 该面服务不可用 | 「暂不可用」态 + 最后一次投影值与时效标注（12.3） |
| 目标对象是 L3 | 先设备锁校验 + 会话内二次确认，再进 `detail`（17.6、20.2、3.4.8） |
| `entity` 未注册 | 「页面不存在」+ 埋点，不白屏 |

`entity` 取值域按面注册在 shell 的深链表里，P1 只登记两域：

- `homeos`：`event` `todo` `reminder` `notification` `dynamic` `member`
- `finance`：`transaction` `account` `category` `budget` `ledger` `bill` `recurring` ／ `②` `loan` `goal` `split` `invoice`

新增 `entity` 必须同时改深链表与该面的只读接口声明，二者缺一在契约测试里失败。

## 三、首页：家庭服务矩阵是主视觉（17.2）

### 3.1 时间窗条 + 四个区

| 区 | 内容 | 数据来源 | 期 |
|---|---|---|---|
| （区之上）时间窗条 | 「2026 年 9 月 ▾」+ 右侧**月 / 季 / 年**三档（⑬）。**首页也渲染**——C 区财务格的状态句读它，所以「时间窗条只在业务面出现」不成立；它属于顶栏之下、A 区之上的独立一条，不占顶栏 | shell 级 `period` store（§6.4） | ① |
| A 家庭区 | 左：问候语（「早上好，爸爸」，称谓 = `members[].relation`，缺值回落成员名，⑭）+ 家庭名；右：**头像排 = 前 3 个成员 + 虚线圈「+N」**（N = 未展出成员数，含无账号成员），**整排点击进 `homeos/family/index`**，「+N」**不是邀请入口**（⑮）。家庭切换动作在顶栏左侧 | `home/summary` 的 `family` 与 `family.members[]` | ① |
| B 今日区 | **跨整行大卡**：卡头「今日 N 项 · 到期与待办 · 日历 ›」+ 卡内**横向时间轴最多 3 张小卡**（时段 + 一句话，首个到期项加重）。`count` 是当日全量、`items[]` 只是前 3 条，两者不等不是 bug；点击进入 `homeos/calendar/index` | `home/summary` 的 `due_today` | ① |
| **C 家庭服务矩阵** | **已启用面宫格**（全 App 唯一面入口，⑫），标题行「已启用 N 面」+ 右侧**只允许不可点的纯文案**（设计注释不得画进产品）；**格子尺寸固定、高度由内容自然决定，不设首屏占比阈值**（原「占首屏高度 ≥45%」的分配口径已作废，17.2） | `home/summary` 的 `faces[]`（**集合 = 已启用 ∩ 已出生**） | ① |
| D 动态区 | 家庭动态流前 20 条 + 「查看全部」进 `homeos/dynamic/index`；条目 = **面图标（与 C 区同一套 registry 图标，不另建缩写方块）+ 发起人 + 动作句 + 对象摘要 + 相对时间**，跨面混排且不引入优先级 | `home/summary` 的 `dynamics` | ① |

**首屏只发一个请求**：`GET /api/homeos/home/summary`。四区不得并行打多个服务（17.2、17.7 第 4、5 条）；这条可以用抓包直接断言，是客户端侧最容易验收的一条。

### 3.2 变长宫格（面集合是变量）

| 已启用面数 | 排布 |
|---|---|
| 1~2 | 每行 2 格 |
| 3~4 | 2×2 |
| 5~6 | 2×3 |
| ≥7 | 每行 3 格继续换行（面目录扩展后的形态） |

- 顺序恒为 registry 登记顺序；**首页自身不进矩阵**（矩阵只列业务面，首页是承载它的那一页）。
- **排布形态 = 固定尺寸卡片 + 自然换行**（定版）：卡片宽高不随格数拉伸，1 面就是左上角一格、其余留白，5~6 面即 2×3 满行。**不设首屏占比阈值，「D 动态区落在几屏之外」不是缺陷也不进验收**——不得为撑满一屏而拉伸卡片高度，那会在单面家庭的首页中央造出大片空白。四区自上而下的顺序恒为 A→B→C→D，任何格数下都不重排。
- **格数不等于 6 不是缺陷**：一个只开通财务面的家庭，首页矩阵就是一格——这正是「家庭的面不是固定的、由管理员配置」在页面上的表现。一格时右半留白也是定版结果，不补占位。
- **矩阵是唯一能点到别的面的地方**（定版 ⑫）：顶栏不放面切换器，任何面的页面内也不放。自面内切面 = 返回该面 `list` → D 行「首页」→ 点目标格，恒定 3 步（§1.4）。
- 首页**不放**「开通更多面」的入口位（定版）：开通与停用统一在「我的 → 开通更多面」（§4.6）。

### 3.3 格子规格与两种状态

| 元素 | 规格 | 说明 |
|---|---|---|
| 图标 + 面名 | 恒渲染 | 来自 registry，**不硬编码** |
| 状态句 | `available` 时为今日状态一句话 | 服务端计算，客户端不做二次聚合或累加 |
| 角标 | 待处理数（`badge`），>0 才渲染；`badge` 上限显示 99+ | 与服务端同一计数口径；**`badge` 是「待处理」，与顶栏/D 行的「未读红点」是两个语义，不得共用字段**（17.1 第 3 条） |
| 时效标注 | `unavailable` 时显示「截至 HH:MM」 | 来自 `as_of`，不显示为实时值 |
| 卡片高度 | 由内容（图标 + 面名 + 状态句 + 角标）自然决定，**同一宫格内各行等高** | 不随格数拉伸、不设首屏占比阈值（§3.2） |

| 状态（`availability`） | 触发 | 呈现 | 可否进入 |
|---|---|---|---|
| `available` | 已启用 + 服务已出生 + 模块权限允许 | 实心格 + 状态句 + 角标 | 点击进入该面 `list` 页（首次进入走 §6.11 按需加载） |
| `unavailable` | 已启用，但该面服务不可达 / 分包下载或校验失败 | **与可用格同尺寸同结构**，仅按面去色 + 最后一次值 + 时效 + 「重试」动作位 | 进入后为该面不可用态，不白屏 |

**「重试」就是 17.2 定死的三件事**，客户端不得各自解释：① 重新请求一次 `home/summary`（**不是**单独打那个面的接口，首屏单请求原则不破）；② 若该格是因分包缺失或校验失败，同时重走一次 §6.11 的按需加载；③ 失败后保持原态与最后值，**不弹错误页、不清缓存**。重试是**读操作**，不进幂等键与离线队列，也不进 18.2 的任何分母。

**没有第三态**：未出生与未启用两种面**根本不出现在 `faces[]` 里**（原「同尺寸描边格」方案随 17.8 作废）；它们只在开通页可见，两态在那儿区分（§4.6）。

### 3.4 聚合接口形状（服务端要兑现的契约）

```jsonc
GET /api/homeos/home/summary?period=2026-09     // ⑬ 三档编码：YYYY-MM / 2026-Q3 / 2026；非法值 400，不回落
{
  "family": { "id": "0193…", "name": "示例家庭", "role": "owner",
              "currency": "CNY", "timezone": "Asia/Shanghai",
              "member_count": 5,                // 头像排「+N」的 N 由 len(members)-3 与本数取大，客户端不数已下载列表
              "members": [{ "id": "…", "name": "…", "avatar": "…",
                            "relation": "爸爸",  // ⑭ homeos.Member.relation，缺值则客户端回落 name
                            "has_account": true }] },
  "due_today": { "count": 5, "items": [          // count 为今日全量（B 区标题行显「今日 5 项」），items 恒 ≤3
    { "kind": "bill", "title": "房贷", "amount": "4200.00", "due_at": "…",
      "code": "finance", "entity": "bill", "id": "…" }
  ] },
  // 顶栏消息入口与 D 行「消息」的红点都取自这里；口径与 notifications 接口完全一致（3.6）
  "unread": { "total": 4, "by_type": { "budget_alert": 1, "system": 2, "reminder": 1 } },
  // 本家庭只开通了财务面：faces[] 只有一项。未启用与未出生的面不出现在这里。
  "faces": [
    { "code": "finance", "availability": "available",
      "headline": "预算剩余 ¥860", "badge": 2, "as_of": "2026-09-29T08:10:00+08:00" }
  ],
  "dynamics": { "cursor": "…", "items": [        // 前 20 条；服务端已按权限裁剪（§7.3）
    { "code": "finance", "actor_name": "妈妈", "action": "记了一笔",
      "summary": "餐饮 ¥128", "at": "2026-09-29T08:04:00+08:00",
      "entity": "transaction", "id": "0193…" }
  ] }
}
```

- `period` 来自 shell 级时间窗 store（§6.4），缺省为家庭时区的当前月；**三档在 P1-M1 全部开放（⑬）**。首页时间窗条与 C 区财务格的状态句读同一值，与流水/报表/预算四处同源（18.3#9）。
- `members[]` 是**全量成员**（含无账号被记录成员），A 区只画前 3 个头像 + 「+N」；`relation` 是 ⑭ 定版的称谓唯一源，**客户端不得为问候语另调 `kin` 的接口**。
- `due_today.items[]` 恒 ≤3 且按 `due_at` 升序，`count` 是全量——**两者不等是设计结果**，客户端不自行截断也不补第 4 条（17.2）。
- `dynamics.items[]` 的 `code` 同时决定条目左侧的**面图标**，与 C 区格子用同一套 registry 图标，**不另建第二套缩写符号**。
- `headline` 全部是**服务端产出的字符串或数字**，客户端只做格式化；18.3#9 明确要求「前端二次累加检查为 0」。
- P1 的 `finance.headline` 由 `svc-homeos` 的投影/聚合得出（16.3），**不是前端调 `/api/finance/*` 拼出来的**。
- `unread` 是**顶栏红点与 D 行红点（含计数）的唯一首屏数据源**：由服务端按 `homeos_notification.read_at IS NULL` 聚合 `member_id` 得出（3.6），与 `GET /api/homeos/notifications` 返回的是同一个数；**客户端拿到后写进 shell 的一份 store，两处渲染读它**（§1.3 第 16 条）。它挂在同一个聚合响应里，**首屏仍然只有一个请求**（§3.1）。
- `faces[]` 必须与 `GET /api/homeos/family/modules` 的启用集合一致；不一致时客户端以 `faces[]` 渲染并上报 `nav_set_mismatch` 埋点（键名以 19.5 埋点字典定版为准，本文先用此名占位），契约测试据此失败。

### 3.5 逐面状态句取值（出生期逐面定义）

| 面 | 出生期 | P1 呈现 | 该面出生后的状态句口径（本文预留，不实现） |
|---|---|---|---|
| 财务 | P1 | 实心格：当前时间窗的预算剩余 / 待缴账单数（取其一为主句 + `badge`）；**切到季/年且只有月度预算时显「未设该周期预算」，不得折算**（⑬ 红线，§6.4） | 预算剩余（周期归零口径，18.3#4） |
| 采购 | P2 | **不在首页出现**（未出生），开通页显示「即将上线」 | 待买 N 件 / 库存告急 N 项 |
| 饮食 | P3 | 同上 | 今晚菜单一句话 |
| 出行 | P6 | 同上 | 明日 HH:MM 接送 |
| 家人 | P4 | 同上 | 作业 N 项 / 轮值今天是谁 |
| 成长 | P5 | 同上 | 最近一条里程碑（身高/体重/作品） |

P1 末的首页验收是**「矩阵格数 = 本家庭已启用面数，且未挂载面零请求、零下载」**（14.5 第 8 项、18.2#9），不是「一张财务摘要卡」，也不再是「六格恒在」。

### 3.6 性能口径

`home/summary` 是单个请求，其延迟按 21.1 的通用接口基线与 18.2 的人体验收判定，**本文不另立阈值**。首页不做「按面并行打多服务」的优化，因为那会直接违反 17.7 第 4 条；跨面聚合的唯一正解是服务端聚合或投影（16.3）。

### 4.3 消息（3 页）

## 六、关键交互流与步数预算

### 6.1 「步」的计数口径（写进验收，避免争论）

一步 = 一次用户主动**点击/确认**；数字键盘输入不计步（18.3#1 原文口径）；一次表单内多字段填写若用同一个面板，计 1 步；系统自动渲染与请求不计。**进入 `quick-add` 路由页算 1 步**（点底部 ＋ 那一下）。

**切面步数（定版 ⑫ 换来的唯一代价，写进验收）**：自任一**面内**页面切到另一个面 = ① 返回该面一级页（或点 D 行）→ ② 点 D 行「首页」→ ③ 点首页矩阵的目标格 = **恒定 3 步**，与家庭开通几个面、面名长短都无关。自**首页**切面是 1 步（点一格）。这条与 4.9 的「记账 ≤3 步」并列进 18.2#9 走查，实测超过 3 步即判失败。

### 6.2 记账的四条路径（都 ≤3 步、≤5 秒端到端）

| 路径 | 步骤 | 失败降级 |
|---|---|---|
| 全局 ＋ | ① 点 D 行 ＋（进 `quick-add/index`） → ② 选「记账」并输入金额+分类（同一面板一次完成） → ③ 保存 | 无依赖，恒可用 |
| 面内悬浮记一笔 | ① 在 `flow/index` 点悬浮按钮（直达 `tx/create`） → ② 输入金额+分类 → ③ 保存 | 2-3 步，比全局 ＋ 少一次目标选择 |
| 小票 OCR | ① ＋ → ② 拍照/选图 → ③ 在 `tx/create` 确认识别结果（逐字段可改） | 识别失败即回落到同一 `tx/create` 手输，**不新增步骤**、不弹错误页 |
| 语音 | ① ＋ → ② 按住说话 → ③ 确认 | ASR 不可用回落手输 |

保存后 5 秒内流水首行可见（本地乐观插入 + 服务端回执校正，冲突走 §6.5）；`redirectTo` 到 `tx/detail`（§2.3）。

### 6.3 全局「＋」页内动作（≤2 步选到目标对象）

```
进入 pages/homeos/quick-add/index
① 输入内容（文字 / 按住说话 / 拍照 / 选模板 四选一，同一面板）
② 选目标对象：只列**本家庭已挂载**（已启用 ∩ 已出生）且当前有权的对象

```

- **无权限项与未挂载面的对象都不显示**，不置灰（17.4、17.8）；一个可建对象都没有时显示「当前家庭未开放任何可创建对象」，管理员在此见「去开通更多面」引导。
- 文字输入进的是「快速捕获」，P6 由 AI 归类分流；P1-P5 草稿只落 HomeOS `Todo`（显式点「存为待办」），**未提交草稿不落任何业务对象**。
- 取消（返回手势或 ✕）= 回到进入前的路由，不产生页面记录。

### 6.4 时间窗条：三档 · 四处同源（18.3#9、定版 ⑬）

- `period` 是 **shell 级状态**（主包 store，按 `family_id` 隔离），**首页与财务面都渲染时间窗条**——首页 C 区财务格的状态句读它，所以「只有业务面才有这条」的旧写法不成立。
- **三档编码定版（⑬）**：`YYYY-MM`（月）/ `YYYY-Qn`（季，`2026-Q3`）/ `YYYY`（年）。**P1-M1 三档全部开放**，不分批；`Qn` 恒为 `Q1`~`Q4`，季的首月为 01/04/07/10。**非法编码服务端返回 400 且不回落为当前月**，客户端据此上报而非静默改参——"周""全部"不在这份档位里（§1.3 第 19 条）。
- 切换 `period` 后：首页 `home/summary?period=`、`GET /api/finance/transactions`、`reports/*`、`budgets` 四个请求都带同一参数，服务端返回什么就显示什么。**四处一致是 18.3#9 的判定项**。
- **环比的上期随粒度**：月比上月、季比上季、年比去年；**环比 =（本期 − 上期）/ 上期，上期为空显示「无对比期」，不得除零**；累计余额取服务端逐期累加值（18.3#9 要求抽样 30 格逐值一致、前端二次累加检查为 0）。
- **红线（⑬）**：粒度是查询参数，预算周期是对象。切到季/年而本家庭只有**月度预算**时，**不得把月度预算乘 3 或乘 12 折算出「预算剩余」**——那是造数。该情形状态句与预算页一律显「未设该周期预算」，并给出「切回月度」的引导；分类预算与固定预算同一处理。
- **时间窗档位 ≠ 列表分组维度**：流水页的分组小标题（按日/按月）是列表自己的呈现参数，不随 `period` 变，也不写回 `period`。
- 切换家庭时 `period` 重置为新家庭的当前月（§6.8）；切换主题不清 `period`（§1.3 第 17 条）。

### 6.5 乐观锁 409 的处置流（金额型不接受静默覆盖）

```
写 → 409 → 「内容有变动」弹层（双版本并排：我的 / 服务端最新）
   → 选「用我的」→ 带新 version 重发一次（仍冲突则再弹，不循环超过 2 次）
   → 选「用最新」→ 丢弃我的改动并重拉
   → 选「手动合并」→ 留在当前 edit 页，字段级标红差异
```

弹层文案不出现「覆盖」字样，避免用户误读为无代价；每次 409 计入 `sync_conflict` 埋点与 21.5 冲突指标。

### 6.6 离线写与重放

- 写请求进 `pending_ops`（按 `(family_id, service)` 分桶），行右上显示「待同步」标记；跨桶不互相阻塞。
- 触发重放：网络恢复 / 前后台切换 / 定时三处（p1-tech-plan 第五章）。
- 离线态禁用四类入口（家庭切换、邀请、权限修改、AI 录入），**在 shell 层统一禁用**，各面不各自判断（21.6）。
- 重放冲突走 §6.5；被拒绝的写不静默丢弃，队列里保留可展开的失败项。

### 6.7 提醒 → 深链 → 完成回写（跨服务闭环）

```
到点（svc-homeos 扫描触发）→ 站内信（type=reminder）+ 推送
→ 点击 → homecube://finance/bill/{id} → finance/bill/detail
→ 「标记已缴」（弹层）→ 本服务写 → 发 finance.bill.paid
→ svc-homeos 消费置完成 → 日历与待办同步消失（收敛 P95 ≤5s）
```

UI 口径：点「标记已缴」后本地即置已缴态并显示「同步中」，**不等待跨服务确认**；5 秒后仍未收敛则显示时效提示而非报错。通知列表项按 `type` 显示分型图标与文案前缀，未读红点在**顶栏消息入口（只显点）与 D 行「消息」（显点 + 计数）两处同源聚合**，两处同时熄灭（17.1）。

### 6.8 家庭切换（≤1 秒上下文重建）

顶栏 → 切换面板 → 选家庭 → token 重签发 → shell 广播「上下文已换」→ **无栈替换**到新家庭的 `homeos/home/index` → 各面丢弃缓存重拉。切换期间显示骨架；`pending_ops` 的分桶游标、时间窗 `period`、权限缓存与**面集合（五个消费位，§1.4）**同时按新 `family_id` 重置。禁止残留上一家庭的任何数据渲染（跨家庭串数据是阻断级缺陷，3.4.1）。

### 6.9 L3 对象与设备锁（3.4.8、20.2）

```
进入 L3 字段对象（含深链）→ 设备锁校验（PIN 散列本地比对，不出端）
→ 会话内二次确认（「将显示敏感信息」，30 秒内免重复）→ detail 页
→ 忘记 PIN → 手机号验证码重验 → 重设 PIN（`homeos/auth/pin-set`）
```

L3 内容不进推送正文、不进默认导出；校验失败只回到进入前路由，不显示任何数据片段。

### 6.10 停用与归档的可感知路径（4.5.9、18.3#10）

| 动作 | 页面 | 客户端断言 |
|---|---|---|
| 停用分类 | `category/edit` → 停用弹层 | 记账选择器与筛选 chips **立即无该项**；历史流水仍可在 `flow/index` 筛出并统计 |
| 排序分类 | `category/sort` | 三处（选择器/图例/chips）顺序一致；拖拽保存带 `version` |
| 归档账户 | `account/archive` | 归档后不在默认账户位与账户汇总；历史流水与净资产不变 |

| 恢复 | 对应弹层 | 恢复后选择器与汇总重新出现该项 |


### 6.11 面开通 · 停用 · 按需加载（17.8、18.2#9）

```
引导态（新家庭创建）：auth/family-create 提交 → redirectTo family/modules（引导态）
  → 至少勾选 1 个面 → 确认 → 家庭创建完成，无栈替换进 home/index（矩阵即所选集合）

管理员开通：me/index → family/modules → 开关置为「启用」（带 version）
  → PUT /api/homeos/family/modules → 服务端落审计 + pver+1 + 发 homeos.family.module.updated
  → 客户端收到变更（下一次 `family/modules` 或 `home/summary` 即体现，≤2 秒内主动刷一次）
  → 首页矩阵多一格（新格加载骨架，非占位入口）+ 其余四个消费位同步出现 → 用户点进去才拉分包

分包加载：读 app/bundles 清单 → 比对本地 (code, version) → 需要则下载
  → sha256 校验 + min_compat 比对 → 通过后挂载该面路由并进入它的列表页（动作段 `index`）
  → 失败/超时/不兼容：该面转「暂不可用」态 + 「重试」，**基座与其他面照常可用，不进白屏**

停用：开关置为「停用」→ 破坏性确认弹层（说明「入口消失、数据保留并继续参与统计」，理由选填）
  → 若这是本家庭最后一个已启用面：服务端拒绝，弹层内提示「至少保留一个面」，开关回位（17.8 第 4 条）
  → 首页格子与其余四个消费位同时消失 → 该面缓存分包标记可淘汰 → 该面接口零请求
```

| 断言 | 判据 |
|---|---|
| 生效时限 | 开通/停用 → 导航更新 P95 ≤2s、P99 ≤5s（18.2#9①） |
| 零请求零下载 | 整个会话抓包里，未启用与未出生面的 `/api/{code}/*` 请求数与分包下载数恒为 0（18.2#9③） |
| **停用不动数据** | 同一 `period` 下，首页格子 / 流水合计 / 报表四视图 / 预算剩余共 **12 组数值**在停用前后逐值比对，**再乘 3 个跨期家庭样本 = 36 组，容差 0**；重新启用后立即可见历史数据、无需补算（17.8 第 2、3 条） |
| **停用有下限** | 只剩最后一个已启用面时停用被拒（8 次负样本全拒并提示），客户端不存在 0 面首页态（17.8 第 4 条） |
| 加载失败降级 | 三种构造样本（校验失败 / 超时 / 版本不兼容）下该面为「暂不可用」，其他面与首页不受影响 |
| 引导不可跳过 | 新家庭创建时未经选面不得进入首页；一个面都不选时「确认」不可用并给出原因文案（17.8） |
| 分包不越界 | 未挂载面在抓包里既无接口请求也无分包下载；已挂载面的分包只在**首次进入该面时**下载一次，二次进入命中缓存零下载（`(code, version)` 键） |
| **面入口只有一处** | 全 App 走查（含各面每一页滚动到底）除首页矩阵外**找不到第二个可切到别的面控件**；开通/停用一个面后首页格数与其余四处同步、无需重启客户端（⑫，门禁 4 第七条） |

## 七、权限对渲染的作用

| 权限层 | 作用点 | 客户端表现 |
|---|---|---|
| scope=module（本家庭未启用 / 未出生） | 首页矩阵格子、深链、＋ 的目标对象、搜索分组、到期中心注册项、动态流筛选 | **入口整体消失**（不置灰、不描边、不占位）；深链返回「未启用」态；该面零请求零下载 |
| 角色默认矩阵（15.3） | 每个页面的写入口 | `create/update/delete/export/invite/admin` 缺失 → 对应按钮**不渲染**（不是置灰） |
| data 范围（全家庭/本账本/本人/指定成员） | 列表行与详情 | 读不到的行不出现；他人流水行显示只读态（无编辑手势） |
| 对象级 ACL / 私密行 | 流水行、附件 | 非作者非管理员：整行不在结果里（行级可见性在 SQL 层，客户端不做二次过滤） |
| 字段级可见性（15.4） | DTO | 服务端不下发即不渲染，客户端不判断字段权限（p1-tech-plan 4.2） |
| condition=时间窗（访客有效期） | 全局 | 到期即下次请求被拒 → 跳「访问已过期」 |
| `pver` | 一切缓存 | 客户端权限缓存 TTL 60 秒 + 收到 `homeos.permission.updated` 立即失效，下一次请求即新表现（15.6） |

**角色在 P1 的可见面（逐行对应 15.3 的五列，即 18.2 逐格断言的「5 角色」）**

| 角色 | D 行可用 | 首页矩阵可见格 | 财务写 | 财务读 | 导出 | 我的 → 家庭/权限/设置 |
|---|---|---|---|---|---|---|
| 管理员（Owner） | 五项全 | 财务 | 全部动作 | 全部 | ✔ | ✔ 可写 |
| 成人成员（Member） | 五项全 | 财务 | 本人 M（他人流水无编辑手势） | 全家庭 R | 需授权，只导可读行 | 只读成员列表；设置与隐私仅本人项可写 |
| 儿童（有账号） | 首页 / 动态 / 消息 | **无财务格**（该面对儿童不存在） | — | — | — | — |
| 儿童/老人（无账号） | 不登录，无入口 | — | 由代管人携带 `on_behalf_of` 写入 | — | — | — |
| 访客（Guest，有效期内） | 首页 / 动态 / 消息 | **无财务格** | — | — | — | — |

- 15.3 的 HomeOS 行只授予成人成员「成员/权限/设置」的读取，儿童与访客为 `—`：这两类角色的「我的」Tab 只保留通知与时间对象，家庭管理、权限、设置三组入口**整组不渲染**（不是点进去报错）。
- ⑫ 之后**只剩一处面入口**，因此「角色 × 面」的渲染判定只有一条：无 `scope=module` 权限 → 首页矩阵不出该格 → 该面对这个角色在客户端**完全不存在**（深链落地为「未启用/无权限」态，下载不到也用不上）。这与「本家庭未启用该面」是同一条渲染路径——差别只在角色行 vs 家庭行。
- 无账号成员**没有登录入口**，只在成员管理里作为被记录对象存在（3.4.1）。

## 八、全局状态与异常态（一套，各面复用）

| 态 | 触发 | 呈现 | 组件 |
|---|---|---|---|
| 即将上线 / 未启用 | **只出现在开通页与深链落地**，不出现在导航与首页（17.8） | 图标 + 「即将上线」/「本家庭未开通」+（管理员）「去开通」引导 + 返回 | `hc-state-disabled` |
| 暂不可用 | 该面服务不可达 | 该面入口不可用态 + 投影最后值与时效戳（12.3） | `hc-state-offline-service` |
| 无权限 | 判定拒绝 | 「无权访问」+ 返回，**不显示任何数据片段** | `hc-state-denied` |
| 空 | 有权且请求成功但零结果 | 引导动作（去记一笔 / 邀请成员），不写「暂无数据」了事 | `hc-state-empty` |
| 加载中 | 首屏 | 骨架屏，不用 spinner 遮内容 | `hc-skeleton` |
| 失败 | 非 2xx、网络 | 可重试 + 错误码可见（用于对账与客服），文案不带堆栈 | `hc-state-error` |
| 离线 | 无网 | 顶栏常驻细条 + 「N 项待同步」 | shell 层 |
| 冲突 | 409 | 见 §6.5 | `hc-conflict-sheet` |
| 待解锁 | L3 对象、设备锁开启 | PIN 输入 + 忘记口令入口 | `hc-state-locked` |

规则：**同一态位在七面用同一组件与同一文案库**（HomeOS 主包提供），避免各面自造「空空如也」；图标统一图标集，`check-no-emoji` 拦 emoji 回流（14.7）。空态、加载态、错误态**都不是路由**（§2.2）。**九个态在亮/暗两态下是同一组件、同一文案，只有主题令牌值不同**（17.9）——两态逐屏走查与对比度判定见 18.2#10，分包内写死色值即门禁 4 失败。
