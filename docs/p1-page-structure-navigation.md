# 家立方 HomeCube · 页面结构与导航框架（P1 落地口径）

> **文档性质**：客户端信息架构规格，是研发交付物。需求权威源是 `docs/prd-homecube.md` 十七章（六面导航与信息架构）、11.3 第 ⑧ 项、14.5 第 8 项；跨服务口径见 `docs/p1-tech-plan.md` 第九章。本文只回答「这些条款在页面上长成什么样、跳来跳去怎么走」，**不新增需求、不裁剪口径**。
>
> **范围**：页面清单、路由与分包、导航层级、跨页跳转、步数预算、权限对渲染的作用、全局状态与异常态、深链与投影卡片的落地规则。
>
> **不含**：视觉规范（色板、字号、栅格、图标集清单）、组件库 API、动效。这些另出 UI 规格，且**不得与本文的层级结论冲突**。
>
> **期次标记**：`①` = P1-M1 交付并可验收；`②` = P1-M2 交付；`③` = 后续出生期（本文只预留挂载位，不设计页面）；`—` = 全期不做。

## 一、导航骨架

### 1.1 三层结构（全 App 唯一）

```
┌──────────────────────────────────────────────────────┐
│ L1 顶栏 A 行（HomeOS 拥有）  [家庭切换器]      [搜索]  │  ← 固定，切面不消失
├──────────────────────────────────────────────────────┤
│ L1 顶栏 B 行（HomeOS 拥有）  ⌂ 财务 采购 饮食 出行 家人 成长 →│  ← 六面横向切换器，可横滑
├──────────────────────────────────────────────────────┤
│ L2 面内二级 Tab（各面拥有，在内容区内，不叠加底部栏）    │
│   财务：流水 / 报表 / 预算 / 账本 / 我的                │
├──────────────────────────────────────────────────────┤
│                                                      │
│                  L3 内容区（页面栈）                   │
│                                                      │
├──────────────────────────────────────────────────────┤
│ L1 底部 Tab（HomeOS 拥有）首页  动态  ＋  消息  我的    │  ← 恒定五项，切面不改变
└──────────────────────────────────────────────────────┘
```

- **B 行的 `⌂` 是「首页」位**（chip 序列 `⌂ 财务 采购 饮食 出行 家人 成长`，顺序固定，17.1）；点 `⌂` 时 A 行与底部 Tab 都不变，只是内容区换成 HomeOS 首页。
- **一级导航（A 行 + B 行 + 底部五项）全部由 HomeOS 的 shell 组件提供**，业务面只消费、不实现（17.7 第 3 条、2.3 第 4 条）。
- **L2 是面内导航**，形态为内容区顶部的横向 Tab；二级 Tab 之下不再有第三层常驻栏。

### 1.2 区域所有权

| 区域 | 拥有方 | 业务面可以做什么 | 校验点 |
|---|---|---|---|
| A 行家庭切换器 | HomeOS shell | 只读当前 `fid`/角色/币种/时区，不得替换 | 分包内出现切换家庭的调用即门禁 4 失败 |
| B 行六面切换器 | HomeOS shell | 声明 chip 图标与标题（registry 域表提供） | `pages.json` 与 registry 对账 |
| 底部五项 Tab | HomeOS shell | 不得增删、不得改顺序 | 同上 |
| L2 面内二级 Tab | 该面 | 自定义数量与标题（17.3 表内五个） | 只允许在该面分包内定义 |
| L3 内容区 | 该面 | 任意 | 只调 `/api/{code}/*` + 显式声明的只读接口（17.7 第 4 条） |

### 1.3 导航不变量（每条都可写成 CI 断言或集成用例）

1. 切换六面**不改变**底部 Tab，也不清空 HomeOS 的 Tab 栈（面内栈各自保留）。
2. 任何面**不得**新增一级导航、自建消息中心、自建推送、自建全局搜索入口（17.7 第 1 条）。
3. 用户上次所在面在**会话内**保持；`⌂` 是会话起始默认位（17.1）。
4. 未出生面的 chip 显示为「即将上线」占位，**不可点击、不建空分包**（11.3 第 ⑧ 项、17.7 第 2 条）。
5. 家庭在 `feature_flags` 里关闭某面（module scope 显式拒绝）→ 该 chip **消失**，深链返回「未启用」页。
6. 跨面跳转**只走深链** `homecube://{code}/{entity}/{id}`，分包之间不得互相 import（17.7 第 4 条）。
7. 全局「＋」是覆盖层，不是路由页：不进入 Tab 栈、不产生页面记录，取消即回到原位置。
8. 客户端只对一个 base URL，路由前缀 `/api/{code}/*` 与页面所属分包一一对应（17.7 第 5 条）。
9. 到期中心（日历/待办/提醒）**没有一级 Tab**，入口是首页摘要位 + 「我的 → 时间与提醒」；这是底部五项恒定换来的唯一代价（见第十章分叉④）。
10. 所有全局面（登录、切换家庭、＋、搜索、深链落地、错误页）都在主包，任何面的页面都不在全局面里被复制一份。

## 二、路由与分包

### 2.1 命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 分包目录 | `pages/{code}/` | `pages/finance/` |
| 页面路由 | `pages/{code}/{module}/{page}` | `pages/finance/tx/form` |
| 页面标识（埋点 `page_path`） | 与路由同值，不另造 ID | `pages/homeos/home/index` |
| 深链 | `homecube://{code}/{entity}/{id}[?from=…]` | `homecube://finance/transaction/0193…` |
| API 前缀 | `/api/{code}/{module}/{action}` | `/api/finance/transactions` |
| 面内二级 Tab key | `{code}.tab.{n}` | `finance.tab.flow` |

页面标识 = 路由 = 埋点 `page_path` 三者同值，是为了让「某个页面有多少入口路径」这类问题在埋点里可直接回答，不必维护映射表（19.5）。

### 2.2 P1 实际 `pages.json` 形状

```jsonc
{
  "pages": [                                  // 主包：shell + HomeOS
    { "path": "pages/homeos/auth/login" },
    { "path": "pages/homeos/home/index" },
    { "path": "pages/homeos/dynamic/index" },
    { "path": "pages/homeos/message/index" },
    { "path": "pages/homeos/me/index" }
    // …余下 HomeOS 页面见 3.x 清单
  ],
  "subPackages": [
    { "root": "pages/finance", "pages": [ /* 见 4.2 清单 */ } ] }
    // P1 到此为止：purchase/diet/trip/kin/growth 五个 root 不得出现
  ],
  "tabBar": { "custom": true, "list": [
    { "pagePath": "pages/homeos/home/index" },
    { "pagePath": "pages/homeos/dynamic/index" },
    { "pagePath": "pages/homeos/message/index" },
    { "pagePath": "pages/homeos/me/index" }
  ] }                                         // ＋ 不是 pagePath，见 1.3 第 7 条
}
```

**目标形态**（P6 末）：`subPackages` 六条，每条对应一个已出生面；`pages.json` 由 CI 与 `registry.Domains()` + 出生期配置对账，出现未出生面的 root 即门禁 4 失败。

### 2.3 深链落地映射

| 到达 | 结果 |
|---|---|
| 已出生面 + 有权 + 对象存在 | 目标页，栈为 `[该面 chip 对应首页, 目标页]` |
| 已出生面 + 无权 | 「无权限」态页 + 返回该面首页，落审计（21.5） |
| 已出生面 + 对象已软删 | 「已删除」态 + 回收站入口（仅作者与管理员可见该入口） |
| 未出生面（P1 收到 `purchase`/`diet`/… ） | 「即将上线」态页，不请求任何服务 |
| 家庭已关闭该面 | 「未启用」态页（17.7 第 2 条） |
| 该面服务不可用 | 「暂不可用」态 + 最后一次投影值与时效标注（12.3） |
| 目标对象是 L3 | 先走会话内二次确认，再进页面（17.6、20.2） |
| `entity` 未注册 | 「页面不存在」+ 埋点，不白屏 |

`entity` 取值域按面注册在 shell 的深链表里，P1 只登记两域：

- `homeos`：`event` `todo` `reminder` `notification` `dynamic` `member`
- `finance`：`transaction` `account` `category` `budget` `ledger` `bill` ／ `②` `loan` `goal` `split` `invoice`

新增 `entity` 必须同时改深链表与该面的只读接口声明，二者缺一在契约测试里失败。

## 三、主包页面清单（HomeOS，22 个路由位 / P1 实建 21）

> 同 4.2 的口径：本章接口列写的是页面所需能力。17.2 已确立「首页摘要聚合走 `svc-homeos` 的聚合接口」，3.7 已列出 families/members/permissions/reminders/todos/notifications/search/settings/calendar/votes/dead-letters；其余（验证码与 token、邀请接受、动态流、聚合摘要、提醒与待办的查询）在 `svc-homeos` 契约设计时补齐，不属新增需求。

### 3.1 进入与家庭（4 项，其中 1 项为覆盖层）

| 期 | 路由 | 页面 | 进入方式 | 依赖接口 |
|---|---|---|---|---|
| ① | `homeos/auth/login` | 手机号 + 验证码登录 | 冷启动无 token / token 过期且 refresh 失效 | `POST /api/homeos/auth/code`、`POST /api/homeos/auth/token`、`POST /api/homeos/auth/refresh` |
| ① | `homeos/auth/family-create` | 创建家庭（名称/时区/币种/头像） | 登录后无家庭 | `POST /api/homeos/families` |
| ① | `homeos/auth/family-join` | 加入家庭（邀请码 / 链接 / 二维码三态合一页） | 邀请链接冷启动直达、或手动输码 | `POST /api/homeos/invitations/accept` |
| ① | `homeos/family/switch`（覆盖层） | 家庭切换面板（≤5 个家庭、当前位标记） | A 行点击 | `GET /api/homeos/families`、`POST /api/homeos/families/switch` |

### 3.2 首页与动态（2 页）

| 期 | 路由 | 页面 | 内容自上而下 | 数据来源 |
|---|---|---|---|---|
| ① | `homeos/home/index` | 首页 | 成员头像排 → 今日到期摘要 → **出生面卡片摘要位（P1 只有一张财务卡）** → 动态流前 20 条 | `GET /api/homeos/home/summary`（聚合口，含投影）；**不在前端并行打多服务** |
| ① | `homeos/dynamic/index` | 动态流 | 按天分组、按面筛选、游标分页 | `GET /api/homeos/dynamics` |

首页财务卡的定版内容（一句话 + 三个数字，点击进 `finance` 深链）：本月支出 / 预算剩余 / 最近待缴账单；卡片是**投影与聚合口**的产物，不直接查 `svc-finance`（17.2、17.7 第 4 条）。

### 3.3 消息（3 页）

| 期 | 路由 | 页面 | 说明 |
|---|---|---|---|
| ① | `homeos/message/index` | 站内通知列表（含 @、免打扰、分组、全部已读） | **推送的唯一 App 内落点**（17.5），各面无独立消息中心 |
| ① | `homeos/message/board` | 家庭留言板 | 3.4.3；评论写入经事件，不由业务面直写 |
| ③(P3/P4) | `homeos/message/vote` | 投票详情与投票动作 | P1 只建 `Vote` 对象与接口，**不出创建入口**（消费方是饮食点菜 P3、家人轮值 P4） |

### 3.4 时间（4 页）

| 期 | 路由 | 页面 | 说明 |
|---|---|---|---|
| ① | `homeos/calendar/index` | 到期中心，日/周/月三视图切换 | 聚合**已出生服务**的注册项（P1 = homeos + finance），未注册对象不出现 |
| ① | `homeos/calendar/event` | 事件详情 + 「前往源对象」深链 | `source_system`/`source_id` 决定跳转；源面不可用则只显示摘要 |
| ① | `homeos/todo/index` | 待办（创建/分配/完成/归档/子任务） | 完成回写走 `homeos.todo.completed`（16.4），UI 不等待回写结果 |
| ① | `homeos/reminder/index` | 提醒列表与周期规则 | 位置提醒在 P6 前只有手动地点，文案明示不保证触达（3.4.2） |

### 3.5 搜索（1 页）

| 期 | 路由 | 页面 | 说明 |
|---|---|---|---|
| ① | `homeos/search/index` | 搜索输入 + 结果按面分组 | 只调 `GET /api/homeos/search` 一个接口（17.6）；未出生域不出现在分组里，而非返回空组；L3 不进索引 |

### 3.6 我的（9 页）

| 期 | 路由 | 页面 | 权限前提 |
|---|---|---|---|
| ① | `homeos/me/index` | 我的首页（账号 / 家庭 / 设置 / 数据 / 隐私 / 时间与提醒 / 帮助 七组入口） | 全角色 |
| ① | `homeos/me/family` | 成员管理（列表、编辑、移除、转让管理员） | 管理员可写，其余只读成员列表（15.3） |
| ① | `homeos/me/family/invite` | 邀请（三态生成 + 有效期 + 撤销） | `invite` 动作，管理员 |
| ① | `homeos/me/family/member` | 成员详情（角色、模块开关、数据范围、代管关系） | 管理员 |
| ① | `homeos/me/family/permission` | 权限设置（模块级开关 + 家庭级覆盖，含矩阵只读视图） | 管理员；变更后 `pver+1` |
| ① | `homeos/me/settings` | 设置（主题/时区/币种/日期格式/语言/免打扰） | 本人偏好可写；家庭级需管理员 |
| ① | `homeos/me/privacy` | 隐私（L2/L3 可见性开关、私密流水行级开关、删除与导出请求） | 家庭开关仅管理员；紧急卡开关 `③(P4)` 才出 UI |
| ① | `homeos/me/data` | 数据（导出、备份状态与恢复入口、跨设备迁移） | `export` 动作 |
| ① | `homeos/me/about` | 帮助与关于（隐私政策 / 用户协议 / 版本号） | 政策文本页 **② 到 P1 末门禁** 才上线，M1 期间入口存在但显示「待定版」 |

> 页面数账法：3.1(4)+3.2(2)+3.3(3)+3.4(4)+3.5(1)+3.6(9)=23 项，其中 `homeos/family/switch` 是覆盖层不占路由，**路由位 22**；`homeos/message/vote` 随 P3/P4 出生，**P1 实建 21**。

## 四、财务面页面清单（`pages/finance`，M1 16 页 / M2 +8 页）

### 4.1 二级 Tab

| Tab | 落地页 | 形态 | 期 |
|---|---|---|---|
| 流水 | `finance/flow/index` | 按日分组列表 + 筛选条 + 悬浮记一笔 | ① |
| 报表 | `finance/report/index` | 概览/趋势/分类/成员四视图 + 下钻 | ① |
| 预算 | `finance/budget/index` | 进度环 + 分类预算行 + 超支标记 | ① |
| 账本 | `finance/ledger/index` | 分组卡片（报表归集范围，非隔离域，4.5.1） | ① |
| 我的 | `finance/mine/index` | 面内设置：账户 / 分类 / 提醒阈值 / 附件限额 | ① |

面内「我的」只管**本面对象的维护**，账号/家庭/权限/导出一律在 HomeOS 的「我的」，两处不互相复制入口（这是 17.3 与 17.5 的边界，见第十章分叉②）。

### 4.2 M1 页面（16 页）

> 接口列写的是页面**所需能力**，不是接口清单：以 `svc-finance` 的 OpenAPI 为准。PRD 4.8 已列出 transactions / accounts / budgets / reports / ledgers / settlements / loans / goals / attachments；表中 `categories`、`bills`、`settings` 的读写由 4.5 与 4.7 的对象存在性推出，属契约设计时补齐的实现细节，不构成新增需求。

| 路由 | 页面 | 关键交互与约束 | 依赖接口 |
|---|---|---|---|
| `finance/flow/index` | 流水 | 日分组、游标分页、滑动改单笔、长按批量、顶部筛选（时间/分类/账户/成员/标签/账本） | `GET /api/finance/transactions` |
| `finance/tx/form` | 记账 / 编辑（同页双态） | ≤3 步口径的实现体；金额以「分」存、显示按家庭币种；带 `client_request_id` | `POST/PUT /api/finance/transactions` |
| `finance/tx/detail` | 单笔详情 | 附件预览（≤3 张、≤5MB、jpg/png/webp）、`version` 冲突提示入口 | `GET /api/finance/transactions/{id}`、`…/attachments` |
| `finance/tx/trash` | 回收站（30 天软删 + 恢复） | 仅作者与管理员可进；M1 必做（4.5.1） | `DELETE`、`POST …/restore` |
| `finance/report/index` | 报表 | 时间窗筛选、图表切换、点击下钻到流水并带筛选态 | `GET /api/finance/reports/summary` |
| `finance/report/export` | 导出 | `type`/`days`/`format` 三参数全部生效（4.5.3 硬约束）；行数与页面筛选结果对账显示 | `GET /api/finance/reports/export` |
| `finance/budget/index` | 预算列表 + 进度 | 月度 + 分类 + 固定/周期；超支行标注来源，**提醒由 HomeOS 下发** | `GET /api/finance/budgets` |
| `finance/budget/form` | 预算创建/编辑 | 阈值设置（默认 80%/100%） | `POST/PUT /api/finance/budgets` |
| `finance/ledger/index` | 账本视图 | 共享/私有/项目三种分组；切换后流水与报表同步过滤 | `GET /api/finance/ledgers` |
| `finance/ledger/form` | 账本创建/编辑 | 成员范围 + 标签；文案明确「分组，不是隔离」（4.5.1） | `POST /api/finance/ledgers` |
| `finance/account/index` | 账户列表 + 余额 | 预置 + 自定义；`is_default` 每家庭至多一个 | `GET /api/finance/accounts` |
| `finance/account/form` | 账户创建/编辑 | 类型、币种、`is_liability`；`②` 补信用卡账单日/还款日 | `POST/PUT /api/finance/accounts` |
| `finance/category/index` | 分类管理（两级） | 图标从统一图标集选，**禁 emoji**（14.7）；预置字典可改名不可删 | `GET/POST /api/finance/categories` |
| `finance/bill/index` | 账单（周期账单/待缴/已缴/逾期） | 「自动扣款标记」仅人工确认（4.5.5）；到期注册到 HomeOS | `GET /api/finance/bills` |
| `finance/bill/form` | 账单创建/编辑 | 存 `due_at` → 发 `{code}.due.registered`，页面不承诺即时上日历（16.4） | `POST/PUT /api/finance/bills` |
| `finance/mine/index` | 面内设置 | 提醒阈值、附件限额、记账默认项 | `GET/PUT /api/finance/settings` |

## 五、关键交互流与步数预算

### 5.1 「步」的计数口径（写进验收，避免争论）

一步 = 一次用户主动操作（点击、输入后确认、切换选择器）；系统自动完成的渲染与请求**不计**；一次表单内多字段填写若用同一个键盘面板，计 1 步。18.3 的「记账 ≤3 步」按此判定。

### 5.2 三条记账路径（都 ≤3 步、≤5 秒）

| 路径 | 步骤 | 失败降级 |
|---|---|---|
| 手输 | ① 悬浮＋或底部＋ → ② 金额键盘 + 分类图标（同一面板一次完成） → ③ 保存 | 无依赖，恒可用 |
| 小票 OCR | ① ＋ → ② 拍照/选图 → ③ 确认识别结果（可逐字段改） | 识别失败即回落到手输同一表单，**不新增步骤**、不弹错误页 |
| 语音 | ① ＋ → ② 按住说话 → ③ 确认 | ASR 不可用回落手输 |

保存后 5 秒内流水首行可见（本地乐观插入 + 服务端回执校正，冲突走 5.4）。

### 5.3 全局「＋」（≤2 步选到目标对象）

```
① 点底部 ＋ → 覆盖层：文字 / 语音 / 拍照 / 模板 四输入 + 目标对象九宫格
② 选目标对象（P1-P5 手选，只列已出生面：HomeOS 待办/提醒 + 财务记账/账单/预算）→ 直接进该对象的表单
```

- **无权限项不显示**，不置灰（17.4）；一个可建对象都没有时覆盖层显示「当前家庭未开放任何可创建对象」。
- 文字输入进的是「快速捕获」草稿页，P6 由 AI 归类分流；P1-P5 草稿只落 HomeOS `Todo`，不假装会识别。

### 5.4 乐观锁 409 的处置流（金额型不接受静默覆盖）

```
写 → 409 → 「内容有变动」弹层（双版本并排：我的 / 服务端最新）
   → 选「用我的」→ 带新 version 重发一次（仍冲突则再弹，不循环超过 2 次）
   → 选「用最新」→ 丢弃我的改动并重拉
   → 选「手动合并」→ 进表单，字段级标红差异
```

弹层文案不出现「覆盖」字样，避免用户误读为无代价；每次 409 计入 `sync_conflict` 埋点与 21.5 冲突指标。

### 5.5 离线写与重放

- 写请求进 `pending_ops`（按 `(family_id, service)` 分桶），行右上显示「待同步」标记；跨桶不互相阻塞。
- 触发重放：网络恢复 / 前后台切换 / 定时三处（p1-tech-plan 第五章）。
- 离线态禁用四类入口（家庭切换、邀请、权限修改、AI 录入），**在 shell 层统一禁用**，各面不各自判断（21.6）。
- 重放冲突走 5.4；被拒绝的写不静默丢弃，队列里保留可展开的失败项。

### 5.6 提醒 → 深链 → 完成回写（跨服务闭环）

```
到点（svc-homeos 扫描触发）→ 站内信 + 推送 → 点击 → homecube://finance/bill/{id}
→ 账单详情「标记已缴」→ 本服务写 → 发 finance.bill.paid → svc-homeos 消费置完成
→ 日历与待办同步消失（收敛 P95 ≤5s）
```

UI 口径：点「标记已缴」后本地即置已缴态并显示「同步中」，**不等待跨服务确认**；5 秒后仍未收敛则显示时效提示而非报错。

### 5.7 家庭切换（≤1 秒上下文重建）

A 行 → 切换面板 → 选家庭 → token 重签发 → shell 广播「上下文已换」→ 各面丢弃缓存重拉。切换期间显示骨架，禁止残留上一家庭的任何数据渲染（跨家庭串数据是阻断级缺陷，3.4.1）。

### 5.8 L3 对象的二次确认

进入 L3 字段对象（含深链）→ 会话内确认一次（「将显示敏感信息」+ 30 秒内免重复）；确认后仍需设备解锁。L3 内容不进推送正文、不进默认导出（20.2）。

## 六、权限对渲染的作用

| 权限层 | 作用点 | 客户端表现 |
|---|---|---|
| scope=module（某面关闭） | B 行 chip、深链、＋ 的目标对象、首页摘要卡 | chip 消失、深链「未启用」 |
| 角色默认矩阵（15.3） | 每个页面的写入口 | `create/update/delete/export/invite/admin` 缺失 → 对应按钮**不渲染** |
| data 范围（全家庭/本账本/本人/指定成员） | 列表行与详情 | 读不到的行不出现；他人流水行显示只读态（无编辑手势） |
| 对象级 ACL / 私密行 | 流水行、附件 | 非作者非管理员：整行不在结果里（行级可见性在 SQL 层，客户端不做二次过滤） |
| 字段级可见性（15.4） | DTO | 服务端不下发即不渲染，客户端不判断字段权限（DTO 层口径，p1-tech-plan 4.2） |
| condition=时间窗（访客有效期） | 全局 | 到期即下次请求被拒 → 跳「访问已过期」 |
| `pver` | 一切缓存 | 客户端权限缓存 TTL 60 秒 + 收到 `homeos.permission.updated` 立即失效，下一次请求即新表现（15.6） |

**角色在 P1 的可见面（客户端视角，逐行对应 15.3 的五列，即 18.2 逐格断言的「5 角色」）**

| 角色 | 底部 Tab 可用 | B 行可见 chip | 财务写 | 财务读 | 导出 | 我的 → 家庭/权限/设置 |
|---|---|---|---|---|---|---|
| 管理员（Owner） | 五项全 | `⌂` + 财务 | 全部动作 | 全部 | ✔ | ✔ 可写 |
| 成人成员（Member） | 五项全 | `⌂` + 财务 | 本人 M（他人流水无编辑手势） | 全家庭 R | 需授权，只导可读行 | 只读成员列表；设置与隐私仅本人项可写 |
| 儿童（有账号） | 首页 / 动态 / 消息 | `⌂`（财务 chip **不显示**） | — | — | — | — |
| 儿童/老人（无账号） | 不登录，无入口 | — | 由代管人携带 `on_behalf_of` 写入 | — | — | — |
| 访客（Guest，有效期内） | 首页 / 动态 / 消息 | `⌂`（财务 chip 不显示） | — | — | — | — |

- 15.3 的 HomeOS 行只授予「成员/权限/设置」的读取给成人成员，儿童与访客为 `—`：因此这两类角色的**「我的」Tab 只保留通知与时间对象**，家庭管理、权限、设置三组入口**整组不渲染**（不是点进去报错）。
- 财务 chip 对无 module 权限的角色直接不显示（1.3 第 5 条同一渲染路径），与"家庭关闭该面"共用一条判定。
- 无账号成员**没有登录入口**，只在成员管理里作为被记录对象存在（3.4.1）。

## 七、全局状态与异常态（一套，各面复用）

| 态 | 触发 | 呈现 | 复用位 |
|---|---|---|---|
| 未启用 | 未出生面、module 关闭 | 图标 + 「即将上线 / 本家庭未启用」+ 返回 | `hc-state-disabled` |
| 暂不可用 | 该面服务不可达 | 该面入口不可用态 + 投影最后值与时效戳（12.3） | `hc-state-offline-service` |
| 无权限 | 判定拒绝 | 「无权访问」+ 返回，**不显示任何数据片段** | `hc-state-denied` |
| 空 | 有权且请求成功但零结果 | 引导动作（去记一笔 / 邀请成员），不写「暂无数据」了事 | `hc-state-empty` |
| 加载中 | 首屏 | 骨架屏，不用 spinner 遮内容 | `hc-skeleton` |
| 失败 | 非 2xx、网络 | 可重试 + 错误码可见（用于对账与客服），文案不带堆栈 | `hc-state-error` |
| 离线 | 无网 | 顶栏常驻细条 + 「N 项待同步」 | shell 层 |
| 冲突 | 409 | 见 5.4 | `hc-conflict-sheet` |

规则：**同一态位在七面用同一组件与同一文案库**（HomeOS 提供），避免各面自造「空空如也」；图标统一图标集，`check-no-emoji` 拦 emoji 回流（14.7）。
