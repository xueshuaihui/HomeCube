> 本文件是**给新窗口主 agent 的任务书**。读者假设：对本项目零上下文。
> 目标：把 P1 做到「全部完成并验证通过」，主 agent 只做调度与把关，实现/验证/评审全部由子 agent 承担。

## 0. 你的角色：调度者，不是实现者

**你（主 agent）只做四件事**：

1. 拆卡与派单：把当期范围拆成任务卡，每张卡交给一个子 agent。
2. 判读：读子 agent 回来的结论 + **自己打开文件核实**，决定放行还是打回。
3. 汇报：按 §7 的格式给人类进度快照。
4. git 操作：提交、按批推送（子 agent 一律禁止 push，见 §9）。

**你不做**：不写代码、不写测试、不写文档正文、不跑构建。你若自己动手实现了，就是流程缺陷——人类会要求推翻。

**一条无法绕开的环境事实**：本 harness 的 Agent 工具只暴露 `subagent_type`（`general-purpose` / `Explore` / `Plan`），**没有 model 参数，无法指定子 agent 使用哪个模型**。所以"全部交给 Qwen3.8-Flash 子 agent"在工具层面不可实现。落地方式：统一用 `general-purpose` 做实现与验证、`Explore` 做定位与走查、`Plan` 做规划；派单时靠**任务书本身的严格程度**保证质量，不靠模型选择。若人类日后接入可按模型派单的通道，再替换。

## 3. 环境事实与硬约束

- 平台：macOS（Intel / x86_64），`/bin/zsh` 登录、脚本按 **bash 3.2** 写。
- **bash 3.2 + 中文 locale 陷阱**：`$VAR` 紧跟中文字符会中断脚本解析。所有 shell 里变量一律写 `${VAR}`，且不要在中文注释行尾留未闭合内容。
- Python 脚本：**不要用 heredoc 从 stdin 喂含中文的脚本**（会报 non-UTF-8 source）。写成文件，首行 `# -*- coding: utf-8 -*-`。
- Node v24.19.0（本机 `node -v` 实测）。`gh` 已授权，但 **GitHub 下载极慢**，需要 `curl` 分片加速取二进制。
- **不要用 shell 碰 `~/Downloads`**。
- 远端：`origin = git@github.com:xueshuaihui/HomeCube.git`，**仓库是 PUBLIC**。push 前按公开标准自查：不含密钥、不含本机绝对路径、不含未定版内部信息。

## 5. 每张卡的统一循环

```
你派单 → 实现子 agent 产出 → 你派「独立验证子 agent」（不给它实现者的解释，只给任务卡 + 判据）
      → 你派「评审子 agent」（只读，找遗漏与阻塞，不看实现者的自述）
      → 有阻塞项 → 回实现子 agent 修复（附评审原文，不许你自己转述软化）
      → 无阻塞项 → 提交、更新任务表、按 §7 汇报
```

**"无遗漏、无阻塞"的判定标准**（三条全满足才算过，缺一条即继续循环）：

1. 该卡出口判据的**每一条**都有可重跑的证明（命令 + 输出，或测试用例名 + 结果），不接受"已实现""应该没问题"。
2. 评审子 agent 找不到**阻塞级**问题（会导致功能不可用、数据错、越权、门禁失败、与定版冲突）。
3. 未登记对象为零：新表未出 17.2/后缀白名单（**P1 当期白名单里是 `calendar_due_registration`，不是 `homeos_due_registration`**）、新事件未出目录（**日历面的事件前缀是 `calendar.`：`calendar.todo.completed`、`calendar.reminder.fired`；`homeos.todo.completed` 已不存在**）、新接口未出 3.7/4.8/**5.8**（日历面接口在 `/api/calendar/*`）、新页面未出导航文档清单（**含 `pages/calendar` 的 9 页**）——任一出现即阻塞。

**循环不设次数上限。** 人类明确要求过：迭代到没有遗漏为止，**禁止为了通过评审而虚假修复**。

## 6. "禁止虚假修复"的可判定禁令

派单时把这段贴进子 agent 的 prompt 末尾，评审子 agent 也拿同一份当尺子：

1. **不得放宽判据**来"通过"验收：改测试阈值、改断言、把 `assert` 改成日志、加 `skip`/`xfail`、删掉难测的用例——一律算虚假修复。
2. **不得用桩冒充实现**：`// TODO`、返回固定值、`panic("not implemented")`、空函数体、`return nil // 待补`，在完成态代码里出现即算虚假。测试替身只允许在测试目录。
3. **不得绕过门禁**：`--no-verify`、`# noqa`、`//nolint`、往白名单里塞特例、把检查项的匹配面缩小——都要先经人类同意。
4. **不得只修症状**：顺着一条错误的临时模型去改数据会被要求推翻。要改就改模型（表结构、集合来源、判定层次），必要时 `git revert` 已推送的症状修复重来。
5. **不得把未验证写成了结**：报告里必须区分「已实测通过 / 已实现未测 / 未实现」三态，不得合并成"完成"。
6. **不得静默改文档**迁就代码。代码与定版冲突时，冲突本身是发现，要报给人类，不是改文档。
7. **回归要自己找**：等人类报症状算失职。报出一个点，就要把同一片区域同类问题一次扫完。
8. **UI 必须真开浏览器**：按真实窗口尺寸走查，覆盖主路径与边界；只看类型检查和单测通过就说"UI 完成"是虚假声明。亮/暗两态逐屏对比度按 19.2#10 实测（60 路由 × 2 态 = 120 屏；**㉚ 后分布 = 主包 22 + 日历 9 + 财务 29，总数不变，三个分包都要走查、不得只查主包**），次级灰承载文字在两态下各自 ≥4.5:1。

## 9. 提交与分支纪律

- **子 agent 一律禁止 `git push`**，也禁止任何写远端的操作。派单 prompt 里明写这条。
- 只有你可以 push，且**需要人类按批授权**；force push 与打 tag 需单独确认。
- 提交节奏：一张卡一个提交，提交信息说明"兑现了哪条出口判据"。
- 禁止 `git add -A` 式笼统暂存；每次 `git status` 复核暂存内容，尤其防泄（仓库公开）。
- 破坏性操作（`reset --hard`、`checkout --`、`clean`、删分支）前先 `git status`，有未提交内容先 stash（用带唯一 tag 的 `git stash apply` 流程，不用裸 `git stash pop`）或提交。
- 部署与发布：**上传部署包由人类手动完成**，脚本不做远程编排；发版脚本保持最薄，不自动备份回滚（PRD 技术方案 §10.1 的 `make restore` / `make rollback` 口径）。
