## HomeCube 项目结构分析（feat/p1 分支）

### 项目定位
- 家立方 HomeCube，家庭生活管理 App，「一个家，六个面」：底座 HomeOS + 业务六面（finance/purchase/diet/trip/kin/growth）。
- 七系统同仓、每期交付一个垂直切片：P1=底座+财务面 → P2 采购 → P3 饮食 → P4 家人 → P5 成长 → P6 出行+规则引擎。
- 六期墙钟 156-189 周。P1 分M1（底座+财务闭环）/ M2（财务深度域）。

### 三处交付落差（关键结论，均已逐行核对代码）
1. **svc-finance 全域无鉴权中间件**（严重）。`server/services/svc-finance/cmd/svc-finance/main.go:9` 注释自认「Not delivered: the authz middleware (S4)」；main.go:188 建 `group := svc.Engine.Group(d.RoutePrefix)` 后直接挂 45 个端点，无 protected 分组。handler 层 `finance.go:72` 直接 `c.Query("family_id")` 信任客户端传入值。对照：homeos 侧 main.go:191 有 `protected := group.Group("", mw.Handler())`，/families、/home/summary、/notifications、/dynamics 等均走 svcauth.Require。finance 全部 31 处 family_id 过滤都在 repo 层按客户端传参过滤，无越权校验。
2. **前端未接 token**。`web/src/api/request.ts:16-17` 自认「鉴权头与 refresh 不在本卡，此处不预埋空的请求拦截器」，request() 直接透传 options.header。页面 16 个 vs 技术方案 S14 出口判据「主包 31 + 财务 29 = 60 路由」。
3. **验收报告结论过期**。`docs/P1-ACCEPTANCE-REPORT.md` + `P1-REGRESSION-TEST-REPORT.md`（10-03 10:16）称 14 Sprint 全完成；但 `.github/workflows/` 只有一个 .gitkeep——4 个门禁脚本（validate-migrations / check-data-ownership / check-frontend-homology / check-contracts）存在却无任何 workflow 调用，即 CI 从未真正跑过。回归报告作者标注「Qoder AI Assistant / 待人工审核」。

### 工程约定（后续沿用）
- Go 走绝对路径 `$(HOME)/sdk/go/bin/go`（1.27.1），Makefile 显式传 GOTOOLCHAIN=local 禁止静默下载工具链。
- Makefile 兼容基线：GNU Make 3.81 + bash 3.2，配方内变量一律 `${VAR}` 形式（$VAR 紧跟中文会中断解析），不用 4.x 写法。
- 一个 code 七处生效：服务名/schema/路由/subject/表前缀/分包/迁移目录，唯一真源是 server/packages/registry。
- 门禁脚本都依赖已构建的 registryd 二进制（`HC_REGISTRYD_BIN` 可覆盖路径）。
- 跨服务零分布式事务，一律 outbox + 事件最终一致；跨服务只读走 packages/rclient（仅 GET、至多 1 跳）。
